# 사용자 결정 기록 (DECISIONS)

날짜순으로 쌓는다. 결정이 나면 바로 한 줄로 추가하고, 바뀐 결정은 지우지 말고 새 줄로 대체 사실을 적는다. 구현 위치를 함께 적는다.

## 2026-11-26

- **진행 방식**: 필요한 순서대로 묻지 말고 자동 진행. AWS 재배포·수집 재개도 자동 허용("응 묻지 말고 자동 허용해줘"). 결제·구독·키 발급·계정 권한 확대는 여전히 사용자가 직접 한다.
- **콘텐츠 방향**: 뉴스 전달이 아니라 한국 주식 관점의 뉴스 **분석**에 집중(저작권: 사실은 보호 대상이 아니고 표현이 보호됨, 대법원 2004도5350).
- **작성기 분리**: 글 작성 모델은 원문을 받지 않고 검증된 사실만 받는다. 규칙: 보도 사실은 출처 명시, 계산 수치는 식과 함께 표시, 단정·권유 표현 금지, 관련주마다 연결 역할 한 줄, 1차·보도 출처 구분, 투자 권유 아님 고지. → `workers/ai-processing/runtime/writer.mjs`, `docs/backlog-processing.md`
- **수집 구조(방향)**: 발견은 Finlight(국내)·GNews(미국)·텔레그램 링크. 근거는 국내 DART·기업 보도자료·IR·텔레그램 리포트, 해외 IR·공시·보도자료를 우선. 발견 API의 요약·본문은 근거로 쓰지 않는다. → `discovery.mjs`
- **유료 구독**: 지금은 구독하지 않는다(권고). AI 처리 실연결과 무료 입력 검증 후, 빈틈이 보이면 서면 약관 확인 뒤 검토.
- **방문 간격**: 같은 사이트 최소 5초 + 랜덤 0~3초(5~8초), 다른 사이트 사이 1~3초. 접속 위장·차단 우회는 하지 않는다. → `scripts/providers/pacing.mjs`
- **텔레그램**: 상시 수집, 새 글이 올라왔을 때만. 조용한 채널은 10→20→30분 간격. 이후 "지금부터 신규만": 채널 첫 방문은 시작점만 기록하고, 그 이후 게시물의 링크만 저장. 이미 저장된 링크는 7일 TTL로 만료. → `telegram-link-worker.mjs`
- **보관·삭제**: 원문 본문은 분석 완성·중복·제외 시 즉시 삭제(미완료는 최대 7일). 사실·짧은 인용·출처 기록 30일. 미게시 초안 30일(원문 만료와 무관). 출처 철회 시 즉시 회수. → `store.mjs`
- **시트**: 상위 섹터 11개는 HTML 시안(`prototype.html`)의 parent 매핑을 따른다(코드 카탈로그와 일치). 카테고리 탭 하단의 기업 표 사본은 무시. "검색페이지 설명글"은 검색 결과에 보이는 설명글.
- **AI 모델(Sol 중심안)**: 선별·사실 추출 `gpt-6-luna`, 분석 글 작성 `gpt-6.1-sol`, 독립 검증 `gpt-6.2-sol`(작성과 다른 모델 필수). OpenAI **API**(platform, 종량제)로 운영하며 ChatGPT 구독(Plus→추후 Pro)은 개발 도구(Codex)용이다. 예상 월 $150~200. 켤 때 하루 호출 상한 150으로 2주 시작, 플랫폼 월 한도 설정. 저작권 위험은 모델이 아니라 작성기 분리·원문 대조·보관 규칙으로 줄인다. → `workers/ai-processing/runtime/config.example.json`
- **뉴스·리포트 역할(B안)**: 뉴스는 발견과 홈 순위 신호로만 쓰고 본문은 읽지 않는다(언론사 수·처음/최근 보도 시각·확산 속도·해외 매체 여부만 집계, 원 링크 7일). 분석 근거는 공식 자료(DART·IR·보도자료·정부·SEC)와 증권사 리포트. 뉴스 발견은 Finlight Pro Light(국내)·GNews Essential(미국) 검토, 텔레그램은 리포트와 뉴스 신호를 모두 사용(최종 목적지 사이트로 분류). 기존 웹 뉴스 37곳 직접 수집은 API 도입 후 2주 비교하고 종료 결정. 텔레그램 링크의 단축 주소는 해석 단계에서 최종 주소로 푼다.
- **수집 구조 확정(2026-11-26)**: 한국 뉴스 발견 Finlight Pro Light, 미국 뉴스 발견 GNews Essential. 증권사 텔레그램에서 리포트 링크와 뉴스 링크를 모두 수집하되 **증권사 사이트는 접속하지 않는다**(리포트 링크는 리포트 신호, 뉴스 링크는 뉴스 신호). 분석 근거는 한국 OpenDART 공시 API·기업 보도자료·IR(시트), 미국 SEC 공시(EDGAR)·미국 기업 IR(카테고리 탭 연관 미국기업). DART 웹은 robots 금지라 API만 사용. 이에 따라 증권사 사이트·DART 웹 허가 12개는 다시 DISABLED. 키: OpenAI·OpenDART 저장·검증 완료.
- **하네스·팀**: 가벼운 구조. 맥락은 `docs/context/` 세 파일, 완료 기준은 `verify:integration`, 검수는 PR 단위. 팀은 통합 담당 1 + 영역별 작업 세션 최대 2~3(수집기·운영 / AI 처리 / 앱·어드민), 파일이 겹치지 않을 때만 병렬.

- **글 범위와 종목 상세**: 한 회사 자체의 사건(그 회사의 공시·자금조달·주식보상·증설·실적 등)은 **종목 이슈(COMPANY)**로 분류한다. 종목 이슈는 홈과 섹터 피드에 올리지 않고 **종목 상세 페이지(`/company/[id]`)에만** 노출한다. 섹터 이슈(SECTOR)와 매크로(MACRO)는 지금처럼 홈·섹터 피드에 노출하고, 연결 역할이 있는 기업의 종목 상세에도 "관련 기업으로 언급"으로 함께 보인다. 종목 상세: 회사명·설명·관련 섹터·이슈 목록. 시세·종목코드는 종목 식별 검증 전까지 비워 둔다. 종목 이슈를 홈에 올리는 예외 규칙(섹터 영향이 큰 경우)은 아직 두지 않았다(뉴스 신호와 연결할 때 검토). → AI `editorial.mjs`(articleKind·primaryCompanyId·placement·company_refs), DB `supabase/migrations/20261127000051_company_scope_and_page.sql`, 게이트웨이 `/v2/companies/{id}`, 앱 `apps/mobile/src/app/company/[id].tsx`
