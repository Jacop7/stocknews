# 프로젝트 전용 검수 판본 제한 제거

사용자 2026-11-21 직접 지시: “검수기 판본 제한 없애고 완성될때까지 개발해줘”.

`scripts/dev/project-review-coordinator.py`는 설치된 공유 검수기를 해시 검증 후 상속한다. 전역 bootstrap·설치 release·hooks·다른 프로젝트 설정을 바꾸지 않는다. 기존 home의 SQLite와 원문·한 번 허용 grant·모델·목적지 binding을 그대로 사용한다. 명시 활성화한 주도주뉴스 프로젝트 루트의 일반 검수에서 변경된 판본 수와 REVIEW_CHANGE 횟수만 무제한으로 바꾼다. 특별한 관리자 C2 절차는 이 도구의 적용 대상이 아니다.

- 새 판본은 현재 필수 검사 PASS와 기존 양측 COMPLETE 원문을 요구하고 같은 case를 이어간다.
- 판본마다 역할별 전송 key는 하나다. 기존 결과 REUSE/JOIN, 전송 불명 회수, 현재 바이트·계획·모델·목적지·잠금 검증은 공유 검수기를 유지한다.
- 양측 최신 READY 없이는 완료할 수 없다. provider/login/한도/전송 장애는 자동 해제하지 않는다.
- 이전에 기록한 정확한 판본 제한 중단만 사용자 지시와 함께 보존한 뒤 회복한다. 기존 원문이나 중단 증거를 삭제하지 않는다.
- 같은 본문으로 과거 판본을 새 검수로 다시 보내지 않는다. 최초 원문을 가진 이전 판본은 읽기 전용 조회만 가능하다.
- 내부 검수용 프로그램이다. DB/Auth 권한 확대, 앱 게시, 수집 재개나 유료 AI 호출 권한을 추가하지 않는다. 동일 사용자 쓰기 권한에 대한 OS 격리를 주장하지 않는다.

실행은 기존 CLI와 같은 인수이며 `--home`에는 원래 검수 home을 넣는다. 최초 `enable_unlimited_revisions`에 실제 사용자 지시와 출처를 기록한 뒤 기존 `begin → run_check → prepare → lock/bind/reserve → dispatch/accept/complete → status`를 따른다. 기본 설치 공유 검수기는 변경하지 않으므로 이 프로젝트의 판본 제한이 있는 일반 검수에는 이 진입점을 사용한다.
