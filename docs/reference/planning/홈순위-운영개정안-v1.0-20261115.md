# 주도주뉴스 홈 순위 운영 개정안 v1.0

2026.11.15 · 기획 변경안 · 구현·운영 활성화 결과 아님

## 1. 변경 목적과 적용 범위

사용자 확정 요구는 다음과 같다. 홈 순위는 24시간 갱신하며 한국시간 08:10 이상~20:00 미만은 KRX·NXT 한국 주식, 20:00 이상~다음 날 08:10 미만은 미국 주식 기준을 사용한다. 갱신 주기는 5분이다. 순위는 주가만으로 정하지 않고 한국 시장에 대한 이슈 파급력을 중심에 둔다. 큰 이슈는 영향이 유효한 동안 오래 상위 후보에 남는다. 현재가·등락률·섹터 평균 수치는 앱에 표시하지 않고, 종목 클릭은 네이버증권 원본으로 연결한다. 조회수 숫자와 내부 점수도 관리자만 확인한다.

이 문서의 점수·구간·시각·검증 기한 수치는 사용자가 일일이 확정한 값이 아닌 초기 설계안이다. 실자료 재생 검증과 구현 전 검수를 거쳐 정책 버전으로 고정한다. 운영자가 매 기사마다 승인하지 않고 근거 검증·영향 평가·갱신을 자동으로 실행한다. 관리자 화면은 감시·설정·정정·비상 중지 수단이다.

이 묶음의 적용 우선순위는 사용자 최신 확정 요구 → 본 문서 → 20261113 기획의 변경되지 않은 조항이다. 기존 서비스 v1.6·어드민 v1.1·제작 v1.3·상세로직 v1.1·공통계약 v1.0의 홈 시간·순위·지속 노출·가격 표시 조항 중 충돌하는 부분은 본 문서로 대체한다. 이 묶음에 실은 기존 문서는 변경 전 참고 스냅샷이며 각 첫머리에 대체 안내를 붙인다. 기존 검수 완료 묶음과 제품 저장소의 검수된 사본은 역사 증거로 보존한다. 매체별 부록106행/112URL, claim 검증, 게시·정정, 저장, 알림3종, 기업·섹터 관계와 독립 신규 제품 경계는 유지한다.

## 2. 24시간 5분 스냅샷과 기준 시장

한국시간 매시 00·05·10·15·20·25·30·35·40·45·50·55분을 cutoff로 한다. 하루 288개 논리 회차이며 회차마다 실제 자료 수신 여부를 별도로 기록한다. 회차 생성은 기사 작성·게시의 선행조건이 아니다. 뉴스 수집·검색·분석·게시·정정은 독립적으로 24시간 순차 처리한다. 이슈 파급력의 한국 주식 관점은 밤에도 바뀌지 않는다.

| 한국시간 | 기본 market_basis | 경계 |
| --- | --- | --- |
| 00:00~08:10 미만 | FOREIGN_US | 장전 마지막 cutoff 08:05 |
| 08:10~20:00 미만 | KR_COMBINED | 한국 마지막 cutoff 19:55 |
| 20:00~24:00 미만 | FOREIGN_US | 장후 마지막 cutoff 23:55 |

한국 공식 거래일 달력이 휴장이면 하루 전체 FOREIGN_US다. 휴장일을 주말 이름만으로 추정하지 않는다. 임시 개장·거래 정지·NXT 비대상·미국 휴장·DST·조기 종료는 검증된 거래소별 세션과 상태를 사용한다. 08:10/20:00은 홈 기준 전환시각이며 모든 거래소가 그 시각에 거래 중이라는 뜻은 아니다. 미국 비거래 시간에는 마지막 완료 정규장 수익률을 실제 거래일과 함께 내부 기록하며 새 시세로 가장하지 않는다. 미국 프리·애프터마켓은 공급·세션 검증 전 제외한다.

KR_COMBINED는 KRX/NXT 두 수익률을 평균하거나 같은 기업을 두 번 세지 않는다. 회사별 하나의 instrumentId에 통합 시세 또는 버전 고정 시장 선택 규칙을 연결한다. NXT 장전에는 실제 거래 가능한 종목의 유효 LAST와 비교 가능한 기준 종가만 쓴다. KRX 전일 종가·예상체결가를 NXT 장전 현재가로 섞지 않는다. NXT 미대상·미체결·거래 정지는 결측으로 표시한다. 당일 수익률 기준 종가·조정 정책·KRX/NXT 세션 연속성·장후 가격 선택은 공급 자료와 함께 7B에서 명시 검증한다. 기존 70% 및 min(3,N) 유효 구성 기준, 중복 제거, 미매핑 분모 유지 규칙은 계속 적용한다. 검증되지 않은 조합은 M에 사용하지 않는다.

스냅샷 식별은 policy_version + cutoff + market_basis + target_kr_trading_day + comparison_set_version + catalog_version이다. 08:10에는 기존 다음 한국 거래일 D를 유지하고 시장 기준만 바꾸며, 20:00에는 다음 한국 거래일 D로 이동한다. 구시장 점수와 신시장 점수를 직접 비교하거나 신시장 스냅샷 대신 구시장 순위를 붙이지 않는다. 단, §7의 HIGH 비가격 carry_order는 시장 가격점수 재사용과 구별해 전달한다. 최초 게시일·Story/Issue ID·파급력 검증 기한은 시장 전환으로 초기화하지 않는다.

완성된 새 스냅샷만 원자적으로 교체한다. 같은 cutoff의 중복 작업은 같은 키로 합쳐지고, 늦은 구회차가 최신 회차를 덮지 못한다. 회차 실패는 같은 context의 직전 완성 스냅샷을 실제 cutoff·지연 상태와 함께 최대15분 참고로 유지한다. 현재 공개 자격은 다시 검사하고, 정정 확인·숨김·철회된 글은 즉시 제거한다. context 전환 후 같은 context의 완성본이 없거나 15분을 넘으면 순위 산정 중으로 표시한다. 새 게시글 자체는 이슈체크·검색에 계속 제공한다.

## 3. 후보와 근거 검증

PUBLISHED인 최신 적격 버전만 후보가 된다. 광고·홍보·무관 정보·근거 미확인·정정 확인 중·숨김·철회는 후보에서 제외한다. 매체 수·텔레그램 전달 수·클릭 수는 사실 확인을 대체하지 않는다. SYSTEMIC_MACRO의 공식 핵심 원문1 또는 독립 원출처3 및 한국 전달 경로 게이트는 종전 공통계약대로 유지한다. 방향이 호재든 악재든 같은 검증 기준을 적용한다.

후보는 해당 거래 구간의 새 적격 Issue와 영향 상태 ACTIVE인 지속 이슈의 합집합이다. 전날 또는 지난주에 처음 게시됐어도 현재 영향이 검증된 큰 사건은 유지할 수 있다. 카탈로그 소속만으로 직접 영향·수혜를 부여하지 않는다. 동일 Story는 A/B/C 전체에서 한 카드이며, 새로운 방향 분리는 종전 NEW_ANGLE 요건을 모두 충족할 때만 가능하다. 다른 매체의 동일 보도·제목 변경·단순 가격 반응은 새 Issue를 만들지 않고 기존 상세 UPDATE로 연결한다.

## 4. 파급력 평가 I

파급력은 한국 주식시장에 대한 전달 경로, 영향 범위, 규모, 지속성을 증거에 연결해 평가한다. 평가자가 숫자를 임의 생성하는 대신 각 항목의 등급·근거 claim ID·영향 섹터·불확실성을 저장한다. 근거가 없으면 높은 점수를 추정하지 않는다. 이 점수는 방향과 별개인 중요도다. 악재를 음수 점수로 내려 버리지 않는다.

| 항목 | 0~5 등급 기준 | 배점 |
| --- | --- | --- |
| 한국 전달 경로 | 0 연결 없음, 1 키워드 유사, 2 간접 가설, 3 확인된 수요·원가·규제·공급 경로, 4 직접 매출·공급망 연결, 5 한국 시장 공통 변수의 직접 변화 | 등급×8, 최대40 |
| 영향 범위 | 0 없음, 1 개별 소규모 기업, 2 한 하위 묶음, 3 한 섹터의 복수 기업, 4 독립 복수 섹터, 5 시장 전반 | 등급×4, 최대20 |
| 경제적 규모 | 0 새 영향 없음, 1 제한적, 2 규모 불확실, 3 근거 있는 유의미한 변화, 4 핵심 수요·공급·이익에 큰 변화, 5 공급 중단·정책 전환 등 중대 변화 | 등급×5, 최대25 |
| 지속성 | 0 종료, 1 당일 일시적, 2 수일, 3 수주·실적기간, 4 복수 분기, 5 구조적 변화 | 등급×3, 최대15 |

raw_I는 네 배점 합계(0~100)다. 한국 전달 경로가3 미만이면 effective_I=min(raw_I,44), 그 외는 effective_I=raw_I다. 산식의 I는 effective_I/100이다. 원점수와 상한 적용 이유를 모두 기록한다. 한국 전달 경로 등급이3 미만이면 상위·지속 노출 자격이 없다. 경제 규모·지속성의3 이상 등급은 회사 발표·공시·정책 시행·구체적 산업 자료 등 해당 등급을 뒷받침하는 근거가 있어야 한다. 자료가 모호하면2 이하로 제한한다. 주가가 올랐다는 이유로 규모·지속성 등급을 올리지 않는다.

파급력 구간은 HIGH(effective_I≥75), MEDIUM(45≤effective_I<75), STANDARD(effective_I<45)로 나눈다. 먼저 구간을 비교하고 같은 구간에서 혼합 점수로 정렬한다. 따라서 높은 주가·조회수·최신성만으로 낮은 파급력 기사가 HIGH를 추월하지 못한다. 평가 변경에는 이전·이후 항목 점수, 이유, 근거 버전, model/prompt/policy_version을 남긴다. 입력이나 근거가 변하지 않으면 5분마다 LLM을 재호출하지 않고 유효한 평가를 재사용한다.

## 5. 오래 유지되는 이슈와 종료

영향 상태는 ACTIVE / CHECK_PENDING / RESOLVED / INVALIDATED로 관리한다. ACTIVE와 현재 근거 게이트를 통과한 HIGH만 A/B의 장기 상위 후보가 된다. 상위 후보 유지와 순위 고정은 다르다. 더 큰 검증 이슈가 나타나면 교체될 수 있고 최초1위를 보장하지 않는다.

기존 A의 일괄6시간 종료·당일 정규장 종료 상한, B의 일괄60분 종료를 지속 HIGH에 적용하지 않는다. ACTIVE이고 근거가 계속 유효하면 여러 날 유지할 수 있다. 단, 매5분 회차마다 공개 상태·근거 만료·예정된 시행/종료·정정 신호를 검사하고, 심층 영향 재검증은 evidence_valid_until 이전에 수행한다. 유효기간은 마지막 성공 검증으로부터 최대24시간이며 예정된 종료·중요 일정이 더 빠르면 그 시각을 따른다. 검증 실패·자료 접근 실패로 기한을 넘기면 CHECK_PENDING으로 바꾸어 A/B와 실시간 순위 후보에서 제외한다. 기존 사실 자체가 여전히 검증됐다면 이슈체크에서 최초일과 실제 업데이트 시각으로 제공할 수 있다. 사실 오류 의심이면 별도 CORRECTION_PENDING으로 즉시 차단한다.

심층 재검증은 규제의 현재 시행 여부, 수주/공급 차질의 해소 여부, 실적·가이던스 변화 등 관측 가능한 현재 상태를 확인한다. 같은 공식 규정이 계속 유효하다는 재확인도 가능하지만 확인 대상·확인 시각·유효 근거를 남긴다. 단순히 반박 기사가 없다는 이유나 같은 기사의 재전송만으로 연장하지 않는다. ‘영향 지속’ 판단을 새 경제 사실처럼 게시하지 않는다.

| 변화 | 처리 |
| --- | --- |
| 핵심 정책·공급 차질 지속, 한국 영향 여전히 큼 | ACTIVE와 HIGH 유지 가능, 일괄 시간 감점으로 강제 탈락 없음 |
| 영향 범위·규모 축소 | 항목 점수 하향, HIGH를 벗어나면 A/B 즉시 해제 |
| 시행 취소·갈등 해소·실적 영향 소멸 | RESOLVED, A/B 및 실시간 지속 후보 제외 |
| 핵심 사실 반박·오류 확인 | INVALIDATED 및 게시 상태 정정/철회 절차, 순위 즉시 제거 |
| 검증 기한 초과 | CHECK_PENDING, 마지막 상위 점수 자동 연장 금지 |
| CHECK_PENDING 재검증 성공 | 공개 자격·근거·현재 한국 영향 재검사 후 ACTIVE 복귀, I 구간 새 평가, 최초일·F·material_change_at 초기화 없음 |
| 새로운 실질 사실/영향 경로 | 기존 상세 UPDATE 우선, 요건 충족 시만 NEW_ANGLE |

material_change_at은 실제 새로운 핵심 사실·영향 방향 변화가 발생한 때만 바뀐다. 출처 추가·맞춤법·같은 발표 재전송·가격 갱신·매일 유효성 재확인은 material_change_at과 최초 published_at을 갱신하지 않는다. 재상승은 현재 근거와 영향 항목이 개선돼야 하며 단순 조회수 증가로 HIGH를 만들지 않는다.

## 6. 보조 점수와 기본 정렬

MEDIUM·STANDARD의 기본 혼합 점수 S = 100×(0.50I + 0.20T + 0.15M + 0.10P + 0.05F)로 한다. T는 아래의 섹터 검색 관심도다. 이는 초기 검증 대상이지 검증된 최적 알고리즘이 아니다. I 구간 → S → 이전 같은context 순위 → material_change_at → 고정 Issue ID 순으로 결정한다. HIGH와 MEDIUM을 나누는 구간이 혼합 점수보다 우선한다. 인기 섹터의 노출 기회를 높이되 검색 인기만으로 HIGH로 승격하지 않는다.

HIGH의 상단 정렬에는 M을 사용하지 않는다. HIGH 점수 S_HIGH=100×(0.50I+0.20T+0.10P+0.05F)/0.85다. 이는 큰 이슈의 집중 대상을 가격 단독 변동으로 교체하지 않기 위한 명시 예외다. HIGH의 가격 반응은 관리자 진단으로만 기록한다. T/P 결측이면 이 HIGH 전용 비중에서 해당 항목만 제거하고 나머지를 합계1로 재정규화한다. HIGH는 가격 공급 유무·KR/US 전환·M 증가/감소와 무관하게 같은 비가격 입력이면 같은 점수를 유지한다. 이후 §7의 S는 해당 구간에 적용한 S_HIGH 또는 S를 뜻한다.

M은 검증된 대표 섹터/비교군의 당일 수익률 반응 크기다. 초기 정규화는 min(abs(return_percent)/10,1)이며 상승·하락 부호는 별도 저장한다. 큰 악재의 하락 반응도 중요 신호로 센다. KR은 검증된 KRX/NXT 비교군, FOREIGN_US는 버전 고정 미국 동종·수요 비교군이다. 단일 종목 급등을 섹터 전체 반응으로 대체하지 않는다. 가격 반응이 있다는 것만으로 뉴스와의 인과관계를 확정하지 않는다.

P는 우리 앱 상세의 유효 최근24시간 UV를 log1p로 정규화한다. 비교 후보가5개 이상이고 합계 UV50 이상일 때만 사용하며, 분모는 같은 cutoff 후보들의 최대 log1p(UV)다. 종전6D 집계·watermark·중복 제거·조작 제외를 유지한다. 신규 글의 UV0과 집계 장애를 구분하고, 충분한 조회 표본이 없다고 게시를 보류하지 않는다.

F는 마지막 실질 변화 이후 경과 시간에 따른 0.5^(elapsed_hours/6)다. 파급력 검증 시각이나 원문 재송고 시각으로 최신성을 초기화하지 않는다. 지속 HIGH가 오래돼 F가0에 가까워져도 I 구간과 I 비중이 남는다. HIGH의 실제 영향이 소멸하면 최신성이 남아 있어도 상위 자격을 잃는다.

누락 값을 0%·조회0으로 채우지 않는다. 가격 권한·자료가 미확정이거나 M을 정렬에 쓰는 MEDIUM·STANDARD 후보 중 하나라도 비교 가능한 유효 M이 없으면 해당 전체 스냅샷에서 M을 끈다. 표본 부족 또는 후보 하나라도 P 집계가 미확보이면 전체 P를 끈다. T의 완전성 검사는 아래를 따른다. 모든 조합은 가용 항목의 기본 비중만 합계1로 나눠 재정규화한다. M off면 I:T:P:F=50:20:10:5, T off면 I:M:P:F=50:15:10:5, T/M/P off면 I:F=50:5다. 가용 비중·off 사유를 스냅샷에 고정하며 서로 다른 항목 조합의 S로 안정화 비교를 하지 않는다. 조합 변경 첫 회차는 새 비교context다. price_missing·검색 결측·UV 부족·정상0·집계장애 사유를 구별한다. 시세나 검색 자료가 없어도 파급력 중심 홈은 산정 가능하다.

M 전체 off는 비교 가능한 가격이 없는 글에0을 주어 불리하게 만들지 않으려는 보수적 의도다. 공급 미확정인 지금은 M이 계속 off여도 정상이다. HIGH/MACRO_ALL의 진단 시세 결측은 다른 구간 M을 끄는 사유가 아니다. MEDIUM·STANDARD MACRO_ALL의 M은 버전 등록한 한국 시장 광역지수(KR) 또는 미국 광역지수(FOREIGN_US) 비교군이 유효할 때만 계산한다. 지수의 자료·산식 검증 전에는 해당 구간 전체 M off이며0으로 대신하지 않는다. 지수 공급 연결도7B 검수 대상이다.

기존 앱 기본은 이 파급력 중심 혼합이다. 원자료 숫자는 공개하지 않는다. 관리자 진단용 순수 가격순·조회수순은 유지할 수 있으나 자동 기본 혼합을 대체하거나 HIGH 게이트를 우회하지 않는다. 과거 정책 스냅샷은 당시 정렬 모드를 유지하며 새 산식으로 과거 결과를 덮지 않는다.

### 6.1 섹터·종목 검색 기반 관심도 T

사용자 추가 요구는 섹터 검색과 해당 종목 검색을 네이버·구글에서 확인해 섹터 가중치에 반영하는 것이다. AI·반도체에 고정 보너스를 주거나 ‘현재 주도’ 가정을 실측 결과로 기록하지 않는다. 실측 전에는 T를 비활성화한다. 검색은 투자 관심의 보조 신호이며 수혜·피해 사실 근거와 다르다.

검색 분석용 관심 묶음은 AI·반도체 / 로봇 / 전기차 / 배터리 / 에너지 / 우주 / 방산 / 조선 / 운송 / 바이오 / 의료 / 금융 / 건설 / 산업재 / 소비재 / 통신·엔터·게임의16개다. 현재 앱 상위 필터11개나 시트 세부 섹터를16개로 자동 재분류하지 않는다. 실제 섹터·하위 묶음·기업 ID와16개 관심 묶음을 별도 버전 매핑한다. 복합 상위 필터를 나눠 분석해도 원래 ID는 유지한다. 매핑 누락·모호함은 활성화 전 해결한다.

| 자료 | 활용 | 한계 |
| --- | --- | --- |
| 네이버 DataLab / NAVER API HUB | 한국 이용자의 섹터·기업 검색 추이 | 일·주·월 상대값, 실제 검색 건수 아님. 공식 문서 간 그룹당 키워드 한도5/20 불일치: 초기 요청5개 이하, 실제 계정 응답으로 확정 |
| Google Trends | 대한민국 지역의 같은 질의 관심 추이 | 웹0~100과 alpha API 일관 척도 구분. alpha는 제한 접근이며 승인 전 자동 API 확보 아님 |
| Google Ads 과거 지표 | 월간 검색 규모 별도 검증 | 월별 추정치와 유사 검색어 합산. 현재5분 검색량 아님 |

섹터 질의는 검증된 산업·핵심·추가 검색어 중 투자 의도가 분명한 표현으로 구성한다. 예: 반도체 관련주, HBM 관련주, 로봇 관련주, 전고체 배터리 관련주. 이는 채택 전 검수할 예시이며 최신 시트를 전수 반영했다는 증거가 아니다. 기업 질의는 해당 세부 섹터에 실제 연결된 한국 상장기업 전부를 대상으로 기업명+주가/실적 등 고정 표현을 쓴다. 특정 대표기업만 임의 선정하지 않는다. 삼성전자 제품 구매·로봇청소기·천문학·연예 팬 검색처럼 주식 외 의도가 섞이는 맨몸 단어는 제외하거나 진단한다. 공급자별 문법·지역·언어·장치 설정 가능 여부를 실제 테스트한다. 밤에도 T의 모집단은 한국 투자자의 관심이며 미국 전체 검색을 섞지 않는다.

query_id·문자열·기업ID·섹터ID·관심묶음ID·역할·catalog_version·query_set_version을 저장한다. 같은 기업의 같은 질의는 한번만 수집하고 여러 관계에 재사용한다. 기업 수·별칭 수가 많은 섹터가 자동 우대되지 않도록 질의별 표준화→기업별 평균→섹터별 기업 평균 순으로 집계한다. 섹터 질의도 별칭별 평균을 쓰며 총합하지 않는다. 기업 채널에서 각 기업 기여는1/N이므로 대형주 하나의 절대 검색량이 전체를 독점하지 못한다. 복수 묶음 기업은 실제 매핑대로 포함하되 전 시장 검색량이나 섹터 합계로 다시 합산하지 않는다. 검색자의 실제 중복 제거를 했다는 뜻은 아니다.

초기 계산 절차의 수치는 모두 재생 검수할 설계 가설이다.

1. 공급자별 동일 지역·필터·56일 창을 고정한다. cutoff까지 수신된 완료 일자만 쓰며 두 공급자 결합은 공통 마지막 완료일로 맞춘다. 시간대/일별 경계가 실제 일치하지 않으면 결합하지 않는다. 실제 지연 분포·품질 검증 전 T 활성화 금지다.
2. 질의 최근7일 평균 a, 직전28일 평균 b에서 증가 신호 G=(clip(log2(a/b),-2,2)+2)/4를 구한다. a≤0 또는 b≤0·저표본·검열된0·자료 없음은 증가율을 만들지 않는다. 무한 급등을1로 채우지 않는다. 공급자의0을 실제 검색0으로 확정하지 않으며 최소 표본 판정은 응답 품질 실험으로 정한다.
3. 관심 규모 L은 교정된 최근7일 평균의16묶음 내 중간순위 백분위다. 섹터 질의 평균과 기업별 질의 평균을 각각16묶음끼리 비교한다. L=(중간순위-1)/15로 하며 동점은 같은 중간순위, 모두 동점은0.5다. 요청별0~100을 바로 합하지 않는다. 공통 앵커·동일 창·연결 배치의 척도 교정을 검증해야 한다. 앵커0·독립배치·검증 실패는 L 결측이다. 일관 척도 API도 공급자 간에는 별도 정규화한다.
4. 질의별 G를 기업/섹터별로 평균한 증가 채널과 L을 합쳐 채널점수=0.6G+0.4L이다. 묶음의 공급자 점수는 섹터검색 채널0.5+기업검색 채널0.5다. 원래 인기와 새 관심을 함께 본다. 별칭·기업 추가로 과거 계산을 소급 변경하지 않는다.
5. 두 공급자 모두16묶음·두 채널이 유효하면 네이버0.6+구글0.4로 결합한다. 이 비중은 점유율을 뜻하지 않는 초안이다. 한 공급자 전체가 불가하면 나머지가16묶음 전체를 완전 제공할 때만 단일 공급자 모드로 전환한다. 부분 결측을0이나 다른 공급자 값으로 조용히 채우지 않는다. 현 초안의 채널 완전성은 고정 등록 질의와 기업 전부의 유효 관측을 요구한다. 한 기업만 저표본이어도 그 채널이 미달이며, 한 묶음이라도 채널·척도·기한 미달이면 전체 홈 T off다. 이는 결측 기업을 제외한 평균으로 편향을 숨기지 않는 보수적 초기 정책이다. 실측상 T를 켜기 어려우면 임의로 표본을 줄이지 않고7B에서 최소 커버리지·저표본 처리·편향 검증의 변경 계획을 별도 DUAL 검수한다. 그 전에는 T off를 유지한다. 종목 없는 묶음은 매핑 검증 단계에서 해결하며 임의0으로 대신하지 않는다. 초기 저표본으로 결측이 많을 수 있으므로 바스켓의 실측 커버리지가 활성화 조건이다.
6. 공통 완료 구간 끝이 cutoff보다96시간 이상 오래되거나 마지막 성공 수신이48시간을 넘으면 T off다. 집계 지연 때문에 현재분 관심도가 아님을 관리자에게 표시한다. 1일1회 수집, 실패 시 최대6시간 간격 재시도를 기본으로 한다. 홈5분 회차는 유효 검색 스냅샷을 재사용하며 미래에 받은 수정 자료를 과거 cutoff에 끼우지 않는다.

기사 T는 제목 키워드가 아니라 근거가 확인된 직접 영향 섹터의 고정 배분 비중(합계1)으로16묶음 점수를 가중평균한다. 인기 섹터 여러 개를 붙인 합계 가산·최댓값 선택은 금지한다. MACRO_ALL은 중립0.5를 쓴다. 전 후보가 동일 검색 스냅샷·모드를 사용하며 누락 매핑은 전체 T off다. 검색량으로 호재/악재 방향을 판정하거나 NEW_ANGLE·알림·material_change_at을 만들지 않는다.

### 6.2 섹터 가중치 운영과 현재 상태

관리자는16묶음별 관측일·수신일·공급자·교정 상태·섹터/기업 채널·G/L/T·적용 비중·결측·질의 버전을 확인한다. 기사 파급력과 검색 관심도 기여를 구분한다. 검색 등록부도 미리보기→과거 재생→검수→버전 게시 순서다. 계산은 자동이며 사람이 매일 AI·반도체에 보너스를 주지 않는다.

현재 API 계정 접근·alpha 승인·16묶음 실제 검색 자료·시트 최신 바스켓 전수 연결은 확보하지 않았다. 따라서 실측 섹터별 가중치 표나 ‘AI·반도체 현재1위’ 결과는 없다. 이번에는 공식 자료 확인과 수집/산정 계약을 정리했다. 검색 실자료 활성화는7B 계획·공급 검증의 별도 완료 조건이다. T off로 영향 평가·합성 검증을 진행할 수 있다.

### 6.3 주도 이슈 유지와 다른 섹터 급락

AI·반도체의 검증된 큰 이슈가 지속되고 검색 관심도도 높은 동안, 다른 섹터의 가격 급락만으로 집중 대상을 옮기지 않는다. 예를 들어 조선이 급락해도 새롭고 중대한 조선 사건이 확인되지 않았다면 신규 조선 카드를 만들거나 기존 조선 기사의 I·지속성·material_change_at을 올리지 않는다. M은 이미 사실 검증을 통과한 해당 Issue의 비교군에서 관측된 반응으로만 사용한다. 무관한 과거 기사를 급락 원인으로 붙여 승격하지 않는다. 시장 동반 하락·수급성 변동·공급 오류는 새 섹터 이슈의 근거가 아니다.

따라서 ACTIVE HIGH AI 이슈와 가격만 급락한 STANDARD 조선 글은 AI가 우선이다. 가격 반응 크기는 I 구간을 넘지 못한다. 두 이슈가 모두 HIGH여도 조선 M만 달라지면 S_HIGH는 바뀌지 않는다. 예: AI I=.80/T=.80, 조선 I=.78/T=.70, P/F 동일이면 AI의 비가격 점수 우위가 유지되며 조선 M이0→1이 되어도 역전되지 않는다. 같은 조건의08:10·20:00 전환도 이 원칙을 유지한다. 조선에 별도로 확인된 중대한 수주 취소·규제·사고 등 새 한국 영향 경로가 생긴 경우에만 그 근거로 I와 T를 평가한다. 그때도 ‘AI는 무조건1위’라는 고정 우선권은 없다. 기존 AI 영향이 해소·반박됐다면 검색 인기만으로 자리를 유지하지 않는다.

## 7. A/B/C 배치·안정성·중복

기존 A/B/C의 초기 크기 A최대2·B최대3·C최대20을 유지하되, A는 현재 검증된 시장 전체 HIGH, B는 A에 포함되지 않은 현재 HIGH 핵심 이슈(신규와 지속 모두), C는 나머지 적격 이슈다. 각 영역 안에서 파급력 구간→혼합 점수로 정렬한다. A/B가 비면 중요하지 않은 글을 억지로 채우지 않는다. HIGH가 자리를 초과하면 C의 상단 후보가 될 수 있다. A→B→C를 합친 전체에서 Story당1카드다. 대표 Issue는 현재 영향·근거·lane 자격을 평가하고 종전 정규 ID 및 공개 자격 규칙을 유지한다. C에서 조회수만 바뀌었다는 이유로 대표 Issue를 교체하지 않는다.

HIGH에서는 시장 전환·M 모드 변경만으로 기존 상대 순서를 초기화하지 않는다. 정책·catalog·후보 자격과 비가격 입력이 같으면 직전 HIGH 상대 순서를 carry_order로 전달한다. 이는 구시장 가격점수나 스냅샷 전체 재사용이 아니다. 시장 전환 시 새 context·새 스냅샷은 생성하지만 HIGH의 비가격 점수·동점 순서를 따로 보존한다. 비가격 자료가 바뀌면 현재 점수로 재평가하며, 모든 이전 순서를 재현 가능하게 기록한다. 최초 HIGH 집합은 비가격 점수→material_change_at→고정ID로 정한다.

파급력 구간·lane이 같고 현재context에 이전 순위가 있으면, 신규 도전자 S가 기존 항목보다5점 이상 높은 상태를 연속2회(5분 간격) 충족할 때만 상위 교체한다. 동점·작은 차이는 기존 상대 순서를 유지한다. 최초 스냅샷·context 전환은 현재 점수와 고정ID로 생성한다. HIGH에 한해서는 같은 절의 비가격 carry_order 규칙을 우선 적용한다. HIGH 승격·새 중대 사실·정정·만료·숨김·철회·RESOLVED는 이 지연을 적용하지 않고 즉시 반영한다. 영역 크기 축소·자격 상실로 빈자리가 나면 현재 적격 후보로 채운다.

이 안정화는 최신 이슈 차단 규칙이 아니다. 새 HIGH는 다음 완성 회차에 즉시 후보가 되며, 같은 구간 내 경미한 점수 진동만 제한한다. 실시간/달력 후보 각각 Story 중복 제거와 섹터 다양성 정책을 기록한다. 다양성 제한으로 중요한 HIGH를 낮은 구간 글로 대체하지 않으며, HIGH 안에서만 동일 파급력 수준의 다양성을 조정한다. 발견 슬롯은 C의 STANDARD에만 적용하고 HIGH/A/B의 자리를 빼앗지 않는다.

## 8. 달력·화면·종목 원본 링크

실시간은 지속 이슈를 포함하지만 오늘·어제·이번주·지난주·이번달·지난달은 최초 앱 게시 한국 날짜로만 필터한다. 지난주 지속 이슈가 오늘 홈 상단에 있다고 오늘 날짜 결과에 새 기사로 추가하지 않는다. 과거 순위는 당시 스냅샷·정책·기사 버전·market_basis를 참조한다. 20261115 정책 이후의 calendar_rank_segment는 FOREIGN_PRE00:00~08:10/마지막08:05, KR_DAY08:10~20:00/마지막19:55, FOREIGN_POST20:00~24:00/마지막23:55, 한국 비거래일 FOREIGN_DAY/마지막23:55다. 이전 정책의09:10·10분 경계로 생성된 역사 자료는 해당 옛 정책을 붙이고 재해석하지 않는다.

앱 홈·이슈체크·섹터랭킹·섹터체크·관련종목·검색·저장·상세에서 가격·등락률·섹터 평균 숫자와 내부 I/T/M/P/F/S·UV를 응답하지 않고 표시하지 않는다. 서버 내부 점수와 시세 필드를 공개 DTO에서 제거한다. ‘섹터랭킹’의 항목 순서는 내부 정책에 따른 이슈 중요도이며 가격순이라고 안내하지 않는다. 섹터랭킹 명칭·별도 화면 개편은 구현 전 화면 검수에서 확정한다. 기업명과 시트의 검증된 설명은 계속 표시한다.

한국 종목 코드는 검증된 master로 연결한다. 종목 클릭 URL 예시는 https://m.stock.naver.com/domestic/stock/005930/total 이다. 이름으로 코드를 추정하지 않는다. iOS/Android 앱 내 브라우저로 원본 주소·원본 페이지를 열고 닫으면 원래 앱 목록 위치로 돌아온다. 출처 화면을 자르거나 시세를 우리 콘텐츠처럼 재구성하지 않는다. 직접 WebView가 필요한 경우의 이용 조건·로그인·보안 동작은 별도 검증하고, 실패하면 외부 기본 브라우저로 전환한다. 링크를 여는 것과 서버가 데이터를 추출하는 것은 별개다.

## 9. 공급과 캡처 제안의 상태
