## 1. 적용 범위와 기존 결정 {#scope}

기준: 서비스 기획안 v1.6, 제작 실행계획 v1.3, 어드민 기획안 v1.1, 현재 대화의 최신 결정. 같은 폴더의 공통-운영계약-v1.0.md를 적용한다. 기존 포괄 규칙과 충돌한 본문은 이번 개정 묶음에서 동기화했다. 충돌·변경점은 22절에 적는다. 수치에는 **초기 제안값**을 표시하며 정책 버전으로 바꿀 수 있다. 개발자가 임의 추측할 빈칸을 줄이는 것이 목적이며, 비용·속도·품질을 실제로 검증했다는 의미는 아니다.

유지할 결정:

- 로그인 없는 Android·iOS 앱. 일반 사용자가 기사 작성·조회수 조작·관리자 기능에 접근하지 못함.
- 하단 홈·이슈체크·섹터랭킹·저장. 카드와 공통 상세의 저장 ID 유지.

- 피해 섹터·일정·수치가 없으면 만들지 않음. 근거 없는 선택 영역 숨김. 시안에서 모든 칸을 채운 요구는 운영 사실을 창작하라는 지시가 아님.

## 2. 처리 단위와 전체 흐름 {#pipeline}

세 가지 단위를 분리한다.

| 단위 | 의미 | 예시 |
| --- | --- | --- |
| Source document | 언론 기사·공시·IR·리포트 한 원문과 그 수정본 | 같은 원문의 네이버·원매체 주소는 하나로 연결 |
| Story | 같은 근본 사건을 묶는 안건 | 특정 회사의 특정 분기 실적, 특정 규제의 진행 |
| Issue | 앱에서 읽는 한 상세와 그 보도 방향 | 실적 발표 분석 / 같은 실적에서 확인된 별도 공급망 투자 영향 |

```text
활성 수집처·권한·경로 확인
  → 목록/피드에서 제목·머리말·식별자 발견
  → URL·원문 ID 중복 검사
  → 광고·무관 글 1차 차단
  → 섹터 / 매크로 관련성 판정
  → 필요한 원문·공식 자료·독립 보도 확보
  → 사실·출처·사건 단계·한국 영향 경로 확인
  → Story 검색 및 기존 Issue와 차이 비교
  → PASS / HOLD / 신규 작성 / 출처만 추가 / 기존 상세 수정 / 새 방향 상세
  → 게시 검사와 버전 충돌 검사
  → DB 반영 + 검색·홈·알림 갱신 요청의 원자적 기록
```

제목·머리말을 많이 보는 단계와 본문을 깊게 읽는 단계를 분리한다. 상세 작성·사건 근거 추가·팩트·맥락 평가는 확보한 본문/공식 자료로 수행한다. 검색 요약만으로 상세 전체를 작성하지 않는다.

## 3. 매체별 수집 등록과 경로 {#sources}

### 3.1 수집처 상태

수집처 상태 집합은 `CANDIDATE / RIGHTS_HOLD / TECH_TEST / SHADOW / ACTIVE / PAUSED_RATE_LIMIT / PAUSED_ACCESS / PAUSED_ERROR / DISABLED`이다. 시트 신규 행은 CANDIDATE이며 곧바로 ACTIVE로 만들지 않는다. `ENDPOINT_UNVERIFIED`, `BOT_ADAPTER_UNVERIFIED`는 별도 상태가 아닌 차단 사유다. 여러 사유를 동시에 보존한다. CANDIDATE는 평가 전 등록 단계이며 요청 실행 불가다. 첫 평가에서 권한 미확인이면 RIGHTS_HOLD / RIGHTS_UNVERIFIED로 전환하며 부록 초기값도 이를 따른다.

| 현재 상태·사건 | 다음 상태 | 재탐침·종료 규칙 초기안 |
| --- | --- | --- |
| CANDIDATE·이용 범위 미확인 | RIGHTS_HOLD | 시간 재시도 없음, 권한 정책 버전 변경으로만 재평가 |
| CANDIDATE/RIGHTS_HOLD·권한 확인 | TECH_TEST | URL/봇 방식 미확정 사유가 남으면 요청 실행 금지, 등록 경로/어댑터 변경 시 검사 |
| TECH_TEST·목록/상세/ID/시각/다음 페이지/실패 처리 검사 통과 | SHADOW | 공개·푸시 없이 처리. 미통과는 TECH_TEST 유지, 같은 구성의 무한 검사 금지 |
| SHADOW·승격 검사 통과 | ACTIVE | 5거래일, 성공 목록 검사 최소 10회, 허용 본문 최소 1건, 미해결 치명 오류 0건·관측 수집 성공률 95% 이상. 이는경로건강/품질승격이며 운영게시LIVE는제작12단계 게이트/activation_receipt 별도. 부족 표본은 그대로 SHADOW |
| ACTIVE·창작/오매칭/중복 게시/정정 미반영 탐지 | SHADOW | 해당 자동 게시 즉시 차단. 수정 버전 후 동일 승격 검사를 다시 통과해야 함 |
| SHADOW/ACTIVE·429 | PAUSED_RATE_LIMIT | Retry-After 이상 + 1·5·15분 백오프 중 느린 값, 일일 재탐침 최대 3회. 회복 검사 후 직전 상태 복귀, 실패 지속은 아래 저빈도 단계 |
| SHADOW/ACTIVE·403/로그인·유료 제한 | PAUSED_ACCESS | 명시적 인증/결제 요구는 재탐침 없음. 일시 403은 1·6·24시간 최대3회 후 저빈도 단계. 회복 검사 후 직전 상태 복귀 |
| SHADOW/ACTIVE·5xx/네트워크 장애 | PAUSED_ERROR | 1·5·15분 재시도 실패 후 1·6·24시간 재탐침 최대3회. 회복 검사 후 직전 상태 복귀, 실패 지속은 저빈도 단계 |
| 모든 상태·이용 허용 철회/경로 폐쇄 확정 | RIGHTS_HOLD 또는 DISABLED | 새 요청 중지, 13절 삭제·근거 의존 검사. 경로/권한/어댑터의 검증된 변경만 TECH_TEST로 깨움 |

가용성 장애 진입 전 `resume_state`와 권한/어댑터/품질 판본을 저장한다. 같은 판본·허용 범위이며 미해결 품질 오류가 없을 때만 5분 이상 간격의 정상 목록/파싱/ID·체크포인트 검사 2회로 복구하고 직전 ACTIVE 또는 SHADOW로 복귀한다. 유효한 빈 목록은 어댑터의 구조·조회 범위 확인을 통과해야 정상이다. 5거래일 재승격은 최초 가동 또는 **품질 강등**에만 적용하고 일시 429/5xx 회복에 다시 적용하지 않는다. 변경된 어댑터/권한은 TECH_TEST, 미해결 품질 오류는 SHADOW를 우선한다.

단기 재탐침 소진 뒤에도 일시 가용성 장애는 같은 PAUSED 상태의 `LOW_FREQUENCY` 단계로 두고 일 1회, 최대14일 자동 확인한다. Retry-After가 더 늦으면 그때까지 기다리며 이 14일 창도 최초 허용 재탐침 시점부터 계산한다. 성공하면 위 회복 검사로 복귀하고 같은 장애의 실패 횟수를 임의 초기화하지 않는다. 끝까지 실패·영구 폐쇄 확정이면 DISABLED. 명시적 로그인/유료/권한 제한에는 이 자동 재탐침을 적용하지 않는다. 재탐침 예산은 도메인/endpoint 모두에 적용한다. 장기 격리/권한·어댑터 변경이 필요한 수집처는 17절의 관리자 예외로 남기며 다른 수집·기사 운영은 사람 승인 없이 계속한다. DISABLED 자체의 무한 재시도는 없다.

권한 상태에는 목록·제목/머리말·본문·AI 입력·보관·앱 표시를 각각 기록한다. robots 허용이나 공개 로그인 가능 여부만으로 나머지 권한을 승인하지 않는다. 확인된 허용 범위 내에서만 다음 단계로 넘기며, 조건이 바뀌면 해당 경로를 중지한다.

### 3.2 어댑터 유형

| 유형 | 발견 방식 | 반드시 저장할 식별자·조건 | 기본 처리 |
| --- | --- | --- | --- |

| 증권 플랫폼 | 제공 API/허용된 목록, 원문 링크 역추적 | platform, 원매체, 원기사 ID·URL | 플랫폼을 별도 독립 취재로 세지 않음 |

| 증권사 리포트 | 등록된 기업/산업 목록 → 보고서 ID → 허용된 PDF | 증권사·작성팀·발간일·대상·PDF 해시·보고서 ID | 기업/산업 범위를 개별 적용, PDF 개정판 보존 |
| Telegram 채널 | 허용 범위를 확인한 공식 연동만 설계 대상 | 채널/메시지 ID·수정/삭제 이벤트·권한 근거 | 현재는 RIGHTS_HOLD. 계정 공유만으로 활성화 금지 |
| KB 리서치봇 | 리포트만, 명령·응답 방식 별도 어댑터 | 요청 작업·보고서 ID·응답 지점 | 일반 채널 폴링에 넣지 않음 |
| 공식 공시·IR·기관 발표 | DART·KIND·SEC·기업/기관의 공식 공개 경로 | 공시/발표 ID, 정정 관계, 실제 발표일·효력일 | 원문 접근·사용 조건을 검증한 경로만 운영 |

사이트정리의 개별 특수 조건을 보존한다: 통합 리포트는 한 번 받아 기업·산업 항목 분기, 다올은 기업분석만, NH 초대 링크는 공개 목록과 구분, 토스 주요뉴스는 탭 선택 확인. 글로벌이코노믹 70·91·92·93행은 시트 분류를 보존하되 실제 종목/시황 혼합 여부를 사전검사한다. 행 번호는 원본 좌표이고 운영 ID가 아니다.

### 3.3 Telegram에 대한 현재 설계 경계

2026.11.13 확인한 Telegram의 Content Licensing 약관에는 AI 개발·배포 등을 위한 플랫폼 데이터의 수집·활용 제한과 제한된 동의 예외가 명시돼 있다. 따라서 개인 계정으로 채널을 볼 수 있다는 사실을 AI 뉴스 서비스의 사용 허가로 취급하지 않는다. 플랫폼·권리자 조건 충족이 확인되기 전에는 메시지·첨부·URL 추출을 AI 파이프라인에 자동 연결하지 않는다. 텔레그램을 경유하지 않고 별도로 등록한 증권사 공식 리포트/뉴스/IR 경로를 사용한다. 향후 허용된 채널을 선택한다면 사용자가 고려한 20~30개 범위에서 별도 실증하되 현재 등록 53개 전체를 자동 활성화하지 않는다. [Telegram 공식 약관](https://telegram.org/tos/content-licensing), [Bot 개발자 약관](https://telegram.org/tos/bot-developers)

### 3.4 필수 등록 필드

`source_id, publisher_id, owner_group_id, source_type, market, endpoint_id, URL, tab_recipe, enabled_scopes, permission_profile, schedule_class, adapter_version, origin_resolution_rule, checkpoint, overlap_window, correction_watch, max_rps, timeout, concurrency, health_state`.

같은 URL의 서로 다른 탭은 endpoint ID를 구분한다. 같은 매체의 여러 목록은 publisher ID를 공유한다. 원문이 여러 경로에서 발견돼도 발견 이력만 여러 개이고 본문은 하나다. 로그인·보안프로그램·CAPTCHA·유료벽은 우회하지 않고 다른 허용 원출처를 찾거나 보류한다.

### 3.5 시트 외 경로와 실행 경계

부록106행은 원본 보존 대상이지 독립 매체 수나 모두 가동 중이라는 뜻이 아니다. 권한 미확인은 RIGHTS_HOLD로 표시한다. CANDIDATE는 등록 직후 평가 전 임시 상태이며 요청 실행 불가다. 첫 평가에서 이용 범위 미확인은 RIGHTS_HOLD로 전환한다. 부록의 미확인 초기값은 RIGHTS_HOLD / RIGHTS_UNVERIFIED로 통일한다.

시트 외 경로도 같은 sources/permission_profiles/endpoint/adapter 버전에 등록한다. 네이버·Brave는 검토 중인 발견 전용 검색 API이며 PLATFORM_RESOLVE·쿼리 예산 큐다. 자체 독립 근거로 세지 않는다. DART/KIND/SEC/중앙은행/정부/기업IR 등은 OFFICIAL 원문·정정 감시 경로다. 계약·기술·허용량 미확정은 비활성으로 둔다. 공식성만으로 수집·보관 허가를 추정하지 않는다.

감시 주제의 검색 표현·별칭·우선순위 수정과 기존 ACTIVE 경로 선택은 다음 회차 반영한다. 새 URL은 등록 요청이며 권한→기술→SHADOW→ACTIVE 검증을 건너뛰지 않는다. 일시 가용성 복구와 신규/품질 강등 SHADOW는 상세로직의 서로 다른 복구 절차를 적용한다.

## 4. 주기·증분 수집·호출 예산 {#scheduling}

다음은 계약 한도보다 느리게 적용하는 초기 제안값이다. 목록 확인 간격과 홈의10분 순위 회차는 다르다. 뉴스 분석·게시·정정은 준비 이벤트로 계속하며10분을 기다리지 않는다.

| 클래스 | 한국 거래일 초기 목록 주기 | 한국 비거래일 | 사용처·원문 요청 |
| --- | --- | --- | --- |

한국 시각 구간은 시작 포함·끝 미포함이며, 정확한20:00에는 FOREIGN_US 첫 순위 회차와 키워드 정비를 별도 수행한다. 콘텐츠 큐는 중단하지 않는다. 장중이 아닌 목록 주기로 바뀌어도 이미 예약한 회차는 취소하지 않는다. 예정 발표 집중 구간은 발표시각 10분 전~20분 후 초기안으로 하고 도메인 허용량이 부족하면 기본 주기를 유지한다.

주기 수치의 단일 권위는 이 표다. 부록은 각 행에 schedule_class를 지정하고 수치를 다시 정의하지 않는다. 미국 활성 구간은 미국 정규장 개장 1시간 전부터 종료 2시간 후까지이며 서머타임·조기 종료를 거래소 캘린더로 계산한다. 실제 권한상 더 느린 제한이 우선한다.

오류 복구·권한 제한은 3.1절, 비거래일 주기는 위 표, 비거래일 회차·발송 여부는 12절을 따른다. 모든 339개 기업·106개 경로를 10분마다 전체 검색하는 것이 아니다. 공통 검색식을 공유하고 신규 사건 확인·정정·오래 밀린 섹터 탐색을 우선한다. 장중에도 상승하지 않은 섹터와 악재/매크로 탐색을 중단하지 않는다.

- 공급처/endpoint/검색식 버전별 성공 체크포인트를 저장한다. 최신순의 첫 페이지 한 번으로 완료 표시하지 않는다.
- 초기 겹침 창 30분, 1시간마다 최근 6시간, 일일 최근 72시간 보완 조회를 제안한다. 실제 색인 지연에 맞춰 조정한다. 검색 공급처가 시간 분할을 지원하지 않으면 검색식을 분할하거나 다른 허용 경로로 보완하며, 지원하지 않는 파라미터를 가정하지 않는다.
- 같은 시각 기사 다수는 `(timestamp, external_id)` 경계로 처리. 날짜 없는 항목은 발견 시각과 원문 시각 미확정을 분리.
- 페이지/결과 상한에 도달하면 `PARTIAL`과 누락 범위를 남긴다. 실패/부분 성공을 ‘새 기사 없음’으로 기록하지 않는다.
- 429는 Retry-After와 지수 백오프, 403/로그인 요구는 접근 상태 전환. 5xx는 초기 1·5·15분 제한 재시도. 같은 도메인의 전체 어댑터에 호출량을 합산한다.
- 비용 예산의 초기 배분: 기본 탐색 40%, 상승/급변 섹터 추적 25%, HOLD 재판정·정정 20%, 늦은 기사 회수 15%. 각 큐 최소 처리량을 둬 특정 분야가 계속 밀리지 않게 한다.

용량 계산 예: 뉴스 39경로를 모두 2분마다 확인하면 시간당 1,170건의 **목록 요청**이다. 10분이면 234건이다. 이는 원문 수·서버 성능·실제 허용량을 검증한 값이 아닌 산술 예다. 필요한 본문 수는 ‘새 후보 수 × 1차 통과율 × 원문 필요율’로 별도 산정한다. 검색 API 호출·PDF·LLM 토큰 비용도 따로 센다. [네이버 API의 응답 범위·제한](https://developers.naver.com/docs/serviceapi/search/news/news.md), [SEC 접근 속도 정책](https://www.sec.gov/filergroup/announcements-old/new-rate-control-limits)

## 5. 수집·패스·보류 상태와 재판정 {#states}

수집 성공과 기사 채택을 같은 상태로 저장하지 않는다.

| 판단 상태 | 뜻 | 저장·다음 행동 |
| --- | --- | --- |
| DISCOVERED | 목록에서 발견 | 최소 메타데이터·식별자 확보 |
| PASS | 무관/홍보/과거 반복 등으로 처리 종료 | 사유·정책 버전·식별 해시 보관, 본문 요청 안 함 |
| HOLD | 관련 가능성 있으나 판단 근거 부족 | 부족한 항목·다음 시각·깨울 조건·종료 기한 기록 |
| COLLECT | 근거 확보 대상으로 채택 | 허용된 본문/공식 자료 요청 |
| EVIDENCE_READY | 필수 사실·영향 근거 확보 | 기존 Story/Issue와 비교 |
| DUPLICATE_LINK | 원문/내용/기존 사건 중복 | 기존 문서·출처에 연결, 새 카드 없음 |
| NEW_ISSUE | 새 사건 또는 새 보도 방향 | 새 상세 초안·게시 검사 |
| UPDATE_ISSUE | 기존 상세에 실질 추가 정보 | 변경 부분만 새 버전·게시 검사 |
| NO_MATERIAL_CHANGE | 표현/순서/단순 주가만 변화 | 근거 이력만 추가, 공개 수정 시각 유지 |
| PUBLISHED | 게시 검사 통과·반영 완료 | 검색·홈 갱신·알림 판단 |
| EXPIRED_HOLD | 기한 내 판단 불가 | 공개하지 않음, 재활성 조건만 유지 |

라우팅 명령과 처리 상태·공개 상태를 구분한다. `NEW_STORY`는 Story 생성 명령 후 NEW_ISSUE로, `NEW_ANGLE`은 같은 Story의 새 방향 명령 후 NEW_ISSUE로 이동한다. `SAME_STORY`는 관계 표기다. `CORRECTION`은 UPDATE_ISSUE의 수정 종류다. 이 명령을 별도 미종결 대기 상태로 저장하지 않는다.

공개 상태 집합은 `DRAFT / PUBLISHED / CORRECTION_PENDING / WITHDRAWN / HIDDEN`이다. 게시 검사 통과 시 DRAFT→PUBLISHED, 핵심 오류 탐지 시 PUBLISHED→CORRECTION_PENDING(해당 본문 노출 차단), 재검증 통과 시 새 버전 PUBLISHED, 근거 철회로 유지 불가하면 WITHDRAWN, 관리자가 숨기면 HIDDEN이다. WITHDRAWN/HIDDEN의 자동 재게시 금지. 처리 결정 PUBLISHED는 이 공개 반영 성공을 뜻하며 공개 상태와 한 트랜잭션으로 기록한다. 저장·알림·검색은 공개 상태를 우선한다.

CORRECTION_PENDING은 진입 시각부터 최대24시간 초기안이다. 상태 안내는 ‘내용 확인 중 · 기존 내용 제공 중지’로 통일하고 홈·검색·공유 미리보기에서 본문을 차단한다. 24시간 내 검증된 정정 또는 영향받지 않은 안전한 이전 버전이 **현재 근거·게시 검사를 다시 통과**하면 새 공개 버전과 정정 이력으로 PUBLISHED 복귀 가능하다. 자동으로 예전 본문을 복원하지 않는다. 24시간이 지나도 실패하면 WITHDRAWN으로 전환해 ‘근거 확인 불가로 게시 중단’ 안내만 저장/알림 링크에도 제공한다. 만료 검사는 24시간·비거래일에도 10분마다 실행하며 실제 deadline으로 계산하고 장중65회차에 의존하지 않는다. 새 증거가 뒤늦게 와도 WITHDRAWN의 자동 재게시 금지와 관리자 승인 예외를 유지한다.

별도의 원문 획득 상태 `UNFETCHED/FETCHED/PARTIAL/FAILED/RESTRICTED`를 둔다. FETCHED라도 PASS가 될 수 있고, 원문 한 곳이 실패해도 다른 공식 자료로 EVIDENCE_READY가 될 수 있다.

### HOLD 사유와 깨울 조건

| 사유 | 조건 충족/재시도 이벤트의 행동 | 초기 종료/완화 기준 |
| --- | --- | --- |
| H_BODY | 다른 허용 원문·공식 자료 확인 | 10·30·120분, 24시간 후 휴면 |
| H_IDENTITY | 동명이인·법인/제품·코드 대조 | 기업 마스터 변경 또는 새 근거 때 즉시, 24시간 후 휴면 |
| H_CORROBORATION | 같은 핵심 주장 독립 원출처 탐색 | 10·30·120분, 일반 24시간·정책안 72시간 |
| H_CONFLICT | 수치·단계·발표일 충돌 해소 | 새 공식 발표/정정 즉시, 활성 72시간 후 EXPIRED_HOLD, 다수결 금지 |
| H_IMPACT | 한국 섹터/시장 전달 경로 부족 | 계약·고객·제품·시장 변수 증거 추가 시, 24시간 후 휴면 |
| H_STORY | 신규/수정/새 방향 구분 불명확 | 같은 안건 새 원문 또는 30분 뒤 다시 비교, 24시간 후 휴면 |
| H_PERMISSION | 사용 범위 미확인 | 시간 재시도 금지, 활성 큐에서 즉시 EXPIRED_HOLD, 권한 정책 변경만 깨움 |

이 문서의 ‘휴면’은 모두 EXPIRED_HOLD와 같은 뜻이다. 활성 재시도·원문 보관 허가는 만료되며 최소 메타데이터만 TTL 안에서 유지한다. H_STORY/H_IDENTITY/H_IMPACT는 24시간, H_BODY는 24시간, H_CORROBORATION은 일반 24시간/정책안 72시간, H_CONFLICT는 72시간이 활성 상한이다. 권한 사유는 즉시 휴면한다.

HOLD는 홈10분 회차마다 본문 전체를 새로 내려받는 지시가 아니다. 새 근거/기한/허용된 재시도 이벤트에서 조건·증거 버전이 바뀌었는지 먼저 비교한다. 동일 입력 해시·모델·정책 버전이면 기존 판단을 재사용한다. 네트워크 재시도 예산과 판단 재시도 예산은 분리한다. 초기 자동 판단 횟수는 입력 버전당 3회, 문서당 일일 6회로 제한한다. 입력 버전 한도 초과는 EXPIRED_HOLD(H_RETRY_EXHAUSTED), 하루 한도만 초과하면 HOLD(H_DAILY_BUDGET)로 다음 한국 자정까지 쉬되 원래 활성 종료 기한을 연장하지 않는다. 기한이 먼저 오면 EXPIRED_HOLD다. 새 증거는 새 입력 버전을 만들 수 있지만 문서당 하루 예산은 초기화하지 않는다.

새 근거·정정·기업 식별 변경이 생기면 휴면 후보도 깨울 수 있다. 깨어난 과거 후보는 9절의 신선도 검사를 다시 통과해야 하며 오늘의 새 사건으로 세탁하지 않는다. EXPIRED_HOLD는 서비스 전체를 멈추지 않고 다른 큐를 계속 처리한다. 운영자는 확인할 수 있지만 정기 사람 승인이 필수인 큐는 아니다. 예약은 DRAFT+scheduled_publish_at이며 공개/작성/판정 상태는 공통계약3절처럼 분리한다.

## 6. 홍보·무관 기사 원천 차단 {#filtering}

### 6.1 세 단계 방어

1. **입구 제한:** 승인된 증권/기업/산업·해외시장·공식 발표 경로만 폴링. 일반 경제·정치·사회 홈 전체를 기본 수집처로 쓰지 않는다. 매크로 감시는 별도 승인 출처·기관 발표 경로에서 수행한다.
2. **메타데이터 필터:** 제목·머리말·섹션·스폰서 라벨·사건 단서로 PASS 또는 후보화. 명확한 배너·광고성 안내는 본문·벡터·LLM 단계에 넣지 않는다.
3. **본문 필터:** 후보 본문에서 새 사건·한국 영향 근거·홍보 의도를 다시 확인. 1차 통과를 최종 채택으로 오해하지 않는다.

판단의 핵심은 단어가 아닌 **새 사건 + 대상 + 주식시장 전달 경로**다. ‘반도체’, ‘AI’, ‘금융’ 한 단어가 있거나 주가가 올랐다는 이유만으로 통과시키지 않는다.

| 예시 유형 | 기본 처리 | 예외 |
| --- | --- | --- |
| 신규 계좌·수수료 할인·금융상품 가입·고객 사은품 | P_PROMOTION | 회사 실적/산업 제도를 바꾸는 별도 확정 사건이 있으면 그 사실만 재평가 |
| 투자 교육 영상·캠페인·시상·인사·임직원 행사 | P_NO_MARKET_EVENT | 사업 재편·경영권/회계·규제 위험처럼 실제 중요한 변화는 별도 |
| 코스피 약보합 마감·외국인 매수 등 숫자 나열 | P_PRICE_RECAP | 본문에 새 정책·수요·실적 사건이 있으면 사건만 추출 |
| 근거 없는 목표 지수·‘지금 사라’·막연한 낙관 | P_OPINION_ONLY | 새 실적 추정/공급 자료와 계산 근거가 있으면 리포트 의견으로 명시해 판단 |
| 특정 종목 실적·수주 | 조건부 COLLECT | 실체 있는 기업 사건이어야 하며 섹터 파급 또는 등록 한국기업 관련성 확인 |
| 일반 정치·사회·범죄·가십 | P_OUT_OF_SCOPE | 검증된 통상·금리·정책·공급 차질로 시장에 전달되면 매크로 경로 |
| 제품/공장/투자 보도자료 | 자동 제외 아님 | 확정 투자·생산·출하·계약 사실인지 확인, 광고 문구 제거 |
| 사후 기사에 과거 사건만 재인용 | P_OLD_RECAP | 원인 근거·과거 맥락으로 연결 가능, 신규 카드 금지 |

키워드가 없는 새 거시 사건도 `시장 변수 → 한국 시장/섹터` 경로가 검증되면 미분류 매크로 후보로 받을 수 있다. 반대로 섹터 키워드가 있어도 사건·영향이 없으면 차단한다. 본문을 보기 전 의미가 애매하면 무조건 차단하지 말고 HOLD/제한 원문 확인으로 보낸다. 오탐·미탐을 모두 측정한다.

### 6.2 기사화 가능한 범위

`SECTOR`: 등록 섹터/한국기업의 생산·수요·가격·투자·실적·공급망·경쟁·규제·재무 등에 구체적 변화.

`MACRO_MARKET`: 금리·물가·환율·유동성·통상·정치 불확실성·시스템 위험처럼 한국 시장 공통 할인율·이익·위험에 미치는 변화.

`MACRO_CROSS_SECTOR`: 운항 차질·에너지·규제처럼 여러 섹터에 서로 다른 방향으로 전달되는 변화. ‘두 섹터 이름을 언급’한 것만으로 주요 매크로가 되지는 않는다.

이 셋이 아니면 운영 기사 본문·분석 저장소로 승격하지 않는다. 사건 발생 사실이나 한국 사업·시장 전달 경로를 확인할 수 없으면 보류한다. 아직 실제 주가가 반응하지 않았다는 이유로 확정 실적·공시를 보류하지 않는다. 모든 개별 종목 뉴스를 산업 전체 뉴스로 포장하지 않는다.

## 7. 출처·팩트·맥락 검증 {#evidence}

### 7.1 사실과 해석의 근거

| 근거 | 확인할 수 있는 범위 | 주의 |
| --- | --- | --- |
| 공시·정부·중앙은행·거래소 공식 원문 | 해당 주체가 공식 발표한 사실·단계·수치 | 그 발표가 한국 모든 기업에 수혜라는 뜻은 아님 |
| 기업 IR·보도자료 | 회사의 발표·계획·현재 입장 | 회사 전망을 실현된 사실로 바꾸지 않음 |
| 언론 독립 취재 | 취재한 주장과 맥락 | 익명 취재원·다른 통신사 인용 여부 구분 |
| 증권사 리포트 | 분석·추정·투자 의견 | 리포트 추정치를 공시 실적으로 바꾸지 않음 |
| 플랫폼 재게시 | 원문 발견·유통 경로 | 독립 근거 추가로 세지 않음 |

보도 수를 원출처 수로 착각하지 않는다. `claim → source document → cited origin/report/release → reporting family`의 근거 계보를 저장한다. 같은 연합뉴스/Reuters 기사, 같은 기업 보도자료, 같은 증권사 리포트 재인용은 각각 한 뿌리다. 기사 수가 10개라도 같은 뿌리면 독립 확인은 1이다. 독립성이 불명확한 익명 인용은 확인된 독립 수에 넣지 않는다.

독립성은 원출처 계보와 `newsroom_id / owner_group_id` 두 축을 모두 검사한다. 같은 편집국의 여러 메뉴는 1곳, 확인된 같은 소유 그룹의 취재도 보수적으로 최대 1곳이다. 같은 원문 계보를 공유하는 서로 다른 그룹도 1곳이다. URL 수·매체 이름 수를 세지 않고, 서로 다른 확인된 그룹이며 같은 뿌리를 공유하지 않는 근거 3개를 고른다. 소유 그룹·편집국·원출처 중 하나라도 미확정인 항목은 3곳 승격 수에 넣지 않는다. 확인된 공식 원문 경로는 별도다. 특정 회사들이 같은 그룹인지 이 문서에서 추정 확정하지 않는다.

부록 모든 행의 origin_resolution_rule은 최소 정책이다. 직접 매체도 전재가 가능하므로 작성자·통신사·인용 보고서/발표를 기사 단위로 검사한다. Yahoo·Investing 등 재게시/혼합 경로는 원매체와 원기사 ID를 필수로 복원한다. 복원 불가면 발견 후보일 뿐 독립 근거가 아니다.

### 7.2 게시 자격과 주요 매크로 승격

| 기사 유형 | 최소 게시 근거 | A 주요 매크로 승격 |
| --- | --- | --- |
| SECTOR | 일반 기업/산업 사실은 공식 원문 1개 또는 실제 취재·핵심 근거가 확인된 원문 1개. 중대한 익명 주장·계약 미확인은 HOLD | 단순 섹터 사건은 A 아님. 시장 전반 핵심 주장을 포함하면 아래 공통 엄격 기준 적용 |
| MACRO_MARKET | 핵심 사실 직접 확인 공식 1개 또는 독립 취재 3개 + 한국 시장 전달 경로 | 같은 근거 기준에 시장 전체 중요도·현재 유효성 추가 |
| MACRO_CROSS_SECTOR | 핵심 사실 직접 확인 공식 1개 또는 독립 취재 3개 + 섹터별 영향 근거 | 같은 근거 기준에 독립된 여러 섹터의 중요한 영향·현재 유효성 추가 |

모든 핵심 claim에 `verification_class = ORDINARY_FACT / SYSTEMIC_MACRO / SENSITIVE_UNCONFIRMED`를 판정한다. SYSTEMIC_MACRO는 기사 유형/노출 영역과 무관하게 공식1 또는 독립3을 요구한다. 금리·통상 같은 주장을 SECTOR로 재분류해 낮은 기준으로 게시할 수 없다. 보도2개뿐인 비공식 매크로는 A뿐 아니라 B/C·일반 목록에서도 의도적으로 HOLD한다. ‘일반 매크로’라는 이름의 완화 경로는 없다. 3곳 확인은 중요도 점수가 아니므로, 기준을 충족해도 중요도가 낮으면 A에 승격하지 않고 다른 공개 경로만 사용한다.

- 일반 섹터 사건: 검증 가능한 공식 원문 하나, 또는 등록된 매체의 실제 취재·대상·핵심 근거가 확인된 원문으로 사실 작성 가능. 익명 단독의 중대 주장·미확인 계약·수치 충돌은 보류. 공식 확인 없이 수주를 확정했다고 쓰지 않는다.
- 주요 매크로: 기존 기준을 유지해 **핵심 사실을 직접 확인하는 공식 원문 1개 또는 독립 취재 매체 3개**를 요구한다. 여기에 한국 시장 공통 변수 또는 독립된 여러 섹터로의 영향 경로, 이번/다음 거래 구간의 유효성이 있어야 한다.
- 공식 선거 결과로 확인할 수 있는 것은 당선/의석이다. 데이터센터 규제 시행은 해당 법안·행정조치 근거를 별도로 확인한다.
- 같은 핵심 주장에 2개만 확보됐으면 주요 매크로 승격은 HOLD. 일반 기사로 내려 게시하는 우회로 동일한 미확인 주장을 사실로 유통하지 않는다.
- 서로 다른 수치/단계가 충돌하면 매체 다수결·AI 확신으로 확정하지 않는다. 공식 정정·대상 기간·통화·단위·gross/net 차이를 확인한다.
- 맥락은 `사건 → 수요/가격/공급/투자/할인율 → 한국 섹터 → 근거 있는 기업`으로 작성한다. 중간 고리가 없으면 영향 불확실 또는 제외.

확신 점수는 검토 순서 보조값이지 게시 허가가 아니다. 모든 핵심 사실은 출처 ID·근거 구간·확인 상태를 가져야 한다. 사건 발생·원문 발행·수집·최초 앱 게시·최근 수정·가격 시각을 별도 저장한다.

## 8. 중복 수집·저장·생성 방지 {#dedupe}

‘중복 수집 불가’는 같은 본문을 반복 저장·분석·게시하지 않는다는 뜻이다. 새 기사 발견을 위한 목록 재조회와 정정 확인까지 금지하면 누락이 생기므로 이를 구분한다.

| 층 | 유일성/비교 | 중복이면 |
| --- | --- | --- |
| 예약 회차 | job type + endpoint/query version + scheduled time | 같은 작업을 다시 만들지 않음 |
| 원출처 문서 | publisher + native article/report ID | 기존 source_document 참조 |
| URL 별칭 | origin + 정상화 URL / 플랫폼 원문 연결 | 원문 하나에 URL aliases 연결 |
| 본문 판본 | document ID + normalized content hash | 판본·LLM 재처리 생략 |
| 전재·번역 | 원통신사/보도자료 ID + 사실·대상·기간 + 내용 비교 | origin family 연결, 독립 근거 수 증가 없음 |
| 사건 안건 | 대상·행동·대상물·회계기간/결정 ID·사건 단계의 조합 | 기존 Story 후보 탐색 |
| 공개 상세 | Story + 보도 방향 + 독립 사건/중요 전환 식별자 | 같은 Issue에 연결/수정 |
| 게시·알림 효과 | Issue + version + effect type / 설치 + 알림 cause key | 같은 효과를 두 번 실행하지 않음 |

제목 유사도·임베딩은 후보 검색에만 사용한다. 같은 제목이라도 회사·분기·계약이 다르면 별도 사건이다. 다른 제목·언어라도 같은 발표면 한 원출처/사건이다. ‘삼성’처럼 법인이 애매하면 확정 병합하지 않는다.

### URL 정상화

확인된 추적 파라미터·불필요한 fragment만 제거한다. `articleId`, `newsId`, `sc_section_code`, 보고서 ID·탭 식별자처럼 의미 있는 값은 보존한다. 짧은 링크·canonical은 허용 도메인으로 검증하고 리디렉션별 최종 URL을 기록한다. 조회용 URL과 원기사 ID를 모두 남긴다. 서명 URL에서 임의 파라미터를 제거해 다른 자료로 오인하지 않는다.

### 동시 실행과 정정 재확인

DB unique 제약 + 트랜잭션 + 문서/안건 잠금을 함께 사용한다. LLM이 같은 사건에 다른 키를 만들 수 있으므로 잠금 안에서 최신 Story/claim 집합을 다시 비교한다. 이미 게시된 근거와 실질 차이가 없으면 신규 쓰기를 차단한다. 같은 회차 두 작업이 하나의 사건을 만들려 하면 하나만 반영한다.

아직 없는 Story도 잠글 수 있도록 LLM이 만든 문자열을 잠금키로 쓰지 않는다. 검증된 기업 ID와 사건 유형을 바탕으로 안건 판정 파티션을 직렬화한다. 기업 사건은 `(entity_id, event_family)` advisory lock 안에서 회계기간·공시/계약/결정 ID·기존 claim을 재조회한다. 여러 기업이면 정렬한 entity ID 순으로 잠가 교착을 막는다. 모든 거시 사건은 발표 기관·키워드 등록 여부와 관계없이 **MACRO_ALL 고정 advisory lock** 안에서 기존 거시 안건과 비교한다. 단일 기관/결정 ID가 없는 해협 운항 차질·지정학 충돌도 이 경로로 처리한다. 초기 거시 처리량에서는 전체 직렬화를 우선하며 실제 병목 측정 전 임의 분할하지 않는다. 기업·거시 잠금이 함께 필요한 작업은 MACRO_ALL→정렬 entity ID 순서를 지킨다.

거시 사건 안에서는 확인된 actor/지역·사건 유형·발생 시각/기간·핵심 사실을 비교하되 authority_id는 선택값이다. 외부 결정 ID가 있으면 정규 사건키에 사용하고, 없으면 잠금 안에서 기존 사실 집합과 대조해 서비스가 canonical_event_identity를 한 번 배정한다. `(event_family, canonical_event_identity)`와 공식 결정 ID/기업 회계기간 정규키에 unique를 둔다. 다음 날 후속 보도도 같은 실제 사건이면 기존 identity를 사용하며 날짜 버킷만으로 새 Story를 만들지 않는다. 대상/발생 사실 자체가 충돌하거나 기존 안건과 구분할 수 없을 때만 H_IDENTITY/H_STORY로 보류한다. 단일 발표 기관이 없다는 이유는 보류 사유가 아니다. 이 경우도 7절 공식1/독립3과 한국 영향 검증은 그대로 적용한다.

URL이 같아도 공식 수정 시각·ETag·본문 해시가 바뀌면 새 source_revision으로 재확인한다. 변경 이력이 없는 경우 초기 2시간·24시간 확인, 이후 활성 주요 안건/정정 알림 중심으로 제한한다. 캐시/304 지원은 endpoint별 확인한다. 불변 URL 전체를 영구 재다운로드하지 않는다. [PostgreSQL의 유일성 충돌 처리](https://www.postgresql.org/docs/current/sql-insert.html)

LLM 후보 추출·근거 비교 초안은 DB 잠금 밖에서 한다. 정부/기관 조치·정책·시장 공통 사건 또는 SYSTEMIC_MACRO 핵심 claim이 있거나 그 분류가 불확실하면 기사 표제와 관계없이 MACRO_ALL 파티션으로 보낸다. 기업 직접 사실만 확인된 사건만 entity/event_family 경로를 사용한다. 교차 사건도 MACRO_ALL→정렬 entity ID→정렬 Story ID 순으로 잠근다. 사후 병합도 같은 순서다.

병합 전 양쪽 Story의 거시/기업 분류와 필요한 entity 집합을 읽어 잠금 계획을 만든다. MACRO_ALL(해당/분류 불확실 시)→정렬 entity ID→정렬 Story ID 순으로만 진입한다. 잠금 후 다른 파티션/기업 잠금이 필요함을 알게 되면 전부 풀고 계획을 다시 만들어 처음부터 순서대로 재진입한다. 이미 Story 잠금을 잡은 상태에서 상위 파티션 잠금을 추가하지 않는다.

잠금 안에서는 최신 catalog/policy·canonical key·사실 집합을 재조회하는 짧은 결정/커밋만 한다. DB lock_timeout 초기2초·transaction5초, 실패 시 HOLD(H_CONCURRENCY) 후 재시도한다. 원문/LLM 네트워크 호출을 잠금 안에 두지 않는다. 불확실하면 초안을 저장하고 잠금을 풀어 재분석 후 expected_version 검사로 재진입한다. 외부 결정 ID unique와 정규 사건/Issue 방향 unique·outbox 효과키가 함께 중복을 막는다. 실제 처리량·교착은 구현 시험으로 검증한다.

## 9. 같은 안건의 신규·수정·새 방향 분리 {#story-routing}

제목 문구가 아니라 **현재 독자가 알아야 할 결론이 달라졌는지** 판단한다. Story는 하나지만 Issue는 조건에 따라 여러 개일 수 있다.

| 들어온 내용 | 처리 | 예시 성격 |
| --- | --- | --- |
| 새 회사/새 회계기간/별도 계약/다른 공식 결정 | NEW_STORY + NEW_ISSUE | 다음 분기 실적, 별도 신규 수주 |
| 같은 발표를 다른 매체가 반복 | DUPLICATE_LINK | 출처만 추가 |
| 기존 주장 근거를 독립 취재로 보강 | 기존 근거 갱신 | 공개 문구가 바뀌지 않으면 수정 시각 안 바꿈 |
| 같은 사건의 확정 수치·시행일·일정 추가 | UPDATE_ISSUE | 알려진 계약의 세부 납기 추가 |
| 통화·단위·오타·잘못된 수치 정정 | CORRECTION | 사실 의존 문장·영향 연결 재검사 |
| 같은 자료의 표현·논조·추상 전망만 변경 | NO_MATERIAL_CHANGE | ‘기대감 확대’ 제목 반복 |
| 사실은 같지만 실제 새 근거로 다른 한국 영향 경로 발견 | SAME_STORY + NEW_ANGLE | 기존 수요 호재와 별개로 공급 병목·원가 부담 확인 |
| 계획→확정→시행 등 단계 변경 | 우선 UPDATE, 아래 기준 충족 시 NEW_ANGLE | 단순 일정 확정과 새로운 수출 금지 발효를 구분 |
| 주가·거래량만 변함 | 가격·순위만 갱신 | 기사 다시 쓰지 않음 |
| 같은 사건의 호재·악재를 나눠 제목만 변경 | 기존 상세의 수혜/피해 함께 작성 | 같은 내용을 카드 두 개로 쪼개지 않음 |

### NEW_ANGLE 허용 조건 — 모두 충족

1. 기존 Issue의 핵심 주장·영향·근거와 비교한 차이 표가 있다.
2. 새로운 검증 가능한 사실/공식 단계 변화가 있거나, 이전에 없던 한국 영향 경로를 뒷받침하는 **새로운 근거**가 있다. 작가 의견만 바뀐 경우 불충족.
3. 독립적인 제목·핵심 설명으로 쓸 실질이 있고 대상 제품·영향 방향·기업군·투자 판단 조건 중 중요한 변화가 있다.
4. 기존 상세의 추가 문단만으로 충분한지 검사한다. 충분하면 UPDATE를 우선한다.
5. Story의 기존 Issue 전부와 재비교해 같은 새 방향이 이미 있는지 확인한다.

같은 규제가 ‘발표’에서 ‘시행’으로 바뀌어도 모든 단계마다 새 글을 만들지 않는다. 실제 금지 품목 확대·한국 공급망 전환 등 중요한 효과가 새로 확인되면 분리 가능하다. 분리 시 `parent_story_id, related_issue_id, angle_code, new_claims, impact_delta, split_reason`을 저장하고 기존 글에 후속 관계를 표시한다. 최초 보도·단순 해설·주가 반응만으로 무한 분리하지 않는다.

### 사후 중복 병합

이미 생긴 중복 Story/Issue는 같은 사실·기간·방향임이 검증될 때만 병합한다. 단순 유사도만으로 자동 병합하지 않는다. MACRO_ALL(해당/분류 불확실 시) → 정렬 entity ID → 정렬 Story ID 순 잠금 → 정규 사건/방향 재검증 → 최초 공개가 빠른 유효 ID를 정규 ID로 선택(동률 고정 ID) → 원문·claim·버전 계보 연결 → 옛 ID를 MERGED 리다이렉트로 영구 식별한다. MERGED는 관계/별칭 상태이며 5절 공개 상태를 대체하지 않는다. 별도 새 방향은 Story만 통합하고 Issue는 유지한다.

서버 resolver가 정규 Issue를 반환하면 앱이 기기 저장소의 ID를 치환·중복 제거하고 과거 저장 시각은 보존한다. 조회는 원시 event ID와 설치·정규 Issue 기준으로 재집계하며 더하지 않는다. 발송 이력·대기 outbox의 원인키도 정규 Story에 연결해 중복 발송을 막는다. 과거 공개 버전·당시 순위는 감사용 불변으로 보존하고 현재 홈/검색/집계 snapshot은 새 버전으로 원자 재발행한다. 병합 중간 상태를 앱에 공개하지 않는다. 수동 보호/상이한 사실 충돌이 있으면 자동 병합하지 않고 해당 후보를 보류한다.

### 신선도·과거 자료

원문 게시일이 오늘이어도 사건이 작년이면 오늘 사건으로 쓰지 않는다. 최근 72시간을 우선 탐색하되 장기 규제·프로젝트는 활성 안건으로 재조회할 수 있다. 늦게 확보한 지난 자료는 근거 보강으로 연결한다. 오래된 사실에서 새 영향이 실제 발생한 경우 ‘무엇이 오늘 달라졌는지’를 설명해야 새 방향 자격이 생긴다.

## 10. 공통 상세 작성과 게시 검사 {#writing}

### 10.1 작성 입력

LLM에는 원문 전체를 무제한 나열하지 않고 검증된 사실 묶음, 근거 구간·출처 ID, 사건 시각·단계, 기존 Issue/claim 차이, 한국 영향 연결과 미확정 항목을 제공한다. 원문 안의 명령·코드·외부 전송 요청은 기사 데이터로만 취급한다. 모델은 DB 쓰기·순위 변경·외부 발송 권한을 갖지 않는다.

초기 작업 분리: 1차 관련성/홍보 분류 → 사실·안건 차이 추출 → 상세 작성 → 규칙 기반 + 별도 검증 단계. 같은 모델의 ‘자기 확신’만으로 통과시키지 않는다. 검증 실패 시 문제 필드만 수정하고 입력 버전당 최대 2회 재작성 후 EXPIRED_HOLD(H_REWRITE_EXHAUSTED). 새 근거 없는 반복 생성을 중단한다. 문제 필드 수정은 판단 호출 한도와 별도 카운트이며 하루 비용 상한을 함께 지킨다.

### 10.2 작성 필드

| 필드 | 작성 기준 | 필수 여부 |
| --- | --- | --- |
| 제목·카드 설명 | 기사 핵심을 축약, 사건 주체·변화 정확, 낚시·무조건 수혜 표현 금지 | 필수 |
| 핵심 이슈 | 확인된 사건·수치·제품·단계, 각 주장에 근거 ID | 최소 한 항목 필수 |
| 이슈 분석 | 한국 전달 경로와 왜 중요한지, 사실·분석 구분 | 필수 |
| 수혜/피해/연관 섹터·기업 | 한국 사업 연결·영향 방향·경로·근거·조건. RELATED는 방향 미확정 | 추가개정 노출 결정표 적용 |
| 예상 시나리오 | 한국 관점의 긍정만 또는 긍정·부정, 예상결과·체크사항 | DAMAGE_ONLY는 숨김. 부정 단독 금지 |
| 리스크 체크리스트 | 실제 불확실성·공급·집행·경쟁 조건, 주의 배지 한 단계 | 근거 있는 경우만 |
| 주요 일정 | 실제 날짜·시간대·발표/시행 근거 | 일정 있을 때만 |
| 뉴스 출처 | 원문 제목·매체/기관·원문 시각·URL·역할·정정 상태 | 필수 |

긴 분석 문단 외 짧은 목록은 명사형을 유지하되 사실/예상을 모호하게 만들지 않는다. ‘한줄 정리’는 추가하지 않는다. 기업 검색 설명을 본문에서 임의로 더 세분화하거나 확정 사업으로 고치지 않는다. 서식은 기존 HTML/앱 상세 템플릿을 따른다.

### 10.3 게시 차단 조건

출처 부재, 핵심 주장 근거 미확보, 원문/발표일 불명확으로 신선도 판단 불가, 기업 오인, 중요한 숫자·단위·통화·기간 불일치, 핵심 근거 충돌, 한국 영향 논리 부족, 광고성/범위 밖, 공개 중복, 권한 부적합은 게시 차단이다. 단순 형식 오류는 수정 후 재검사한다. 핵심 사실은 충분하고 일정만 없으면 일정 영역만 숨긴다.

저장 계약: `article_type, story_id, issue_id, angle_code, primary_sector_id?, related_sector_ids[], title, summary, key_claim_ids[], analysis, impacts[], scenarios[], risks[], schedule[], source_refs[], publication_state, scheduled_publish_at?, version, policy_version, catalog_version, generator_version, evidence_version`.

섹터 기사는 활성 대표 섹터 1개 필수. 매크로는 대표 섹터가 없어도 가능하다. 관련 섹터·기업마다 실제 근거가 필요하며, 섹터가 같다는 이유로 전체 기업을 자동 채우지 않는다.

### 10.4 수정·정정·철회·수동 보호

- 공개 본문이 실질 변경될 때만 새 article_version과 수정 시각을 만든다. 최초 게시 시각·기존 저장 ID·조회 이력은 유지한다.
- 기존 글에 추가 보도 디테일이 들어가면 변경 근거와 요약을 보존한다. 출처만 추가한 경우 본문 최신성을 부풀리지 않는다.
- source revision → claim → 문장·숫자·기업 연결·카드·검색·알림의 의존 관계를 추적한다. 정정이 핵심을 무너뜨리면 즉시 홈/검색 노출을 중지하고 5절 CORRECTION_PENDING 및 공통계약9절을 적용한다. 기존 본문을 차단하고 재검사 통과 버전만 새 공개 버전으로 제공한다.
- 수동 보호 글의 AI 변경은 제안으로 저장한다. 안전상 잘못된 내용의 노출 차단은 수동 보호와 무관하게 적용할 수 있지만 본문 자동 덮어쓰기·관리자 숨김 글 재게시는 금지한다.
- 관리자/봇 동시 변경은 `expected_version`과 현재 버전이 다르면 재검사한다. 오래된 AI 초안으로 새 편집을 덮지 않는다.
- 발송된 푸시는 회수됐다고 표시하지 않는다. 클릭하면 최신 정정/철회 안내를 열고 원래 잘못된 본문을 캐시에서 계속 보여주지 않는다.

## 11. 홈 배치와 이슈 순위 {#home}

### 11.1 수집처 순위와 홈 순위 분리

포털 인기순·언론사 메인 배치·텔레그램 조회수·검색 결과 순위를 홈 순위로 복사하지 않는다. 홈은 **우리 기사 자격 + 한국에 대한 중요도/시장 신호 + 우리 앱 관심도 + 사건 다양성**으로 구성한다. 같은 사건의 여러 보도는 인기 점수를 중복 가산하지 않는다.

### 11.2 배치 우선순위

| 영역 | 자격·정렬 | 초기 표시 한도 |
| --- | --- | --- |
| A 주요 매크로 | 7절 확인 + 한국 시장 경로 + 현재 유효성. 사건 중요도·근거·실제 조치 시각 순 | 2개 |
| B 새 주요 이슈/시장 신호 없는 주요 이슈 | 장전 비교 대상 없음, 장중 중대한 새 발표, 장후 실적·공시, 중요한 기존 글 업데이트 | 3개, 보통 60분, 무시세 주요 사건은 최대 다음 장전 재평가 |
| C 홈 이슈 순위 | 공개 자격 + 유효 시장 지표 또는 조회수 모드의 자격 | 20개 |

모든 영역에 걸쳐 Story 하나는 한 번만 노출한다. 우선 A → B → C. 공통계약2절의 lane 자격·기존대표 유지·실질변화·동률 해소 규칙에 따라 하나를 대표 카드로 고르며 나머지는 상세 후속 연결·이슈체크/검색에서 찾을 수 있다. 섹터별로 같은 안건을 복제하지 않는다. A/B의 실제 순위 숫자와 C 점수를 혼동해 표시하지 않는다.

A/B/C 모두 7.2절 유형별 최소 게시 근거를 통과해야 한다. A로 못 올라간 매크로를 B/C에서 더 낮은 근거로 게시하지 않는다. A는 최초 중요 변화 확인 후 6시간을 초기 유효기간으로 두고 10분마다 철회·중요도·한국 경로를 재검증한다. 표현/출처 추가로 기한 연장 금지. 새 실질 변화가 확인되면 같은 Story의 valid_until을 재계산하되 해당 다음 한국 정규장 종료를 넘기지 않는다. 만료는 A만 제거하며 기사 자체는 유효할 때 목록/검색에 남는다. B 만료 뒤에도 자격이 맞으면 C에 갈 수 있다.

### 11.3 기간과 섹터 필터

여섯 날짜 버튼 오늘·어제·이번주·지난주·이번달·지난달의 뜻은 한국 달력과 **최초 앱 게시일**이다. 오늘/어제는 단일 날짜 표시를 유지한다. 업데이트로 최초 게시일을 바꾸지 않는다.

최초 진입 홈은 **실시간** 상태이며 날짜 버튼은 미선택이다. 일곱 번째 기간 탭은 추가하지 않는다. 콘텐츠 위 상태줄에 ‘실시간 · 실제 시작~종료 · 거래일 기준’을 표시한다. 버튼을 고르면 달력 보기로 전환하고, ‘실시간으로’ 링크로 기본 상태로 돌아온다. 달력 오늘과 거래 구간을 같은 선택값으로 부르지 않는다.

실시간 C는 한국 시각 **09:10 이상~20:00 미만 KR**, **20:00 이상~다음09:10 미만 FOREIGN_US**로 전환한다. 한국 비거래일에는 KR을 만들지 않고 FOREIGN_US를 유지한다. 20:00은 해외 기준 첫 회차이며 한국 기준 마지막 회차는19:50이다. 한국 기준은 거래일 D, 직전 한국 정규장 종료 직후~회차 cutoff를 후보 창으로 고정한다. 해외 기준은 다음 한국 거래일 D, 직전 한국 정규장 종료 직후~회차 cutoff를 사용한다. 금요일 장후·주말·연휴를 빠뜨리지 않는다. 09:10 전환 때 D·하한을 유지하며 market_basis만 바꾼다. 20:00 전환 때 다음 D로 이동한다. 최초 게시일·Story/Issue ID는 바꾸지 않는다. A/B의 이전 글은 현재 실질 변화가 있을 때 최초 날짜+업데이트 일시를 표시한다. 뉴스 게시와 별개로 C만10분 스냅샷이다. 전환 실패는 현재 모드의 지연/미확보로 표시하고 다른 시장의 직전 순위를 현재 순위로 재사용하지 않는다. 구모드 결과는 기준시각·시장명을 붙인 별도 과거 참조로만 제공한다.

달력 보기의 후보는 스냅샷이 아니라 **선택한 한국 달력 기간에 최초 앱 게시된 Issue 전체**에서 만든다. 현재 공개 자격을 다시 검사하고 숨김 본문을 복원하지 않는다. 현재 A/B를 끼워 넣지 않는다. 달력 홈도 전체 선택기간에서 Story당1개다. 해당 기간 안의 Issue 중 최초 게시시각이 가장 최근인 것을 대표로 선택하고 동률은 고정ID로 정한다. 실시간 대표 선정과 달력 후보 선정은 서로 별도다. 이슈체크·검색은 방향별 Issue를 모두 제공할 수 있다.

선택한 대표 Issue를 실제 최초 게시 한국 날짜별로 묶고, 날짜 안에서는 **최초 게시시각의 시장 구간(calendar_rank_segment)**으로 각각 한 번만 배정한다. 한국 거래일은00:00~09:10 미만 FOREIGN_PRE,09:10~20:00 미만 KR_DAY,20:00~24:00 미만 FOREIGN_POST의3구간이며 한국 비거래일은 하루 전체 FOREIGN_DAY다. 구간 시작 포함·끝 미포함이다. 각 구간의 마지막 완성 C 스냅샷(오늘은 해당 구간 안의 현재까지)만 참조한다. 쿼리는 한국 날짜·market_basis·target_D·구간 시작/끝·cutoff를 함께 고정한다. 정상 종료 cutoff는 FOREIGN_PRE09:00,KR_DAY19:50,FOREIGN_POST/FOREIGN_DAY23:50이다. 평일 오전 글의 KR19:50 순위를21:00 이후 해외23:50 순위로 대체하지 않는다. FOREIGN_PRE와FOREIGN_POST도 같은FOREIGN_US라는 이유로 합치지 않는다. 한국 비거래일의FOREIGN_DAY는 실제 미국 거래일·시세시각을 표시한다. 해당 구간이 아직 시작되지 않았으면 미래 그룹을 만들지 않으며, 구간 스냅샷이 없으면 다른 구간으로 대체하지 않고 그 구간만 미확보로 표시한다. 기간 전체 Story1개 대표 선정 후 구간으로 배정하며, 순위 대조도 그 한국 날짜·구간에 최초 게시된 Issue만 남긴다. 스냅샷에 없는 적격 글은 해당 구간의 ‘당시 순위 미포함’에 최초 게시 최신순으로 보존한다. 날짜 그룹은 최신 날짜 순, 날짜 안 구간은 시작시각 역순, 구간 안은 당시 순위→미포함 순으로 제공하고 각 머리에 시장 기준·실제 cutoff·target_D를 표시한다. 서로 다른 시장/구간 순위 번호·점수는 합산·비교하지 않는다. 과거 순위는 당시 정책·기사버전·시장시각을 유지하고 최신 점수로 가장하지 않는다. 한국 날짜 선택·최초 게시일은 바꾸지 않는다.

섹터 선택은 B/C·일반 목록에 실제 연결된 섹터를 적용한다. 시장 전체 A는 필터 위 별도 ‘시장 전체’ 영역으로만 제공하고 선택 섹터 기사처럼 표시하지 않는다. 달력 보기에는 이 예외도 없다.

SourceDocument는 원문, Story는 실제 사건, Issue는 앱 상세의 방향이다. Story 1:N Issue, Issue 1:N article_version. 새 사실·새 영향 경로와 독립 제목의 실질·기존 상세로 처리 불충분·기존 방향 전수 비교를 모두 통과한 경우만 NEW_ANGLE로 별도 Issue를 만든다. 일반 후속은 UPDATE 우선. 표현·주가 반응만 바뀌면 새 글을 만들지 않는다.

조회·저장은 Issue 단위이며 부모의 조회를 새 방향에 복사하지 않는다. 홈은 A→B→C 전체에서 Story당 한 카드다. 대표 Issue는 공개·자격 통과 후보 중 A 자격 우선, 다음 B 자격, 다음 기존 대표가 자격을 유지하면 유지한다. 새 실질 변화로 상위 lane 자격이 생길 때만 교체한다. 동률은 최근 material_change_at, 최초 published_at, 고정 Issue ID 순이다. C의 조회 점수 변동만으로 대표를 바꾸지 않는다. 다른 방향은 상세 후속 링크·이슈체크·검색에서 제공한다.

### 11.4 가격 기준과 대표 섹터

FOREIGN_US는 버전 고정 미국 벤치마크를 사용한다. 미국 정규장 중 현재가/직전 정규장 종가, 정규장 밖 최근 완료 정규장 종가/그 이전 종가 수익률이다. 휴장에는 실제 기준 거래일·시각을 유지한다. 해외 연관기업 R열 전체를 무조건 평균하지 않는다. 비교군은 실제 동종·수요 지표와 제품 관련성을 검증해 별도 버전으로 고정한다. 공급사·고객·지주사를 섞는 자의적인 조합이나 가장 많이 오른 한 기업 사후 선택을 금지한다.

한국은 대표 섹터의 고정 구성 종목 동일 비중 평균을 초기안으로 사용한다. 시작 기준은 전 거래일의 검증된 정규장 종가, 관측값은 같은 공급처·가격 세션의 현재가다. 장기 성과는 동일한 조정 기준과 거래일 캘린더를 사용하며 뉴스 날짜와 별도 설정한다.

유효성 게이트는 홈M과 섹터랭킹 모두에 적용한다. 같은 종목은 한 섹터에서 1번 계산. 유효 비율 70% 이상, 유효 수 `min(3, 등록 구성 수)` 이상을 초기안으로 한다. 소수/단일 구성은 대표기업 기준임을 표시한다. 가격 누락을 0%로 채우지 않는다. 다른 시장·휴장·가격 시각·NXT 세션이 뒤섞인 값은 같은 비교에 넣지 않는다.

미국 비교 지표가 없는 카테고리·시장 전반 매크로·불충분한 시세에는 M을 만들지 않는다. 해당 기사는 B 등 순위 밖 경로를 사용한다. 조회수순은 가격이 없어도 자격이 맞으면 가능하다. 대표 섹터는 실제 사건의 1차 영향 대상으로 정하고 자격 검증 후 고정한다. 더 잘 오른 관련 섹터로 매번 바꾸지 않는다.

### 11.5 혼합 산식과 표본 부족

기존 초기안 `S = 100 × (0.60M + 0.30P + 0.10F)`를 유지한다.

- M: 대표 섹터 중복을 제거한 유효 비교군에서 부호 있는 기간 수익률의 평균 순위 백분위. 음수도 부호를 유지하며 손실 절댓값을 상승으로 쓰지 않는다.
- P: 최근 24시간의 우리 앱 유효 UV를 Issue 기준으로 중복 제거한 값의 순위 백분위. 언론사·플랫폼 조회수는 사용하지 않는다.
- F: `max(0, 1 - 최초 게시 후 경과시간/24시간)`. 단순 수정·출처 추가로 리셋하지 않는다. 중요한 업데이트는 B의 제한된 유효성으로 반영한다.
- 비교 대상 2개 이상일 때 `percentile(x) = (작은 값 수 + (동률 수 - 1)/2) / (N - 1)`. 모두 같은 M 또는 단일 대상 M은 0.5. P가 모두 0이면 0. 단일 양수 P는 형식상 1이지만 표본 게이트를 우선 적용한다.

초기 조회 표본 게이트: 비교 가능한 기사 5개 이상, 유효 UV 합계 50 이상. 미달이면 P를 끄고 M/F 비중을 6:1로 재정규화한다. 이는 검증 전 제안값이며 실제 트래픽으로 조정한다. 조회 0과 집계 장애는 별도 상태다. 특정 기사만 집계가 누락되면 그 기사를 0으로 벌점 처리하지 말고 회차 전체 P를 끈다. M이 없는 기사를 0%로 만들어 혼합에 넣지 않는다.

숫자 예: M=.80, P=.50, F=.75이면 70.5점. P 비활성이고 M=.80, F=.75이면 약 79.29점. 이 점수는 실제 등락률이 아니며 앱에 내부 점수/UV를 노출하지 않는다.

### 11.6 다양성과 안정성

| 모드 | C 정렬·표본 부족/장애 | 섹터 제한·발견 슬롯 |
| --- | --- | --- |
| 혼합 | M/P/F. P 부족·장애는 M/F 6:1, M 없음은 혼합 C 제외·B 자격시 B·그 외 이슈체크/검색. 조회수순 모드는 별도 | 이 모드에만 아래 상위10 제한·발견 슬롯 적용 |
| 등락률 높은순 | 검증된 부호 있는 대표 섹터 수익률 내림차순, 동률 중요도→최초 게시→ID. 무시세 제외 | 적용 안 함. Story 1회와 A→B→C 중복 제거만 공통 |
| 조회수 많은순 | 정상 집계된 최근24시간 UV 원수 내림차순. 5기사/50UV는 혼합 P 활성 게이트만 해당. 표본 작아도 실제 UV 정렬, 모두0은 최신순·표본 부족 표시. 장애는 최신순·조회 집계 지연 표시 | 적용 안 함. Story 1회 공통, 미시세도 게시 자격이면 가능 |

장애 시 다른 기준으로 바뀐 화면을 순수 조회수순이라 표시하지 않는다. 서버는 effective_sort와 지연 사유를 함께 내려준다. A/B 영역은 세 모드 공통이며 C 정렬 점수에 더하지 않는다.

- C 상위 10개에 같은 대표 섹터 최대 2개 초기안. 전체에는 같은 Story 한 개. 완전히 동일한 사건은 섹터가 달라도 중복 금지.
- C의 5·10·15·20번을 검증된 새 Issue 발견 슬롯으로 초기 제안한다. 이미 A/B나 C에 등장한 사건은 제외하고, 후보가 없으면 일반 점수순으로 채운다. 가짜 조회는 부여하지 않는다.
- 동률은 검증된 사건 중요도 → 최초 게시 시각 → 고정 Issue ID 순. 미세 변동만으로 순위를 매 분 흔들지 않고 10분 스냅샷으로 발행한다.
- 최종 순서와 원래 점수·다양성 조정 이유를 관리자에 보존한다. 새 슬롯/섹터 제한이 적용된 목록을 순수 등락률순이라고 표시하지 않는다. 순수 등락률 모드는 시장 성과 기준 정렬을 유지하며 새 이슈는 B에서 발견한다.
- 관리자 고정/제외는 사유·만료가 필요하고 게시 자격을 우회할 수 없다. 섹터랭킹 화면 자체에는 조회·최신성을 섞지 않는다.

공개 목록은 PUBLISHED만 반환한다. 알려진 Issue ID의 resolver는 본문 API와 분리해 canonical_issue_id·공개 상태·안내를 반환한다. HIDDEN/WITHDRAWN/CORRECTION_PENDING의 본문·민감한 내부 사유는 반환하지 않는다. 존재하지 않는 ID와 비공개 본문을 구분하는 안내 범위를 제한하고 공개 ID 추측으로 내부 원문을 읽을 수 없게 한다.

저장 목록은 해당 ID의 안내 항목을 유지하고 사용자가 삭제할 수 있다. 서버는 병합된 정규 ID를 알려주고 앱은 기기 저장소의 ID를 치환·중복 제거하며 최초 저장시각을 보존한다. 서버가 로컬 저장을 직접 고친다고 가정하지 않는다. 병합의 옛 ID는 redirect 관계이며 공개 상태가 아니다. 조회는 정규 Issue로 재집계하고 부모·자식 조회를 단순 합하지 않는다.

## 13. 보관·삭제·재활용 {#storage}

권한 프로필의 제한이 아래 초기 보관 제안보다 우선한다. 본문 사용·보관이 허용되지 않으면 해당 본문을 저장하지 않는다. 원문 전체 복제와 근거 최소 저장을 구분한다.

| 자료 | 초기 보관 제안 | 목적·삭제 |
| --- | --- | --- |
| 목록 원시 응답·디버그 HTML | 최대 7일, 허용 범위 내 | 어댑터 오류 진단 후 삭제 |
| 채택 원문/PDF 원본 | 최대 30일 또는 권한상 더 짧은 기간 | 해시·근거 좌표·허용 발췌 보존. 계약이 장기 허용하면 개별 설정 |
| 원문 ID·URL·해시·판본·PASS 사유 | 장기 최소 식별 기록, 권한·삭제 의무에 따른 기간 설정 | 동일 문서 재처리 차단. 지워지면 중복 방어 범위도 줄어듦을 기록 |

| 수집·분석·게시 작업 로그 | 초기 90일, 집계 지표 1년 | 오류·비용·누락 재현, 비밀 제외 |
| 유효 조회 원시 이벤트 | 초기 30일, 일별 집계 1년 | 설치 식별 최소화·접근 제한·기간 고지 |

URL/원문 ID tombstone과 문서 해시는 실제 본문과 분리한다. ‘본문을 지웠으니 동일 기사인지 모름’으로 매번 새 상세를 만들지 않는다. 반대로 계약/삭제 의무로 식별 정보도 삭제해야 한다면 영구 중복 방지를 보장한다고 하지 않는다. 보관 만료 후 원문을 다시 볼 권한이 없으면 당시 근거·판단의 한계를 기록한다.

임베딩·검색 인덱스·LLM 캐시·백업도 삭제 대상에 포함한다. 이전 원문을 지운 뒤 벡터에 본문을 무기한 보존하는 우회는 하지 않는다. 공개 상세의 보관·제공 범위도 원문 이용 조건과 별도로 검증한다.

유효 조회 원시30일·일별 집계1년은 개인정보 확인 전 초기 상한이다. UV는 요청 구간 전체가 원시 보관 창 안에 있고 집계가 정상인 경우에만 계산한다. 30일 밖의 주/월/임의기간 UV는 초기 기능에서 **지원하지 않음**으로 표시한다. 31일짜리 달의 정확 월 UV도 제공하지 않는다. 원시 이벤트 만료 전 장기 집계를 만들었다고 추정하지 않는다. PV 합계와 일별 UV 각각은 제공할 수 있으나 일별 UV 합을 기간 UV라고 표시하지 않는다. 설치 목록·기간별 고유집합을 장기 보존하는 우회 집계는 도입하지 않는다. 보관 창 안에서도 원시 누락/배치 실패가 있으면 ‘집계 미확보’다.

원시 보관은 서버 수락시각 기준 **30×24시간 롤링**이며 삭제 작업은 그보다 오래된 이벤트만 대상으로 한다. UV 질의는 고정 as_of와 동일 DB 읽기 스냅샷에서 완전성 watermark를 확인한다. 초기 안전 여유1시간을 두고 start≥as_of−(30×24시간−1시간), end≤as_of이며 실제 보관/집계 watermark도 요청 시작을 덮어야 지원한다. 한국 달력 구간을 UTC 경계로 변환해 이 조건을 검사한다. 30일짜리 달도 월말이라는 이유로 자동 지원하지 않는다. 여유 안에서도 수집/집계 누락이 있으면 집계 미확보로 표시하고 일별합으로 대체하지 않는다.

원문 허용기간 만료·권한 철회는 source_revision·blob·임베딩·검색색인·LLM cache·파생 결과·백업 복구 경로까지 삭제/비공개 정책으로 연결한다. 최소 식별 tombstone은 허용된 범위에서만 남겨 재수집·재게시를 막는다. 삭제 ledger는 복원 후에도 재적용한다. 삭제 완료와 백업에서 완전 소거 시점을 구분하고 권한 철회 건은 복원 직후 공개 전에 차단한다. 실제 보관기간·데이터 항목은 개인정보 문서와 일치해야 한다.

## 14. 20:00 키워드 검토·자동 반영 {#keywords}

매 달력일20:00 실행한다. 범위 변화 없는 기존 검색어의 약어·표기 변형만 공식 용어 또는 독립 원출처3건·표본 검증 후 자동 별칭 연결한다. 기존 카테고리의 신규 의미 연결·새 기업/제품 역할·수혜 판정·카테고리 통합/삭제·새 출처 활성화는 자동 반영하지 않고 근거 있는 제안으로 보존한다. 예외가 대기해도 기존 조건으로 계속 운영한다. 하단D 앱 검색어·E 표시 설명·F 보조문맥은 뉴스 키워드 정비가 자동 변경하지 않는다.

키워드 정비 D일 묶음은 **전날20:00 초과~D일20:00 이하**의 연속24시간 창이다. 앱 게시일·한국장65회와 구분한다. 각 원문판본의 keyword_eligible_at은 max(최초 발견 작업의 예약시각, 확인된 원문 발표시각)으로 한 번 고정한다. 20:00 회차가 20:01 발표를 뒤늦게 받아도 다음날 묶음이고,19:50 작업이20:03에 끝나도 발표가19:50 이전이면 D일 묶음이다. 22:00 발표를22:10 수집하면 다음날20:00 묶음에 포함한다.20:01·23:59·00:00 자료도 빠짐없이 각각 한 번 포함한다. 발행시각 미확인은 PENDING_TIME으로 두고 확인 후 이 규칙에 따라 귀속하며 원래 날짜의 늦은 추가 묶음이 될 수 있다.

PENDING_TIME은 최초 발견 후72시간 상한이다. 그 안에 확인되면 위 규칙, 끝내 미확인이면 최초 발견 작업의 예약시각을 keyword_eligible_at으로 고정하고 ‘시각 미확인 · 발견 기준’ 표지를 남겨 그 귀속 날짜의 늦은 추가 묶음으로 처리한다. 확정한 귀속은 뒤늦은 원문 시각 발견으로 재이동·중복 반영하지 않고 정정 이력만 추가한다. 이는 키워드 정비 자료의 귀속 규칙일 뿐이며 기사 게시의 신선도/근거/HOLD 기준을 완화하지 않는다.

작업ID 목록과 SourceDocument/revision별 고정 귀속을 cutoff manifest로 보존한다. 한 폴링 작업이 경계를 넘는 판본을 받으면 판본별로 서로 다른 묶음에 배정할 수 있다. 이미 콘텐츠 판단 이벤트에서 처리한 자료도 같은 판본 ID로 한 번만 센다.20:30 미완료는 PARTIAL로 마감하고 뒤늦은 결과는 고정 귀속 날짜의 추가 묶음으로 처리한다. 신규자료를 임의로 과거 날짜에 넣거나 같은 판본을 다음날 재반영하지 않는다. 기준버전 충돌·재실행·부분 선적용·관찰·개별관계 롤백을 기록한다.

## 15. 알림·조회·저장 연동 {#notifications}

오전 장·장 마감·관심 섹터 알림만 지원한다. 초기 시각08:50/15:40, 한국 비거래일 묶음 알림 없음. 실제 운영 시각은 설정값이며 마감은 정규장 기준이지20:00 정비 완료 알림이 아니다. 관심은 근거 있는 primary_sector_id ∪ related_sector_ids와 이용자 설정을 교집합한다. 시장 전체라는 이유로 모든 관심 섹터에 자동 연결하지 않는다.

설치·정규Story·material_change_id 원인키를 3종 공통 unique로 둔다. 같은 원인의 동시 제안은 공통 outbox 조정자가 모아 **발송 자격이 있는 유형 사이에서만** 관심→마감→오전 우선으로 한 delivery를 원자 예약한다. 관심 상한·30분 제한·야간·미동의 등으로 자격이 없으면 그 유형은 원인을 claim하지 않고 다음 적격 묶음 후보로 남긴다. 원인 claim과 설치별 할당량 갱신은 같은 트랜잭션에서 검사한다. 이미 확정/전송된 원인은 다른 유형으로 재발송하지 않는다. 묶음에 포함된 원인만 예약하고 모두 중복이면 묶음 발송을 생략한다. 묶음 자체도 설치·한국거래일·digest_type unique로 한 번만 발송한다. 각 알림은 cutoff_snapshot_id·포함 원인·게시 버전을 고정한다. 늦은 회차는 다음 적격 묶음에 반영하고 이미 보낸 푸시를 다시 보내지 않는다. 정정·숨김 클릭은 상태 안내로 연결한다. 재시도는 같은 delivery/effect 키를 쓰며 공급처 수락 불확실 시 새 키로 보내지 않는다.

관심 알림 초기 상한은 설치당 하루5회·같은Story30분 이내 중복 금지이며 정정도 수신 해제·야간 설정을 우회하지 않는다. 단순 업데이트·전재·새 시세는 새 원인키를 만들지 않는다. 유효한 NEW_ANGLE도 상세 분리만으로 알림 자격을 얻지 않는다. 설치 수신선택·관심목록·OS권한을 발송 직전 재검사한다. 정규장 마감 묶음은15:40 회차를 최대15:45까지 기다리고 실패 시 마지막 검증 스냅샷의 실제 시각을 표시한다. 푸시 공급처 수락·기기도달·읽음을 구분한다.

공개 목록은 PUBLISHED만 반환한다. 알려진 Issue ID의 resolver는 본문 API와 분리해 canonical_issue_id·공개 상태·안내를 반환한다. HIDDEN/WITHDRAWN/CORRECTION_PENDING의 본문·민감한 내부 사유는 반환하지 않는다. 존재하지 않는 ID와 비공개 본문을 구분하는 안내 범위를 제한하고 공개 ID 추측으로 내부 원문을 읽을 수 없게 한다.

저장 목록은 해당 ID의 안내 항목을 유지하고 사용자가 삭제할 수 있다. 서버는 병합된 정규 ID를 알려주고 앱은 기기 저장소의 ID를 치환·중복 제거하며 최초 저장시각을 보존한다. 서버가 로컬 저장을 직접 고친다고 가정하지 않는다. 병합의 옛 ID는 redirect 관계이며 공개 상태가 아니다. 조회는 정규 Issue로 재집계하고 부모·자식 조회를 단순 합하지 않는다.

| 상태 | 앱 문구·본문 |
| --- | --- |
| CORRECTION_PENDING | 내용 확인 중 · 기존 내용 제공 중지 / 본문 차단 |
| WITHDRAWN | 근거 확인 불가로 게시 중단 / 본문 차단 |

| 정정 완료 PUBLISHED | 정정 시각·변경 요약 표시, 재검사 통과 새 버전만 제공 |

정정 확인 중24시간 후에도 미해결이면 WITHDRAWN. 과거 본문 자동 복원 금지. 안전한 이전 버전도 모든 검사를 통과해 새 공개 버전으로 커밋해야 제공한다. 앱 캐시는 상태/버전 확인 전 비공개 본문을 계속 제공하지 않는다.

## 16. DB·큐·API의 책임 {#data-contract}

Supabase/PostgreSQL은 상태·근거·정책·버전·작업 기록의 저장소다. 별도 Docker worker가 허용된 수집·추출·AI API 호출·배치 판단을 수행한다. Expo 앱은 수집·AI API 키를 갖지 않고 공개 결과만 읽는다. 관리자 웹은 편집·정책·감사 권한을 가진다. 모델이 Supabase 안에서 자체 실행된다고 가정하지 않는다.

## 17. 어드민에서 확인할 화면 {#admin}

기존 사이드바를 유지하고 기능을 연결한다. 일상 자동 운영은 사람이 모든 항목을 승인하는 구조가 아니다. 관리자 화면은 예외 확인·정책 조정·긴급 중지를 위한 장치다.

| 기존 메뉴 | 추가/명확화할 항목 |
| --- | --- |

일상 채택·보류·갱신·순위·발송은 사람 승인 없이 처리한다. 단, 14일 회복 탐침 소진, 권한 변경/유료·로그인 제한, 어댑터 구조 변경, 품질 오류, 철회·수동 숨김 글 재공개는 관리자/개발자의 예외 처리 대상으로 남긴다. 이 예외를 해소할 사람이 없어도 해당 경로/글만 차단하고 나머지는 계속한다. 무인 운영이 제한 우회·품질 오류 자동 승인·철회 글 자동 복원을 뜻하지 않는다.

긴급 중지는 수집처별·생성·자동 게시·순위 갱신·푸시를 분리한다. 자동 게시를 멈춰도 정정·철회·보안 차단은 수행한다. 재개 시 미완료만 회수하며 낡은 묶음을 오늘 새 사건처럼 밀어 넣지 않는다.

출시 초기 개발 게이트: 서로 다른5거래일·장전/장중/장후·해외 종료 구간의 허용 자료를 그림자 처리하고 표본을 직접 검수한다. 치명적인 창작·기업 오인·중복 게시·정정 미반영이 발견되면 원인 수정과 재검증 후 자동 게시를 켠다. 이는 운영자 상시 투입이 아니라 출시 전 검증 단계다. 평가 자료/라벨/만료·측정합격 기준·P01~12·SHADOW/LIVE 분리는제작18절을 따른다. 매체별 최신 100건 평가는 실제 100개 원문 확보 여부와 분모를 명시하고, 부족하면 ‘100건 완료’로 계산하지 않는다.

핵심 이슈는 해당 사건 주체·시각·실적·정책 등 **원래 사건의 사실**을 쓴다. 해외 선정 기사라면 해외 기업/시장의 사건을 중심으로 쓰며 억지로 한국 사실로 바꾸지 않는다. 이슈 분석·예상 시나리오·수혜 섹터·피해 섹터·연관 섹터·리스크 체크리스트·주요 일정은 항상 **한국 상장기업과 국내 섹터의 관점**이다. 예: 엔비디아 실적은 핵심 사실, 국내HBM/후공정의 제품·고객·수요 연결과 불확실성은 한국 영향 분석이다. 국내 전달 근거가 없으면 해외 가격 급등만으로 게시하지 않는다.

기사 버전에는 `selection_market_basis(KR/FOREIGN_US), source_market, evidence_as_of, analysis_perspective=KR_EQUITY, impact_profile, visibility_policy_version`을 저장한다. 홈 스냅샷의 현재 market_basis는 별도다.09:10/20:00이 됐다는 이유로 기사를 다시 게시하거나 source_market/최초일을 바꾸지 않는다. 새 사건/근거 없이 기존 본문을 재작성하지 않는다. 해외 비교군과 시트 연관기업은 탐색 도구이며 국내 기업 영향 근거를 대신하지 않는다.

### 기사별 상세 영역 노출 {#article-visibility}

같은 템플릿을 사용하되 모든 영역을 채우지 않는다. 공통 필수는 기사 상단·핵심 이슈·한국 관점 이슈 분석·출처이고 선택 영역은 아래 결정표로 산출한다. 빈 제목·빈 구분선·‘등록된 정보 없음’ 자리 채움 문구를 표시하지 않는다. 부정 시나리오만 단독 표시하지 않는다.

| 근거 기반 분석 상태 | 예상 시나리오 | 섹터·리스크 노출 |
| --- | --- | --- |
| 유효한 긍정 경로만 있음 | 긍정만 | 수혜/연관은 각각 해당 근거가 있을 때만, 피해는 없음. 리스크도 실제 체크할 내용이 있을 때만 |
| 유효한 긍정과 부정 경로 모두 있음 | 긍정·부정 | 각 방향의 예상결과·체크사항을 구분하고 해당 섹터만 노출 |
| 피해만 확인되고 유효한 긍정 경로 없음(DAMAGE_ONLY) | 전체 미노출 | 피해 섹터와 리스크 체크리스트 노출. 수혜를 만들지 않으며 부정 예상결과/확인 조건은 리스크에 통합 |
| 직접 호재·피해로 단정할 수 없으나 실제 국내 연결 있음(RELATED_CONDITIONAL) | 근거 있는 조건부 긍정 또는 긍정·부정 | 연관 섹터로 노출. 방향을 사실로 단정하지 않고 조건/불확실성 명시 |

서버의 방향 판정은 검증된 영향 경로를 먼저 구조화한 뒤 결정한다. `positive_path`는 BENEFIT 근거 또는 검증된 조건부 긍정 경로, `negative_path`는 DAMAGE 근거 또는 검증된 조건부 부정 경로의 존재다. 둘 다 있으면 POSITIVE_NEGATIVE로 긍정·부정을 함께 표시한다. BENEFIT과DAMAGE가 동시에 있으면 서로 다른 섹터/경로여도 반드시 이 규칙이며 긍정만으로 축소하지 않는다. 긍정만 있으면 POSITIVE_ONLY(피해 섹터 없음), 긍정 없이DAMAGE가 있으면 DAMAGE_ONLY로 시나리오를 숨긴다. 직접BENEFIT/DAMAGE 없이RELATED만 있으면 RELATED_CONDITIONAL로 두고 positive_path/negative_path 조합에 따라 긍정만/양쪽/미노출을 산출한다. 직접 피해 없이 부정 조건만 있는 경우도 시나리오는 숨기고 검증된 연관/리스크에 설명한다. 별도의 부정 단독 시나리오나 임의 예외는 두지 않는다. 이 판정은 LLM의 시나리오 문장 유무가 아니라 근거 ID가 붙은 영향 경로에서 산출하고 이후 문장을 작성한다.

RELATED_CONDITIONAL에서조차 근거 있는 긍정 경로가 없으면 긍정을 창작하지 않고 예상 시나리오는 숨긴다. 확인된 연관과 리스크만 설명할 수 있다. 이는 연관 섹터를 무조건 수혜로 바꾸지 않는 안전 조건이다. DAMAGE_ONLY의 리스크는 실제 피해의 지속·확대·해소를 확인할 항목을 근거로 작성하며 내용 없이 게시 형식만 채우지 않는다.

수혜/피해는 국내 사업·수요·원가·규제 등 방향과 전달 경로의 근거가 충분한 경우, 연관은 연결은 확인됐으나 방향/규모/조건이 미확정인 경우다. 여기서 확실한 호재·피해는 **영향 방향의 근거**를 뜻하며 주가 상승/하락 확정이나 수익 보장이 아니다. 같은 섹터·동일 영향 경로를 세 영역에 중복 배치하지 않는다. 서로 다른 경로는 구분 설명·근거를 두고 표시할 수 있다. `related_sector_ids`는 필터/관심알림 연결의 상위 집합이며 화면의 연관 섹터 목록과 같다고 가정하지 않는다. `impacts[].direction=BENEFIT/DAMAGE/RELATED`·한국 섹터/기업·경로·근거 ID·조건으로 표시 목록을 별도 산출한다.

주요 일정은 **해당 기사 이후 국내 영향 판단을 위해 실제 확인할 발표·시행·실적·행사**가 있고 시각/기간·시간대·공식/검증 근거가 있을 때만 표시한다. 해외 행사도 한국 영향 체크 대상이면 포함한다. 이미 끝난 사건 날짜나 막연한 ‘향후 확인’은 일정 칸을 만들지 않는다. 발표일은 미정이나 공식 예정기간이 확인되면 그 기간과 미확정 사실을 명시한다. 시간 경과/취소/정정 시 재검증해 지난 항목은 향후 일정에서 제거한다.

표시용 `visible_sections`는 서버가 최신 공개 article_version·검증 근거·visibility_policy_version으로 계산하고 관리자 미리보기와 Android/iOS가 같은 계약을 사용한다. 클라이언트의 임의 숨김만으로 잘못된 생성 데이터를 통과시키지 않는다. 선택 영역만 근거가 없으면 그 영역을 제외하고, 핵심 사실/한국 영향이 무너지면 기존 게시 차단·정정 절차를 적용한다. 시간 경과에 따른 일정 제거는 표시 갱신이며 최초 게시일을 변경하지 않는다. 본문 실질 변경은 새 버전·감사 이력으로 처리한다.

## 개발 프로세스 개정 — 시험·운영 활성화 경계 {#process-rollout}

제품의24시간 무인 뉴스 운영·한국/해외 기준·기사별 조건부 노출 계약은 유지한다. 제작 실행계획18절(development-gates)이 개발 증거와 배포 게이트의 단일 기준이다. 공통 큐/outbox·lease·재시작 복구는4단계, 한국 관점·영향/visible_sections 계약과 수동 경로 R05~R08은4~5단계, 가격·시장전환/달력 R01/R10은7단계, 실제24시간 파이프라인 R02~R04/R09는8~10단계에 연결한다.3단계 공급 시험은 병행하며 M1은 명시된 수동/샘플 fixtures로 만들 수 있다. 실제 공급 권한 통과를 샘플로 대체하지 않는다.

원문/발췌/파생 자료의 권한·보관 상한을 지키는 평가 registry·Story 분할·dataset/acceptance policy 버전을8단계까지 고정한다.9단계는 격리된 SHADOW 기능/품질 시험이며 운영 공개/실제 푸시는 없다. 운영 LIVE는12단계의 권한·경로 승격·고정평가·다중거래일/휴일 통합·환경·배포/이전앱 호환·복원·알림/공개문서 게이트에 결속된 activation_receipt 범위만 활성화한다. 이는 출시 전 개발/배포 증거이며 정상 운영의 기사별 사람 승인이나 새로운 이용자 알림 유형을 추가하지 않는다.

8단계부터 운영 담당용 오류/큐/정정지연/비용 경보를 두고10단계에서 긴급 중지·재개를 시험한다. 앱3종 알림과 별도 채널이다. 0~1단계부터 계정 유형·공급 허가·테스터 모집 등 긴 외부 준비를 병행한다. 소프트웨어 버전·계정별 스토어 조건·요금은 실제 착수 시 다시 확인하고 기존 기록을 실제 완료로 표현하지 않는다. 배포는expand→호환 서버/worker→앱→지원정책 확인 후contract이며 코드 롤백과 데이터 복원을 분리한다.
