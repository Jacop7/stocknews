### 목표와 이용자 {#goals}

#### 서비스 목표

1. 미국장과 한국장의 뉴스를 한국 주식 섹터 관점으로 정리한다.
2. 주가가 움직인 섹터에서 관련 사건과 근거 뉴스를 찾는다.
3. 뉴스가 어떤 섹터·기업에 어떤 이유로 영향을 줄 수 있는지 설명한다.
4. 기사와 시세를 갱신하고, 관심 섹터의 중요한 이슈를 알림으로 전달한다.

뉴스와 상승률의 동시 발생을 확정적인 원인·결과로 표현하지 않는다. 사실, 분석, 예상 시나리오를 구분한다.

#### 이용자와 권한

| 구분 | 이용 방식 | 주요 기능 |
| --- | --- | --- |
| 일반 이용자 | 회원가입·로그인 없음 | 뉴스 열람·저장, 검색, 필터, 섹터·종목 확인, 관심 섹터, 알림 설정 |
| 관리자 | 관리자 전용 로그인 | 키워드·기업·카테고리 관리, 기사 작성·수정·게시, 자동화 관리 |
| 자동화 작업 | 서버 전용 권한 | 뉴스·시세 수집, AI 분석, 기사 저장, 키워드 검토, 알림 발송 |

#### 대표 이용 흐름

- 장전: 홈 → 미국발 주요 이슈 → 이슈체크 상세 → 관련 섹터 → 한국 관련 종목.
- 장중: 섹터랭킹 → 상승 섹터 → 관련 이슈 → 수혜·피해 기업 확인.
- 장후: 실적·공시 관련 알림 → 새 이슈 또는 갱신된 상세 확인.
- 검색: 검색 아이콘 → 뉴스/종목 선택 → 검색 결과 → 이슈 상세 또는 관련 종목.

### 문서 기준과 현재 상태 {#basis}

이 폴더의 서비스 v1.6·어드민 v1.1·제작 실행계획 v1.3·뉴스 상세로직 v1.1·매체별 부록을 하나의 개정 묶음으로 사용한다. 기존 판본은 이력으로 보존한다. 문서 해시는 bundle-manifest.json에 기록한다. 사용자 확정 요구가 우선이고, 같은 묶음의 운영 계약은 **공통-운영계약-v1.0.md**, 세부 처리 절차는 뉴스 상세로직 v1.1, 화면은 서비스 v1.6·어드민 v1.1, 순서는 제작 실행계획 v1.3을 따른다. 충돌이 발견되면 임의로 유리한 규칙을 택하지 않고 해당 작업을 보류한다.

사용자의 ‘진행 및 클로드 검수’ 요청에 따라 아래 선택안을 작성자가 **초기 설계기준**으로 채택했다. 모든 수치를 사용자가 직접 승인했거나 실운영으로 입증했다고 표시하지 않는다. 운영 설정으로 변경 시 정책 버전·변경 이유·회귀 검사를 남긴다. 공급 계약·법적 이용 범위·개인정보 보관기간은 별도 확인 전 활성화하지 않는다.

최신 문서 기준은56카테고리·에이직랜드 제외 한국기업339개이며 실제 시트 재조회 결과라는 뜻은 아니다. 구판의340개는 그 시점 스냅샷 이력이다. import는 실제 최신 시트·원본 좌표·해시·차이·수동충돌을 확인한 뒤 적용한다. 초기 이관 후 운영 DB가 기준이며 시트와 양방향 자동 덮어쓰기는 하지 않는다.

섹터명·설명·순서·삭제(비활성), 하위 묶음·한국종목 추가/해제/순서, 기업 마스터 비활성·대체, 내부 제품 역할·미국 비교군 버전을 관리한다. 관련 메타데이터가 바뀌면 catalog_version 증가, 영향 미리보기·원자 적용·감사 기록. old job은 커밋 직전 최신 버전으로 재검사한다. 삭제 기업/섹터를 재연결하지 않는다. 표시 설명E·묶음 설명·내부 상세 역할은 분리한다. 대표 섹터 대체는 본문 실질 변화가 없으면 메타데이터 버전만 올리고 최초/본문 수정일을 바꾸지 않는다.

현재 HTML은 화면 시안이며 운영 앱·DB·자동화·실시세·실제 알림을 구축한 결과가 아니다.

### 홈 {#app-home}

기간 선택 → 필터 → 실제 조회 구간 → 콘텐츠의 배치, 카드·검색·저장 버튼과 흰 배경/보라색 배지는 유지한다. 실시간 초기 상태와 달력 선택 전환은 다음 계약을 따른다.

여섯 날짜 버튼 오늘·어제·이번주·지난주·이번달·지난달의 뜻은 한국 달력과 **최초 앱 게시일**이다. 오늘/어제는 단일 날짜 표시를 유지한다. 업데이트로 최초 게시일을 바꾸지 않는다.

최초 진입 홈은 **실시간** 상태이며 날짜 버튼은 미선택이다. 일곱 번째 기간 탭은 추가하지 않는다. 콘텐츠 위 상태줄에 ‘실시간 · 실제 시작~종료 · 거래일 기준’을 표시한다. 버튼을 고르면 달력 보기로 전환하고, ‘실시간으로’ 링크로 기본 상태로 돌아온다. 달력 오늘과 거래 구간을 같은 선택값으로 부르지 않는다.

실시간 C는 한국 시각 **09:10 이상~20:00 미만 KR**, **20:00 이상~다음09:10 미만 FOREIGN_US**로 전환한다. 한국 비거래일에는 KR을 만들지 않고 FOREIGN_US를 유지한다. 20:00은 해외 기준 첫 회차이며 한국 기준 마지막 회차는19:50이다. 한국 기준은 거래일 D, 직전 한국 정규장 종료 직후~회차 cutoff를 후보 창으로 고정한다. 해외 기준은 다음 한국 거래일 D, 직전 한국 정규장 종료 직후~회차 cutoff를 사용한다. 금요일 장후·주말·연휴를 빠뜨리지 않는다. 09:10 전환 때 D·하한을 유지하며 market_basis만 바꾼다. 20:00 전환 때 다음 D로 이동한다. 최초 게시일·Story/Issue ID는 바꾸지 않는다. A/B의 이전 글은 현재 실질 변화가 있을 때 최초 날짜+업데이트 일시를 표시한다. 뉴스 게시와 별개로 C만10분 스냅샷이다. 전환 실패는 현재 모드의 지연/미확보로 표시하고 다른 시장의 직전 순위를 현재 순위로 재사용하지 않는다. 구모드 결과는 기준시각·시장명을 붙인 별도 과거 참조로만 제공한다.

달력 보기의 후보는 스냅샷이 아니라 **선택한 한국 달력 기간에 최초 앱 게시된 Issue 전체**에서 만든다. 현재 공개 자격을 다시 검사하고 숨김 본문을 복원하지 않는다. 현재 A/B를 끼워 넣지 않는다. 달력 홈도 전체 선택기간에서 Story당1개다. 해당 기간 안의 Issue 중 최초 게시시각이 가장 최근인 것을 대표로 선택하고 동률은 고정ID로 정한다. 실시간 대표 선정과 달력 후보 선정은 서로 별도다. 이슈체크·검색은 방향별 Issue를 모두 제공할 수 있다.

선택한 대표 Issue를 실제 최초 게시 한국 날짜별로 묶고, 날짜 안에서는 **최초 게시시각의 시장 구간(calendar_rank_segment)**으로 각각 한 번만 배정한다. 한국 거래일은00:00~09:10 미만 FOREIGN_PRE,09:10~20:00 미만 KR_DAY,20:00~24:00 미만 FOREIGN_POST의3구간이며 한국 비거래일은 하루 전체 FOREIGN_DAY다. 구간 시작 포함·끝 미포함이다. 각 구간의 마지막 완성 C 스냅샷(오늘은 해당 구간 안의 현재까지)만 참조한다. 쿼리는 한국 날짜·market_basis·target_D·구간 시작/끝·cutoff를 함께 고정한다. 정상 종료 cutoff는 FOREIGN_PRE09:00,KR_DAY19:50,FOREIGN_POST/FOREIGN_DAY23:50이다. 평일 오전 글의 KR19:50 순위를21:00 이후 해외23:50 순위로 대체하지 않는다. FOREIGN_PRE와FOREIGN_POST도 같은FOREIGN_US라는 이유로 합치지 않는다. 한국 비거래일의FOREIGN_DAY는 실제 미국 거래일·시세시각을 표시한다. 해당 구간이 아직 시작되지 않았으면 미래 그룹을 만들지 않으며, 구간 스냅샷이 없으면 다른 구간으로 대체하지 않고 그 구간만 미확보로 표시한다. 기간 전체 Story1개 대표 선정 후 구간으로 배정하며, 순위 대조도 그 한국 날짜·구간에 최초 게시된 Issue만 남긴다. 스냅샷에 없는 적격 글은 해당 구간의 ‘당시 순위 미포함’에 최초 게시 최신순으로 보존한다. 날짜 그룹은 최신 날짜 순, 날짜 안 구간은 시작시각 역순, 구간 안은 당시 순위→미포함 순으로 제공하고 각 머리에 시장 기준·실제 cutoff·target_D를 표시한다. 서로 다른 시장/구간 순위 번호·점수는 합산·비교하지 않는다. 과거 순위는 당시 정책·기사버전·시장시각을 유지하고 최신 점수로 가장하지 않는다. 한국 날짜 선택·최초 게시일은 바꾸지 않는다.

섹터 선택은 B/C·일반 목록에 실제 연결된 섹터를 적용한다. 시장 전체 A는 필터 위 별도 ‘시장 전체’ 영역으로만 제공하고 선택 섹터 기사처럼 표시하지 않는다. 달력 보기에는 이 예외도 없다.

조회수·내부 점수는 앱에 공개하지 않는다. 카드를 누르면 공통 상세로 이동한다.

### 이슈체크 {#app-issues}

- 카드에 발행 일시, 제목, 핵심 요약, 수혜섹터·피해섹터 정보를 표시한다. 매크로 기사는 ‘매크로’ 배지로 구분하고, 연결 근거가 있는 섹터만 표시한다.
- 발행 일시는 `YYYY.MM.DD HH:mm` 형식으로 표시한다. 목록 카드를 구성할 때 날짜를 맨 아래로 내렸던 요청은 취소됐으므로 기본 위치를 유지한다.
- 출처를 섞은 `AI 반도체 · 06:30 · Reuters` 형식은 사용하지 않는다.
- 수혜섹터·피해섹터는 해당하는 섹터와 기업을 연결해 표시한다.
- 예: `수혜섹터  HBM (SK하이닉스, 삼성전자)`.
- 괄호 안 기업명은 진한 회색으로 표시한다.
- 각 수혜·피해 줄은 한 줄을 넘지 않는다. 넘칠 때는 `감속기 (에스비비테크) 외 총 1개`처럼 축약한다.
- ‘외 총 N개’는 숨겨진 섹터 항목 수를 뜻하도록 정의하는 것을 제안한다. 기업 수와 섞어 세지 않는다.
- 모든 카드에서 동일한 상세 템플릿을 사용하되 내용은 각 사건에 맞게 작성한다. 각 카드에 저장·저장 취소 버튼을 제공한다.
- HBM·감속기 등의 주제·하위 묶음 표시와 실제 카테고리 이동은 [분류·표시 주제·기업 영향의 연결](#sector-linking)의 연결 규칙을 따른다.

### 섹터랭킹 {#app-ranking}

- 홈·이슈체크와 같은 섹터 필터를 제공한다. 선택한 상위·하위 섹터 안에서 등락률 순으로 표시한다.
- 섹터별 등락률을 계산해 내림차순으로 표시한다.
- 순위, 섹터명, 등락률을 제공한다. 종목 가격은 표시하지 않는다.
- 목록 상단에 ‘섹터 등락률 / 동일 비중 평균’ 설명 행을 반복하지 않는다.
- 섹터 클릭 시 해당 섹터체크로 이동한다.
- 계산 시점, 구성 종목, 누락 데이터 처리 기준을 서버에서 관리한다.
- 기간 선택은 섹터 성과 기간과 연결한다. 구체적인 적용 범위는 최종 화면 설계에서 확정한다.
- 섹터랭킹은 섹터 성과 순위다. 조회수를 섞는 홈 뉴스 순위와 분리한다.

### 저장 {#app-saved}

홈·이슈체크·상세에서 저장하고 하단 네 번째 탭에서 최근 저장 순으로 제공한다. 오른쪽 위 알림·설정 아이콘은 기존 설정 크기로 맞춘다. 로그인 없이 기기 저장소를 사용한다.

공개 목록은 PUBLISHED만 반환한다. 알려진 Issue ID의 resolver는 본문 API와 분리해 canonical_issue_id·공개 상태·안내를 반환한다. HIDDEN/WITHDRAWN/CORRECTION_PENDING의 본문·민감한 내부 사유는 반환하지 않는다. 존재하지 않는 ID와 비공개 본문을 구분하는 안내 범위를 제한하고 공개 ID 추측으로 내부 원문을 읽을 수 없게 한다.

저장 목록은 해당 ID의 안내 항목을 유지하고 사용자가 삭제할 수 있다. 서버는 병합된 정규 ID를 알려주고 앱은 기기 저장소의 ID를 치환·중복 제거하며 최초 저장시각을 보존한다. 서버가 로컬 저장을 직접 고친다고 가정하지 않는다. 병합의 옛 ID는 redirect 관계이며 공개 상태가 아니다. 조회는 정규 Issue로 재집계하고 부모·자식 조회를 단순 합하지 않는다.

| 상태 | 앱 문구·본문 |
| --- | --- |
| CORRECTION_PENDING | 내용 확인 중 · 기존 내용 제공 중지 / 본문 차단 |
| WITHDRAWN | 근거 확인 불가로 게시 중단 / 본문 차단 |
| HIDDEN | 현재 제공하지 않는 글 / 본문 차단 |
| MERGED 관계 | 정규 상세로 연결, 이후 정규 상태 적용 |
| 정정 완료 PUBLISHED | 정정 시각·변경 요약 표시, 재검사 통과 새 버전만 제공 |

정정 확인 중24시간 후에도 미해결이면 WITHDRAWN. 과거 본문 자동 복원 금지. 안전한 이전 버전도 모든 검사를 통과해 새 공개 버전으로 커밋해야 제공한다. 앱 캐시는 상태/버전 확인 전 비공개 본문을 계속 제공하지 않는다.

#### 알림 {#app-notifications}

오전 장·장 마감·관심 섹터 알림만 지원한다. 초기 시각08:50/15:40, 한국 비거래일 묶음 알림 없음. 실제 운영 시각은 설정값이며 마감은 정규장 기준이지20:00 정비 완료 알림이 아니다. 관심은 근거 있는 primary_sector_id ∪ related_sector_ids와 이용자 설정을 교집합한다. 시장 전체라는 이유로 모든 관심 섹터에 자동 연결하지 않는다.

설치·정규Story·material_change_id 원인키를 3종 공통 unique로 둔다. 같은 원인의 동시 제안은 공통 outbox 조정자가 모아 **발송 자격이 있는 유형 사이에서만** 관심→마감→오전 우선으로 한 delivery를 원자 예약한다. 관심 상한·30분 제한·야간·미동의 등으로 자격이 없으면 그 유형은 원인을 claim하지 않고 다음 적격 묶음 후보로 남긴다. 원인 claim과 설치별 할당량 갱신은 같은 트랜잭션에서 검사한다. 이미 확정/전송된 원인은 다른 유형으로 재발송하지 않는다. 묶음에 포함된 원인만 예약하고 모두 중복이면 묶음 발송을 생략한다. 묶음 자체도 설치·한국거래일·digest_type unique로 한 번만 발송한다. 각 알림은 cutoff_snapshot_id·포함 원인·게시 버전을 고정한다. 늦은 회차는 다음 적격 묶음에 반영하고 이미 보낸 푸시를 다시 보내지 않는다. 정정·숨김 클릭은 상태 안내로 연결한다. 재시도는 같은 delivery/effect 키를 쓰며 공급처 수락 불확실 시 새 키로 보내지 않는다.

관심 알림 초기 상한은 설치당 하루5회·같은Story30분 이내 중복 금지이며 정정도 수신 해제·야간 설정을 우회하지 않는다. 단순 업데이트·전재·새 시세는 새 원인키를 만들지 않는다. 유효한 NEW_ANGLE도 상세 분리만으로 알림 자격을 얻지 않는다. 설치 수신선택·관심목록·OS권한을 발송 직전 재검사한다. 정규장 마감 묶음은15:40 회차를 최대15:45까지 기다리고 실패 시 마지막 검증 스냅샷의 실제 시각을 표시한다. 푸시 공급처 수락·기기도달·읽음을 구분한다.

#### 설정 {#app-settings}

- 설정 메뉴는 알림 설정, 이용약관, 개인정보처리방침, 앱 버전, 이메일 문의다.
- 개인정보처리방침에는 광고·맞춤형 광고 안내를 포함한다. 메뉴 보조 문구로 ‘광고 및 맞춤형 광고 안내 포함’을 제안한다.
- 문의 이메일은 `callamelo@naver.com`이며 클릭 시 메일앱을 호출한다.
- 실제 앱 버전 값은 배포 버전에서 가져온다. 미정인 버전을 확정 값으로 기재하지 않는다.
- **설계기준:** 알림 설정 안의 ‘관심 섹터 이슈 알림’ 항목 아래에 ‘관심 섹터 관리’ 진입을 제공한다. 관심 대상 선택과 알림 수신 동의는 별도로 저장한다. 관리 화면에서 뒤로 가면 알림 설정으로 돌아온다.

**확정:** 이용자 회원가입·로그인 화면은 추가하지 않는다.

**설계기준:** 앱 설치 단위로 관심 섹터·알림 설정을 관리하고, 설치 식별자와 쓰기 권한을 분리한다. 설정 변경 요청은 해당 설치의 검증된 권한으로만 처리한다. 공개 조회 키나 설치 식별자만으로 토큰·선호를 수정할 수 없게 한다.

**제안:** 내부 구현은 서버가 발급한 설치 인증 수단 또는 Supabase 익명 인증 중 선택한다. 익명 인증을 사용해도 일반 설치와 관리자 권한은 분리하며, 화면상 회원가입·로그인을 요구하지 않는다. 재설치 시 복원·여러 기기 동기화는 초기 보장 범위에 넣지 않는다.

### 검색 {#app-search}

- 검색 아이콘 클릭 시 상단 영역이 검색 입력창으로 전환된다.
- 앞쪽 검색 아이콘, 입력 내용, 지우기 버튼, 우측 취소 버튼으로 구성한다.
- 참고 이미지의 어두운 색은 적용하지 않고 기존 앱 색을 유지한다.
- 뉴스 / 종목 두 탭은 기간 선택과 같은 둥근 탭 스타일로 구성한다.
- 뉴스는 제목·요약·기사 내용과 관련 키워드 기준으로 검색한다.
- 종목은 기업명·별칭·종목코드·기업별 적용 검색어 기준으로 검색한다.
- 같은 기업이 여러 카테고리에 있어도 검색 결과 기업은 중복 제거하고 관련 카테고리를 연결한다.
- 검색 결과 종목의 기업명 아래에 ‘카테고리 3 / 합의 11’ 하단 E열 ‘검색 시 설명글’의 최신 값을 표시한다. 기업명과 소속 카테고리로 연결하고, 수동 편집한 문구와 줄바꿈을 보존한다.
- 단독 기업 상세페이지는 아직 확정하지 않았다. 초기에는 관련 섹터·종목 화면으로 연결하는 구성을 제안한다.

상세 표현 규칙:

- ‘한줄 정리’ 영역은 제외한다.
- ‘직접영향’ 배지와 상단 Reuters 단독 표시는 제외한다. 실제 출처는 하단 출처 영역에 보존한다.
- 핵심 이슈의 녹색·붉은색 좌측 세로선은 사용하지 않는다.
- 긍정·부정 배지는 항목 제목 왼쪽에 표시한다.
- 괄호 설명은 해당 제목과 같은 크기의 진한 회색으로 표시한다.
- 핵심 이슈 아래 긴 분석 문단은 기본 3줄을 표시한다. 셋째 줄 문장 바로 뒤에 `… 더보기`를 붙이고 클릭 시 펼친다. 펼친 후 접기 동작도 제공하는 것을 제안한다.
- 수혜·피해 설명에 ‘최근 호재:’라는 접두어를 붙이지 않고 실제 호재·리스크 내용을 작성한다.
- 수혜·피해 섹터 사이 선은 얇게 유지한다. 내부에서 수혜·피해를 반복하는 별도 배지는 제외한다.
- 관련 기업은 홈의 기업 배지 표현과 일관되게 구성한다.
- 시나리오는 테두리 박스를 유지한다. 박스 배경색과 좌측 색상선은 제거하고 긍정·부정 배지 배경색은 유지한다.
- 시나리오의 ‘성립조건’ 행은 제목과 중복되므로 제외한다. 항목명은 ‘예상결과’, ‘체크사항’을 사용한다.
- 리스크 제목·리스트의 기본 텍스트는 검정 계열로 표시한다. 리스트는 시나리오 본문과 같은 크기로 맞춘다.
- 주요 일정의 별도 날짜 칸은 제외하고 작은 회색 선 달력 아이콘을 사용한다. 실제 일정 날짜는 필요한 본문 정보로 보존한다.
- 긴 이슈 분석 문단을 제외한 짧은 설명·목록은 가능한 범위에서 명사형 문장으로 작성한다.

**운영 데이터 원칙:** 시안의 비어 있는 구역을 채워 달라는 요청은 화면 샘플의 완성도 요구로 해석한다. 실제 기사에서 확인되지 않는 피해 섹터·리스크·일정을 생성하라는 운영 규칙으로 사용하지 않는다. 설계기준으로 근거 없는 선택 구역은 숨기고 남은 구역 순서를 유지한다. 핵심 사실·출처가 없으면 기사 전체를 게시하지 않는다. 시나리오는 분석임을 구분하고 사실처럼 작성하지 않는다. 구체적인 게시 검사는 [게시 검사·정정](#admin-publishing-rules)을 따른다.

#### 뉴스 출처 팝업 {#app-sources}

- 상세 하단 뉴스 출처 박스 클릭 시 배경을 어둡게 하고 둥근 모서리의 하단 팝업을 연다.
- 기사 제목, 매체, 발행 시각과 원문 링크를 목록으로 제공한다.
- 참고 이미지의 ‘방금 읽은 기사와 유사한 뉴스…’ 안내 문구는 제외한다.
- ‘보통이에요’, ‘짧아요’ 등 읽기 길이 배지는 제외한다.
- 항목 사이는 얇은 구분선을 사용한다.
- 원문 열기, 뒤로 가기·바깥 영역·닫기 등의 종료 동작을 정의한다.
- 팝업 제목은 ‘뉴스 출처’를 제안한다.

### 섹터체크와 종목 웹뷰 {#app-sector}

상단 헤더는 ‘섹터체크’다. 선택한 섹터명 아래에 어드민 섹터 설정에서 저장한 설명글을 표시한다. 최초 설명글은 기준 시트 C열(세 번째 열)에서 가져온다. 섹터 상세 상단의 배지와 HOT 테마순위·등수 표시는 제외한다.

탭은 **이슈체크 / 관련 종목** 두 개다. 자금흐름·토론 탭은 제외한다.

이슈체크 탭:

- 해당 섹터에 실제로 연결된 뉴스만 표시한다.
- 제목, 핵심 요약, 발행 일시를 제공한다.
- 이 목록에서는 수혜섹터·피해섹터 줄을 생략한다.
- 발행 일시는 카드 맨 아래에 표시한다. 일반 이슈체크 목록과 날짜 위치가 다른 화면이다.
- 관련 기사 여러 건을 제공하고 클릭 시 공통 이슈 상세로 이동한다.
- ‘투자 인사이트를 확인하세요’ 안내 박스는 제외한다.

관련 종목 탭:

- 한국 기업만 표시한다.
- 시트의 굵은 소제목은 초기 하위 카테고리로 이관한다. 운영 중에는 어드민 섹터 상세에서 설정한 하위 카테고리·종목 순서를 적용하고, 소제목 위에 얇은 구분선을 넣는다.
- 회사명과 그 섹터·하위 분류에 맞는 설명을 왼쪽에 표시한다.
- 현재가와 가격 변화·등락률을 오른쪽에 표시한다.
- 종목 행을 누르면 해당 종목의 네이버증권 모바일 종합 페이지를 앱 내부 웹뷰에서 연다. 예를 들어 삼성전자는 종목코드 005930으로 연결한다. 닫기·뒤로가기는 같은 섹터의 관련 종목 탭으로 돌아간다. [네이버증권 삼성전자 종합](https://m.stock.naver.com/domestic/stock/005930/total)
- **설계기준:** 연결 주소는 검증한 종목코드로 만든다. 페이지를 열 수 없으면 다시 시도와 외부 브라우저에서 열기를 제공한다. 네이버증권 웹뷰 연결과 앱에 표시하는 시세 공급은 별도다.
- 행에 색 배경을 넣지 않는다. 하위 분류가 없는 경우에도 행 사이 구분선을 제공한다.
- 설명은 단순 검색 키워드 나열이 아니다. 예를 들어 핸드 영역의 로보티즈 설명에 양산·액추에이터·핸드를 모두 반복하지 않는다.
- 종목 목록 위에는 선택 기간의 섹터 등락률을 표시한다. 금액은 표시하지 않고 등락률 글자 크기는 종목 가격과 맞춘다.
- 기간은 오늘 / 1주 / 1개월 / 3개월 / 직접입력으로 구성한다. 홈의 달력 기준 기간과 별도다.
- 직접입력은 시작일·종료일로 구성한다. **확정:** 적용 버튼은 두지 않는다. **설계기준:** 두 날짜가 유효하고 순서가 맞으면 자동 반영하며 입력 중인 불완전한 값은 조회하지 않는다. 날짜 입력칸 배경색은 유지하고 선택 버튼은 기존 요청대로 비선택 색 배경을 제거한다.

### 섹터 필터 {#app-filter}

**확정:** 섹터와 하위 섹터를 하나의 팝업에서 선택한다. 참고 서비스는 구성·크기의 참고이며 브랜드 색은 유지한다.

1. 상단에는 상위 섹터 탭을 가로 스크롤로 표시한다.
2. 본문에는 상위 섹터 순서대로 하위 섹터 버튼 묶음을 표시한다.
3. 탭 클릭 시 해당 본문 위치로 이동한다. 본문을 스크롤하면 해당 탭 상태를 맞춘다.
4. 하위 섹터는 여러 개 선택할 수 있다.
5. 상위 섹터의 ‘전체’를 누르면 하위 항목 전체가 선택 상태로 표시된다.
6. 선택값에는 ‘AI·반도체 전체’처럼 상위 이름이 함께 표시된다.
7. 팝업 하단에 선택값, 개별 삭제, 전체 삭제, 닫기, 결과보기를 제공한다.
8. 하단 선택값과 본문 선택 버튼의 크기·텍스트 스타일을 맞춘다.
9. ‘결과보기’에서 실제 필터에 반영하고 ‘닫기’에서는 미적용 선택을 취소하는 동작을 제안한다.

팝업 전체의 큰 ‘필터’ 제목·전체 초기화·상단 X를 별도로 반복하지 않는다. 하단 닫기·선택 삭제로 조작한다. 각 상위 섹터 묶음의 ‘초기화’는 그 묶음의 선택만 해제하는 동작으로 제공한다. 일부 선택 상태와 전체 선택 상태의 일관성, 선택 항목 삭제 시 전체 상태 해제도 구현한다.

**운영 반영:** 상위 탭과 그 안의 하위 섹터 버튼은 어드민에 게시된 활성 섹터의 표시명·순서를 따른다. 이름을 바꿔도 기존 선택은 같은 ID로 유지하고, 삭제 처리된 ID는 선택값에서 제거한다. ‘전체’는 현재 활성 하위 섹터에 적용한다. 관련 종목을 묶는 하위 카테고리는 섹터 상세의 내부 분류이며 필터 항목은 [분류·표시 주제·기업 영향의 연결](#sector-linking)의 앱 하위 카테고리를 사용한다.

### 공통 내비게이션과 디자인 {#app-design}

#### 전역 구조

상단은 기존 로고와 검색 아이콘을 사용한다. 별도 고정 검색바로 교체했던 요청은 취소됐으므로 검색 아이콘을 유지한다. 화면별 기간·필터는 상단 전역 내비게이션이 아닌 콘텐츠 영역에서 제공한다.

하단 내비게이션은 홈, 이슈체크, 섹터랭킹, 저장의 네 항목이다. 저장 화면의 오른쪽 위에는 알림과 설정 아이콘을 함께 표시한다. 로그인 메뉴는 없다. 상세·검색·설정 등 하위 화면에는 돌아가기 동작을 제공한다. 하위 화면에서 하단 내비게이션을 유지할지는 화면별 설계에서 결정한다.

#### 디자인 원칙

- 기존 보라색 브랜드와 로고를 유지한다.
- 기본 콘텐츠 배경은 흰색으로 구성한다.
- 홈·이슈체크 목록은 연한 회색(#f7f8fa) 바깥 배경에 흰색 콘텐츠 박스를 사용한다. 기사 상세와 섹터체크 상세는 넓은 화면에서 같은 배경 조합을 쓰고, 시안 기준 768px 이하에서는 화면 배경까지 흰색으로 표시한다.
- 선택된 필터와 탭은 기존 보라색 계열로 표시한다. 참고 이미지의 주황색을 그대로 가져오지 않는다.
- 가격 상승은 빨강, 하락은 파랑으로 표시하고 기호·숫자를 함께 사용한다.
- 대구역 구분선은 연한 회색, 같은 수준의 내부 구분선은 얇은 회색으로 구분한다.
- 핵심 이슈 등 상세 섹션 제목의 크기는 통일하고 진한 회색을 사용한다. 구체적인 글자 크기는 Expo 공통 스타일 값으로 확정한다.
- 모바일 글자 확대, 작은 화면, 긴 기업명·카테고리명을 고려한다.
- 공통 푸터의 서비스 소개·메뉴·약관 링크 영역은 제거한다. 이용약관과 개인정보처리방침은 [설정](#app-settings)에서 연다.
- 정보가 없을 때 샘플 값이나 근거 없는 설명을 만들어 채우지 않는다.

### 이슈체크 관리 {#admin-issues}

#### 기사 목록 {#admin-issue-list}

필터는 기간, 수동/AI, 기사 유형(섹터 / 매크로), 공개 상태, 카테고리, 출처, 예약 시각·수동 REVIEW·AI 판정 사유, 자동 갱신 모드다. 기본 열은 제목, 최초 게시·수정 시각, 대표 섹터, 작성 방식, 상태, 조회 통계, 순위 포함 여부다.

조회 통계는 관리자 목록에만 표시한다. 기사 상세 미리보기에는 실제 앱처럼 조회수 숫자를 표시하지 않는다.

#### 등록·편집과 섹터 선택 {#admin-editor}

- **확정:** 관리자가 글을 올릴 때 기사 유형을 선택하고 연결 근거가 있는 섹터를 지정한다. 수동·AI 기사 모두 같은 편집기에서 연결을 확인하고 수정할 수 있다.
- **설계기준.** 초안은 섹터 없이 임시 저장할 수 있다. 섹터 기사는 예약·게시 시 활성 대표 섹터 한 개를 지정한다. 매크로 기사는 영향이 확인된 섹터를 연결하고, 시장 전반에 걸친 이슈는 대표 섹터 없이 게시할 수 있다. 게시 전 홈 배지와 적용 필터를 확인한다.
- 대표 섹터는 섹터 기사의 카드 배지와 기사 순위의 시장 성과에 사용한다. 대표·관련 섹터는 필터와 섹터체크 기사 목록에 연결하며 기사 ID로 중복을 제거한다. 섹터 연결이 없는 매크로 기사는 전체 이슈체크 목록에서 확인할 수 있고, 주요 매크로 지정 조건을 통과하면 홈의 ‘주요 매크로’에도 표시한다. 수혜·피해 분류와 기업별 영향은 각각 근거로 작성한다.

- 제목·핵심 요약·원문 출처·발표 시각·사건 연결.
- 핵심 이슈·한국 관점 분석·수혜/피해/연관 섹터와 한국 기업·영향 근거.
- 긍정만/긍정·부정/피해만/연관 조건부 분류·노출 미리보기·예상결과·체크사항.
- 리스크 체크리스트·주요 일정.
- 기사 유형(섹터 / 매크로), 대표·관련 섹터, 홈 노출 자격. 매크로 기사에는 사건 단계와 한국 시장으로 영향이 전달되는 경로를 기록한다.
- 최초 게시·예약·수정 상태·자동 갱신 허용 여부.

기존 기사처럼 보이는 입력은 중복 가능성을 보여준다. 근거 없는 구역은 숨기고 핵심 사실·출처가 없으면 게시를 차단한다. 일상 섹터·매크로는 게이트 통과 후 무인 게시한다. 경로별 품질시험·이용허가 미통과로 비활성인 범위는 운영 설정에 기록하며 사람의 상시 승인을 요구하지 않는다.

#### 미리보기·예약·게시 {#admin-publishing}

미리보기→예약 또는 게시. 작성·공개·판정 축은 아래 계약을 따른다.

공개 상태는 DRAFT/PUBLISHED/CORRECTION_PENDING/WITHDRAWN/HIDDEN. 예약은 DRAFT + scheduled_publish_at이며 예약시각에도 최신 근거·정책·catalog_version을 재검사한다. 수동 작성의 선택적 REVIEW 플래그는 공개 상태가 아니다. 자동 후보 판정은 COLLECT/PASS/HOLD/EXPIRED_HOLD와 상세로직 사유 체계를 사용한다. 수집 성공/부분 실패·수집처 상태도 별도 축이다.

일상 섹터·매크로 게시와 보류 재판정은 무인 처리한다. 관리자 검수 대기라는 말은 모든 기사에 사람 승인을 강제하는 뜻으로 쓰지 않는다. HOLD는 사유·깨울 조건·판정횟수·원래 deadline을 가진다. 새 근거 없이 반복 호출하지 않고, 상세로직의 24/72시간 상한을 지킨다. 수동 보호 글의 AI 수정은 제안으로 남기되 잘못된 본문의 안전 차단은 즉시 한다.

#### 수동 수정 보호·자동 게시 검사·정정 {#admin-publishing-rules}

핵심 주장에 ORDINARY_FACT/SYSTEMIC_MACRO/SENSITIVE_UNCONFIRMED를 부여한다. SYSTEMIC_MACRO는 일반/주요 또는 SECTOR라는 기사명과 관계없이 공식 원문 1개 또는 독립 원출처 3개, 한국 전달 경로, 사실의 유효성을 확인해야 한다. 부족하면 A/B/C·일반 목록 모두 게시 보류다. 관리자 수동 게시에도 같은 게이트를 적용하며 우회 게시 권한은 두지 않는다.

공식 확인은 해당 기관이 확인한 사실 범위만 충족한다. 정책 발표 1개로 모든 기업 수혜를 확정하지 않는다. 같은 통신사·보도자료·동일 취재 재인용은 1건, 같은 소유 그룹은 보수적으로 최대 1건이다. 원출처/그룹 미확정은 독립3에 더하지 않는다. 카테고리 소속은 기업 직접 영향 근거가 아니다. 주요 A 승격은 위 기준에 중요도·현재 한국 시장 영향을 추가한다.

공개 목록은 PUBLISHED만 반환한다. 알려진 Issue ID의 resolver는 본문 API와 분리해 canonical_issue_id·공개 상태·안내를 반환한다. HIDDEN/WITHDRAWN/CORRECTION_PENDING의 본문·민감한 내부 사유는 반환하지 않는다. 존재하지 않는 ID와 비공개 본문을 구분하는 안내 범위를 제한하고 공개 ID 추측으로 내부 원문을 읽을 수 없게 한다.

저장 목록은 해당 ID의 안내 항목을 유지하고 사용자가 삭제할 수 있다. 서버는 병합된 정규 ID를 알려주고 앱은 기기 저장소의 ID를 치환·중복 제거하며 최초 저장시각을 보존한다. 서버가 로컬 저장을 직접 고친다고 가정하지 않는다. 병합의 옛 ID는 redirect 관계이며 공개 상태가 아니다. 조회는 정규 Issue로 재집계하고 부모·자식 조회를 단순 합하지 않는다.

| 상태 | 앱 문구·본문 |
| --- | --- |
| CORRECTION_PENDING | 내용 확인 중 · 기존 내용 제공 중지 / 본문 차단 |
| WITHDRAWN | 근거 확인 불가로 게시 중단 / 본문 차단 |
| HIDDEN | 현재 제공하지 않는 글 / 본문 차단 |
| MERGED 관계 | 정규 상세로 연결, 이후 정규 상태 적용 |
| 정정 완료 PUBLISHED | 정정 시각·변경 요약 표시, 재검사 통과 새 버전만 제공 |

정정 확인 중24시간 후에도 미해결이면 WITHDRAWN. 과거 본문 자동 복원 금지. 안전한 이전 버전도 모든 검사를 통과해 새 공개 버전으로 커밋해야 제공한다. 앱 캐시는 상태/버전 확인 전 비공개 본문을 계속 제공하지 않는다.

#### 게시 날짜와 기사 버전 {#article-dates}

시각은 UTC 저장·한국 표시, 원문/발표/발견/예약/최초게시/실질수정/회차cutoff를 구분한다.

SourceDocument는 원문, Story는 실제 사건, Issue는 앱 상세의 방향이다. Story 1:N Issue, Issue 1:N article_version. 새 사실·새 영향 경로와 독립 제목의 실질·기존 상세로 처리 불충분·기존 방향 전수 비교를 모두 통과한 경우만 NEW_ANGLE로 별도 Issue를 만든다. 일반 후속은 UPDATE 우선. 표현·주가 반응만 바뀌면 새 글을 만들지 않는다.

조회·저장은 Issue 단위이며 부모의 조회를 새 방향에 복사하지 않는다. 홈은 A→B→C 전체에서 Story당 한 카드다. 대표 Issue는 공개·자격 통과 후보 중 A 자격 우선, 다음 B 자격, 다음 기존 대표가 자격을 유지하면 유지한다. 새 실질 변화로 상위 lane 자격이 생길 때만 교체한다. 동률은 최근 material_change_at, 최초 published_at, 고정 Issue ID 순이다. C의 조회 점수 변동만으로 대표를 바꾸지 않는다. 다른 방향은 상세 후속 링크·이슈체크·검색에서 제공한다.

여섯 날짜 버튼 오늘·어제·이번주·지난주·이번달·지난달의 뜻은 한국 달력과 **최초 앱 게시일**이다. 오늘/어제는 단일 날짜 표시를 유지한다. 업데이트로 최초 게시일을 바꾸지 않는다.

최초 진입 홈은 **실시간** 상태이며 날짜 버튼은 미선택이다. 일곱 번째 기간 탭은 추가하지 않는다. 콘텐츠 위 상태줄에 ‘실시간 · 실제 시작~종료 · 거래일 기준’을 표시한다. 버튼을 고르면 달력 보기로 전환하고, ‘실시간으로’ 링크로 기본 상태로 돌아온다. 달력 오늘과 거래 구간을 같은 선택값으로 부르지 않는다.

실시간 C는 한국 시각 **09:10 이상~20:00 미만 KR**, **20:00 이상~다음09:10 미만 FOREIGN_US**로 전환한다. 한국 비거래일에는 KR을 만들지 않고 FOREIGN_US를 유지한다. 20:00은 해외 기준 첫 회차이며 한국 기준 마지막 회차는19:50이다. 한국 기준은 거래일 D, 직전 한국 정규장 종료 직후~회차 cutoff를 후보 창으로 고정한다. 해외 기준은 다음 한국 거래일 D, 직전 한국 정규장 종료 직후~회차 cutoff를 사용한다. 금요일 장후·주말·연휴를 빠뜨리지 않는다. 09:10 전환 때 D·하한을 유지하며 market_basis만 바꾼다. 20:00 전환 때 다음 D로 이동한다. 최초 게시일·Story/Issue ID는 바꾸지 않는다. A/B의 이전 글은 현재 실질 변화가 있을 때 최초 날짜+업데이트 일시를 표시한다. 뉴스 게시와 별개로 C만10분 스냅샷이다. 전환 실패는 현재 모드의 지연/미확보로 표시하고 다른 시장의 직전 순위를 현재 순위로 재사용하지 않는다. 구모드 결과는 기준시각·시장명을 붙인 별도 과거 참조로만 제공한다.

달력 보기의 후보는 스냅샷이 아니라 **선택한 한국 달력 기간에 최초 앱 게시된 Issue 전체**에서 만든다. 현재 공개 자격을 다시 검사하고 숨김 본문을 복원하지 않는다. 현재 A/B를 끼워 넣지 않는다. 달력 홈도 전체 선택기간에서 Story당1개다. 해당 기간 안의 Issue 중 최초 게시시각이 가장 최근인 것을 대표로 선택하고 동률은 고정ID로 정한다. 실시간 대표 선정과 달력 후보 선정은 서로 별도다. 이슈체크·검색은 방향별 Issue를 모두 제공할 수 있다.

선택한 대표 Issue를 실제 최초 게시 한국 날짜별로 묶고, 날짜 안에서는 **최초 게시시각의 시장 구간(calendar_rank_segment)**으로 각각 한 번만 배정한다. 한국 거래일은00:00~09:10 미만 FOREIGN_PRE,09:10~20:00 미만 KR_DAY,20:00~24:00 미만 FOREIGN_POST의3구간이며 한국 비거래일은 하루 전체 FOREIGN_DAY다. 구간 시작 포함·끝 미포함이다. 각 구간의 마지막 완성 C 스냅샷(오늘은 해당 구간 안의 현재까지)만 참조한다. 쿼리는 한국 날짜·market_basis·target_D·구간 시작/끝·cutoff를 함께 고정한다. 정상 종료 cutoff는 FOREIGN_PRE09:00,KR_DAY19:50,FOREIGN_POST/FOREIGN_DAY23:50이다. 평일 오전 글의 KR19:50 순위를21:00 이후 해외23:50 순위로 대체하지 않는다. FOREIGN_PRE와FOREIGN_POST도 같은FOREIGN_US라는 이유로 합치지 않는다. 한국 비거래일의FOREIGN_DAY는 실제 미국 거래일·시세시각을 표시한다. 해당 구간이 아직 시작되지 않았으면 미래 그룹을 만들지 않으며, 구간 스냅샷이 없으면 다른 구간으로 대체하지 않고 그 구간만 미확보로 표시한다. 기간 전체 Story1개 대표 선정 후 구간으로 배정하며, 순위 대조도 그 한국 날짜·구간에 최초 게시된 Issue만 남긴다. 스냅샷에 없는 적격 글은 해당 구간의 ‘당시 순위 미포함’에 최초 게시 최신순으로 보존한다. 날짜 그룹은 최신 날짜 순, 날짜 안 구간은 시작시각 역순, 구간 안은 당시 순위→미포함 순으로 제공하고 각 머리에 시장 기준·실제 cutoff·target_D를 표시한다. 서로 다른 시장/구간 순위 번호·점수는 합산·비교하지 않는다. 과거 순위는 당시 정책·기사버전·시장시각을 유지하고 최신 점수로 가장하지 않는다. 한국 날짜 선택·최초 게시일은 바꾸지 않는다.

섹터 선택은 B/C·일반 목록에 실제 연결된 섹터를 적용한다. 시장 전체 A는 필터 위 별도 ‘시장 전체’ 영역으로만 제공하고 선택 섹터 기사처럼 표시하지 않는다. 달력 보기에는 이 예외도 없다.

### 섹터 관리 {#admin-sectors}

#### 섹터 목록·앱 필터 반영 {#admin-sector-list}

- 섹터 목록에서 항목을 선택하면 섹터 설정을 연다. 섹터명·설명글·같은 단계 안의 표시 순서를 수정하고, 앱 필터와 섹터체크의 변경 내용을 미리 본 뒤 저장한다. 이름 변경에도 고정 섹터 ID를 유지한다.

#### 섹터 상세·하위 카테고리·관련 종목 {#admin-sector-detail}

- 섹터 상세에서 하위 카테고리의 이름·순서를 설정하고, 한국 종목을 검색해 추가하거나 연결을 삭제한다. 종목을 하위 카테고리에 배치하고 묶음 안의 순서를 바꿀 수 있다. 하위 카테고리 없이 종목만 나열하는 섹터도 지원한다.
- 종목은 종목코드가 포함된 공통 종목 정보에서 선택한다. 같은 묶음에 같은 종목을 중복 추가하지 않으며, 다른 하위 카테고리에 같은 종목을 배치할 때에는 해당 묶음에 맞는 설명을 편집한다.
- 섹터 설정에서 삭제를 실행할 수 있다. **설계기준**은 비활성화로 앱 목록·필터와 신규 기사 선택에서 제외하고 기사·이력을 보존하는 방식이다. 삭제 전 연결 기사·하위 섹터·종목·관심 설정·키워드를 확인한다. 게시·예약 글의 대표 섹터라면 대체 섹터를 지정하고, 상위 섹터의 활성 하위 섹터는 이동 또는 비활성화 대상을 정한 뒤 반영한다. 종목 삭제는 현재 섹터나 하위 카테고리에서의 연결 해제로 처리한다.
- 종목 편입 변경 후 새 집계에는 최신 구성 종목을 사용한다. 이미 생성한 과거 섹터 성과 스냅샷은 당시 구성과 계산 기준을 보존한다.

이 절은 **설계기준**이다. ‘섹터’라는 표시 단어 하나로 모든 데이터를 저장하지 않는다.

| 데이터 종류 | 예시 | 사용 목적 |
| --- | --- | --- |
| 상위 분류 | 로봇, AI·반도체 | 상위 탭·필터 그룹 |
| 앱 하위 카테고리 | 휴머노이드 액추에이터·핸드, 메모리 양산 | 목록 이동·필터·성과 집계 |
| 기업 하위 묶음 | 감속기, 핸드, 리플로우, 테스트 장비 | 관련 종목 내 소제목·문맥별 설명 |
| 뉴스 주제 키워드 | HBM, 하이브리드 본딩 | 수집·검색·표시 주제 |
| 기업 영향 연결 | 특정 사건의 특정 한국 기업 | 수혜·피해·관련 판정과 근거 |

각 항목에는 표시명과 별도로 바뀌지 않는 식별자를 부여한다. 같은 표시명이 있어도 목적·적용 범위가 다르면 별도 연결로 관리한다. 뉴스 키워드는 여러 카테고리에 연결할 수 있다.

##### 표시와 이동

- ‘감속기 (에스비비테크)’에는 감속기 하위 묶음, 상위 앱 카테고리, 기사에 실제 연결한 기업을 함께 저장한다.
- ‘HBM (SK하이닉스, 삼성전자)’는 표시 주제이며 기사에서 확인된 메모리 카테고리로 연결한다. HBM이라는 단어만 보고 모든 후공정 기업을 추가하지 않는다.
- 배지·줄 클릭 시 이동할 앱 카테고리를 지정한다. 여러 카테고리이면 목록 선택 또는 기사 상세에서 관련 카테고리를 보여준다.
- 기업 설명은 기업 자체의 기본 설명과 ‘해당 카테고리·하위 묶음에서의 설명’을 나누고 현재 문맥의 설명을 우선한다.
- ‘외 총 N개’는 줄에서 숨긴 영향 항목 수다. 한 영향 항목은 표시 주제/하위 묶음과 실제 관련 기업 묶음으로 구성한다. 같은 기업이 여러 번 나왔다고 기업 수를 합산하지 않는다.

##### 순위와 영향의 분리

섹터 등락률은 해당 카테고리의 유효 구성 종목으로 계산한다. 기사에 연결된 수혜 기업 몇 개만 임의로 골라 전체 섹터 등락률로 표시하지 않는다. 기사 영향 기업, 섹터 구성 기업, 해외 비교 기업을 다른 관계로 저장한다.

**확인 사례:** 액추에이터와 핸드에 모두 속한 기업도 핸드 영역에서는 핸드 설명만 표시한다. 기사 표시 주제명을 바꿔도 필터·이동·과거 순위의 식별자는 유지된다.

#### 스프레드시트 이관 {#sheet-import}

스프레드시트는 초기 이관 자료로 사용하고 이후 관리자 DB를 기준으로 운영하는 방식을 제안한다. 양방향 자동 동기화는 현재 확정된 요구사항이 아니다. 변경 미리보기, 원본 보관, 중복 검사, 반영 이력으로 키워드 손실을 방지한다.

상단 B열의 기업·하위 묶음, C열의 섹터 상세 설명, D열의 검색페이지 설명을 구분해 보존한다. 하단 D열은 직접 적용 검색어, E열은 검색 시 설명글, F열은 산업·수요 연관 검색어다. 하단 E열은 상단 D열과 별도의 편집 필드이며, 최신 셀 값을 기업 검색 설명으로 이관한다. 굵은 하위 묶음을 구조화해 관리한다. 시트 열 대응은 어드민 기획안 v1.1의 ‘스프레드시트 항목의 정확한 대응’을 참고한다.

### 홈 순위 관리 {#admin-ranking}

A는 주요 매크로 2개, 최초 중요 변화 확인 후 6시간을 초기안으로 하며 10분마다 재검사한다. 새 실질 변화만 연장하고 재계산 시 다음 한국 정규장 종료를 넘기지 않는다. 출처 추가·영향 지속 설명만으로 연장하지 않는다. B는 장전/장중/장후 중대한 새 사건·기존 중요 업데이트 3개, 기본60분이다. 무시세 주요 사건은 다음 장전 재평가 상한. C는20개. 수치는 운영 전 검증할 초기값이다.

| 모드 | 정렬 | 조회 장애/표본 부족 | 다양성 |
| --- | --- | --- | --- |
| 혼합 | 100×(.6M+.3P+.1F) | 회차 전체 P 제거, M/F 6:1 재정규화 | 상위10 섹터 제한·발견 슬롯은 이 모드만 |

모든 모드에 Story 중복 제거·공개 자격은 공통이다. 혼합에서 M 없는 글은 C에 넣지 않고 B 자격일 때 B, 나머지는 이슈체크/검색에서 제공한다. ‘조회수 경로’는 별도 조회수순 모드이며 혼합 C의 비공식 우회 슬롯이 아니다. API는 effective_sort·기준시각·지연 사유를 반환하되 PV/UV·내부 점수는 공개하지 않는다. 가격 장애는 마지막 **검증된 같은 모드·세션** 자료·시각을 사용하고 **혼합·등락률순에서만** 유효한 M이 하나도 없으면 C를 같은snapshot_context_id의 마지막 완성 스냅샷으로 유지한다. 모드 전환 직후 같은snapshot_context_id의 유효 스냅샷도 없으면 현재 순위 미확보로 표시한다. 조회수순은 가격 장애만으로 멈추지 않고 해당 모드의 UV·공개 자격·장애 규칙을 적용한다.

#### 정책 설정과 미리보기 {#home-ranking-preview}

기준시각·모드·가중치·기간·누락·제외사유를 관리자에서 미리 보고 정책버전으로 원자 적용한다. 앱에는 결과와 effective_sort·기준시각·지연상태만 제공한다.

기본 성과 기간은 당일이다. 홈M은 KR 시간대에는 한국 대표 섹터, FOREIGN_US 시간대에는 버전 고정 미국 동종·수요 벤치마크를 사용한다. 해외 기준은 초기 미국 상장 비교군이며 중국 등 다른 시장으로 임의 대체하지 않는다. 미국 R열 기업을 전부 평균하지 않는다. 홈의 해외 비교군은 미국 정규장 중 현재가/직전 정규장 종가, 정규장 밖에는 최근 완료 정규장 종가/그 이전 정규장 종가를 사용한다. 프리·애프터마켓은 공급·세션 검증 전 제외한다. 실제 미국 거래일·시장상태·시세시각을 표시하고 휴장·주말의 마지막 값을 새 거래일 수익률처럼 표시하지 않는다. 비교군 버전·동일시장/세션·조정 기준을 고정한다. 장후 한국 가격은 공급계약·세션 검증 전 KRX 정규장 종가 고정이다. 유효70% 이상·유효수 min(3,N) 이상, 구성 종목 중복 제거를 홈 비교군과 섹터랭킹 각각에 적용한다. 미달은 수익률 ‘—’·해당 가격순위 제외·누락 표시이며0%로 채우지 않는다. 소수 구성은 대표기업 기준임을 표시한다. 섹터랭킹·섹터체크 관련종목은 밤에도 한국 종목·선택 성과기간 기준을 유지하고 홈 해외M과 혼동하지 않는다. 실제 공급·조정주가·캘린더 검증은 구현 선행조건이다.

### 뉴스 조회 통계 {#admin-views}

#### 통계 화면 {#admin-views-screen}

유효 조회 원시30일·일별 집계1년은 개인정보 확인 전 초기 상한이다. UV는 요청 구간 전체가 원시 보관 창 안에 있고 집계가 정상인 경우에만 계산한다. 30일 밖의 주/월/임의기간 UV는 초기 기능에서 **지원하지 않음**으로 표시한다. 31일짜리 달의 정확 월 UV도 제공하지 않는다. 원시 이벤트 만료 전 장기 집계를 만들었다고 추정하지 않는다. PV 합계와 일별 UV 각각은 제공할 수 있으나 일별 UV 합을 기간 UV라고 표시하지 않는다. 설치 목록·기간별 고유집합을 장기 보존하는 우회 집계는 도입하지 않는다. 보관 창 안에서도 원시 누락/배치 실패가 있으면 ‘집계 미확보’다.

원시 보관은 서버 수락시각 기준 **30×24시간 롤링**이며 삭제 작업은 그보다 오래된 이벤트만 대상으로 한다. UV 질의는 고정 as_of와 동일 DB 읽기 스냅샷에서 완전성 watermark를 확인한다. 초기 안전 여유1시간을 두고 start≥as_of−(30×24시간−1시간), end≤as_of이며 실제 보관/집계 watermark도 요청 시작을 덮어야 지원한다. 한국 달력 구간을 UTC 경계로 변환해 이 조건을 검사한다. 30일짜리 달도 월말이라는 이유로 자동 지원하지 않는다. 여유 안에서도 수집/집계 누락이 있으면 집계 미확보로 표시하고 일별합으로 대체하지 않는다.

원문 허용기간 만료·권한 철회는 source_revision·blob·임베딩·검색색인·LLM cache·파생 결과·백업 복구 경로까지 삭제/비공개 정책으로 연결한다. 최소 식별 tombstone은 허용된 범위에서만 남겨 재수집·재게시를 막는다. 삭제 ledger는 복원 후에도 재적용한다. 삭제 완료와 백업에서 완전 소거 시점을 구분하고 권한 철회 건은 복원 직후 공개 전에 차단한다. 실제 보관기간·데이터 항목은 개인정보 문서와 일치해야 한다.

#### 조회 수집과 공개 범위 {#admin-views-policy}

- 수집 단위는 원문 언론사 기사가 아니라 우리 앱의 고정된 이슈 ID다.
- 상세 진입, 유효 상세 조회 PV, 고유 조회 UV, 원문 클릭을 구분한다.
- 초기안은 본문 로드·활성 화면의 3초 체류 후 유효 조회다. 시간은 시험 후 확정한다.
- 순위에는 최근 24시간 고유 조회를 기본안으로 사용하고, 재렌더링·전송 재시도·관리자 미리보기·테스트 유입을 중복·유효 집계에서 제외한다.
- 설치 단위 소유권과 이벤트 식별·서버 수락 시각으로 검증한다. 클라이언트가 조회수 누적값을 직접 수정하지 못하게 한다.
- 관리자 목록·통계·순위 미리보기에서만 숫자를 조회한다. 공개 기사·검색·홈 응답에는 조회 통계·내부 인기 점수를 포함하지 않는다.
- 서버 전송 처리와 실제 읽음·체류를 구분하고 이상 반복 조회를 감지한다. 초기안은 완벽한 사람 판별을 보장하는 지표가 아니다.
- 실제 수집 항목과 보관 기간은 개인정보처리방침·스토어 공개 내용에 반영한다.

### 키워드 검토 {#admin-review}

매 달력일20:00 실행한다. 범위 변화 없는 기존 검색어의 약어·표기 변형만 공식 용어 또는 독립 원출처3건·표본 검증 후 자동 별칭 연결한다. 기존 카테고리의 신규 의미 연결·새 기업/제품 역할·수혜 판정·카테고리 통합/삭제·새 출처 활성화는 자동 반영하지 않고 근거 있는 제안으로 보존한다. 예외가 대기해도 기존 조건으로 계속 운영한다. 하단D 앱 검색어·E 표시 설명·F 보조문맥은 뉴스 키워드 정비가 자동 변경하지 않는다.

키워드 정비 D일 묶음은 **전날20:00 초과~D일20:00 이하**의 연속24시간 창이다. 앱 게시일·한국장65회와 구분한다. 각 원문판본의 keyword_eligible_at은 max(최초 발견 작업의 예약시각, 확인된 원문 발표시각)으로 한 번 고정한다. 20:00 회차가 20:01 발표를 뒤늦게 받아도 다음날 묶음이고,19:50 작업이20:03에 끝나도 발표가19:50 이전이면 D일 묶음이다. 22:00 발표를22:10 수집하면 다음날20:00 묶음에 포함한다.20:01·23:59·00:00 자료도 빠짐없이 각각 한 번 포함한다. 발행시각 미확인은 PENDING_TIME으로 두고 확인 후 이 규칙에 따라 귀속하며 원래 날짜의 늦은 추가 묶음이 될 수 있다.

PENDING_TIME은 최초 발견 후72시간 상한이다. 그 안에 확인되면 위 규칙, 끝내 미확인이면 최초 발견 작업의 예약시각을 keyword_eligible_at으로 고정하고 ‘시각 미확인 · 발견 기준’ 표지를 남겨 그 귀속 날짜의 늦은 추가 묶음으로 처리한다. 확정한 귀속은 뒤늦은 원문 시각 발견으로 재이동·중복 반영하지 않고 정정 이력만 추가한다. 이는 키워드 정비 자료의 귀속 규칙일 뿐이며 기사 게시의 신선도/근거/HOLD 기준을 완화하지 않는다.

작업ID 목록과 SourceDocument/revision별 고정 귀속을 cutoff manifest로 보존한다. 한 폴링 작업이 경계를 넘는 판본을 받으면 판본별로 서로 다른 묶음에 배정할 수 있다. 이미 콘텐츠 판단 이벤트에서 처리한 자료도 같은 판본 ID로 한 번만 센다.20:30 미완료는 PARTIAL로 마감하고 뒤늦은 결과는 고정 귀속 날짜의 추가 묶음으로 처리한다. 신규자료를 임의로 과거 날짜에 넣거나 같은 판본을 다음날 재반영하지 않는다. 기준버전 충돌·재실행·부분 선적용·관찰·개별관계 롤백을 기록한다.

#### 반영 전후 평가와 되돌리기 {#keyword-quality}

표본검증·부분선적용·오탐/미탐·비용·버전 충돌을 관리하고 이번 변경 관계만 복구한다. 관리자 수동 편집을 자동 덮어쓰지 않는다. 키워드 복구가 게시 기사 정정을 대신하지 않는다.

### 자동화·검색 이력 {#admin-jobs}

회차 목록에서 성공·대기·실패·부분 누락을 확인한다. 회차를 열면 검색식, 공급처, 원문 확보, AI 검수 결과, 사용량과 비용을 확인하고 필요하면 재시도하거나 중지한다.

관리자에서 다음 항목을 확인하고 사건·검색식·실행 회차별로 추적한다.

- 공급처, 언어·국가 조건, 검색식과 버전, 연결 후보 카테고리.
- 예약·실행·완료 시각, 조회 범위, 확인 지점, 페이지 제한·실패·누락 상태.
- 발견 기사와 원문 URL, 중복 사건, 원문 확보 상태.
- 채택·제외·검수 대기 이유, 실제 연결 섹터·기업과 근거.
- 새 이슈 생성·기존 이슈 갱신·출처만 추가한 결과.
- 검색 API 호출량, 원문 확보 작업량, AI 분석량과 비용.

공통 검색식 공유, 후보 단계의 중복 제거, 이미 분석한 원문의 재사용, 본문 변경 확인으로 불필요한 호출을 줄인다. 관련성이 명확하지 않은 후보를 모두 전체 상세 작성 단계까지 보내지 않는다. 공급처 한도·비용 때문에 중지·지연된 검색은 관리자에 표시하고 완료된 것처럼 처리하지 않는다.

### 뉴스 수집·AI 분석·작성 {#news-production}

SourceDocument는 원문, Story는 실제 사건, Issue는 앱 상세의 방향이다. Story 1:N Issue, Issue 1:N article_version. 새 사실·새 영향 경로와 독립 제목의 실질·기존 상세로 처리 불충분·기존 방향 전수 비교를 모두 통과한 경우만 NEW_ANGLE로 별도 Issue를 만든다. 일반 후속은 UPDATE 우선. 표현·주가 반응만 바뀌면 새 글을 만들지 않는다.

조회·저장은 Issue 단위이며 부모의 조회를 새 방향에 복사하지 않는다. 홈은 A→B→C 전체에서 Story당 한 카드다. 대표 Issue는 공개·자격 통과 후보 중 A 자격 우선, 다음 B 자격, 다음 기존 대표가 자격을 유지하면 유지한다. 새 실질 변화로 상위 lane 자격이 생길 때만 교체한다. 동률은 최근 material_change_at, 최초 published_at, 고정 Issue ID 순이다. C의 조회 점수 변동만으로 대표를 바꾸지 않는다. 다른 방향은 상세 후속 링크·이슈체크·검색에서 제공한다.

핵심 주장에 ORDINARY_FACT/SYSTEMIC_MACRO/SENSITIVE_UNCONFIRMED를 부여한다. SYSTEMIC_MACRO는 일반/주요 또는 SECTOR라는 기사명과 관계없이 공식 원문 1개 또는 독립 원출처 3개, 한국 전달 경로, 사실의 유효성을 확인해야 한다. 부족하면 A/B/C·일반 목록 모두 게시 보류다. 관리자 수동 게시에도 같은 게이트를 적용하며 우회 게시 권한은 두지 않는다.

공식 확인은 해당 기관이 확인한 사실 범위만 충족한다. 정책 발표 1개로 모든 기업 수혜를 확정하지 않는다. 같은 통신사·보도자료·동일 취재 재인용은 1건, 같은 소유 그룹은 보수적으로 최대 1건이다. 원출처/그룹 미확정은 독립3에 더하지 않는다. 카테고리 소속은 기업 직접 영향 근거가 아니다. 주요 A 승격은 위 기준에 중요도·현재 한국 시장 영향을 추가한다.

원문 접근·AI 분석 권한이 확인된 리포트는 SECTOR의 **분석/추정 의견** 기사 근거가 될 수 있다. 기존 공개 사실과 리포트의 새 추정·가정·의견을 분리하고 상세 핵심 이슈 위에 ‘리포트 의견’, 작성 증권사·원문 시각·원문 링크를 표시한다. 검증 가능한 공개 사실과 계산/추정 근거가 없는 목표가 홍보는 제외한다. 리포트1건으로 SYSTEMIC_MACRO 사실·미확정 계약·확정 수혜를 게시하지 않는다. 인용 허용 범위 밖 표/문장 복제 금지. 권한 미확정 리포트/Telegram은 RIGHTS_HOLD 유지다.

### 뉴스 검색·원문 확보·관련성 판단 {#news-search}

부록106행은 원본 보존 대상이지 독립 매체 수나 모두 가동 중이라는 뜻이 아니다. 권한 미확인은 RIGHTS_HOLD로 표시한다. CANDIDATE는 등록 직후 평가 전 임시 상태이며 요청 실행 불가다. 첫 평가에서 이용 범위 미확인은 RIGHTS_HOLD로 전환한다. 부록의 미확인 초기값은 RIGHTS_HOLD / RIGHTS_UNVERIFIED로 통일한다.

시트 외 경로도 같은 sources/permission_profiles/endpoint/adapter 버전에 등록한다. 네이버·Brave는 검토 중인 발견 전용 검색 API이며 PLATFORM_RESOLVE·쿼리 예산 큐다. 자체 독립 근거로 세지 않는다. DART/KIND/SEC/중앙은행/정부/기업IR 등은 OFFICIAL 원문·정정 감시 경로다. 계약·기술·허용량 미확정은 비활성으로 둔다. 공식성만으로 수집·보관 허가를 추정하지 않는다.

감시 주제의 검색 표현·별칭·우선순위 수정과 기존 ACTIVE 경로 선택은 다음 회차 반영한다. 새 URL은 등록 요청이며 권한→기술→SHADOW→ACTIVE 검증을 건너뛰지 않는다. 일시 가용성 복구와 신규/품질 강등 SHADOW는 상세로직의 서로 다른 복구 절차를 적용한다.

수집→제목/머리말 홍보·무관1차차단→본문/공식근거→claim·시각·기업·한국 영향→Story비교→상세작성/갱신→게시검사 순서다. 제목/검색 요약만으로 본문을 생성하지 않는다. 목록/본문 미확보·PARTIAL·지연을 구분하고 checkpoint를 성공인 척 전진하지 않는다. 행별 주기와 특수경로는 매체별 부록, 큐/재시도/한도는 상세로직3~7절을 따른다.

운영 시간의 기준은 한국 시간이며 시장 휴장·서머타임을 반영한다.09:10은KR 첫 회차,19:50은KR 마지막,20:00은FOREIGN_US 첫 회차다. 뉴스 게시/정정은 이 회차를 기다리지 않는다. 늦은 결과는 [20:00 해외 전환과 일일 키워드 마감](#daily-cutoff)을 따른다.

장후에는 가격 급등만이 아니라 중요 사건 자체를 기준으로 기사를 작성한다. 아직 주가 반응이 없는 실적 발표도 수집 대상이다. 거래나 새 시세가 없으면 마지막 가격·기준 시각을 유지하고 새 시세처럼 표시하지 않는다.

20:00 키워드 정비·FOREIGN_US 전환·뉴스24시간 처리는 독립 실행한다. 야간에도 게시·갱신·정정을 계속하며 다음 장전까지 보류하지 않는다.


#### 장후 새 이슈와 홈 노출 {#after-hours}

A는 주요 매크로 2개, 최초 중요 변화 확인 후 6시간을 초기안으로 하며 10분마다 재검사한다. 새 실질 변화만 연장하고 재계산 시 다음 한국 정규장 종료를 넘기지 않는다. 출처 추가·영향 지속 설명만으로 연장하지 않는다. B는 장전/장중/장후 중대한 새 사건·기존 중요 업데이트 3개, 기본60분이다. 무시세 주요 사건은 다음 장전 재평가 상한. C는20개. 수치는 운영 전 검증할 초기값이다.

기본 성과 기간은 당일이다. 홈M은 KR 시간대에는 한국 대표 섹터, FOREIGN_US 시간대에는 버전 고정 미국 동종·수요 벤치마크를 사용한다. 해외 기준은 초기 미국 상장 비교군이며 중국 등 다른 시장으로 임의 대체하지 않는다. 미국 R열 기업을 전부 평균하지 않는다. 홈의 해외 비교군은 미국 정규장 중 현재가/직전 정규장 종가, 정규장 밖에는 최근 완료 정규장 종가/그 이전 정규장 종가를 사용한다. 프리·애프터마켓은 공급·세션 검증 전 제외한다. 실제 미국 거래일·시장상태·시세시각을 표시하고 휴장·주말의 마지막 값을 새 거래일 수익률처럼 표시하지 않는다. 비교군 버전·동일시장/세션·조정 기준을 고정한다. 장후 한국 가격은 공급계약·세션 검증 전 KRX 정규장 종가 고정이다. 유효70% 이상·유효수 min(3,N) 이상, 구성 종목 중복 제거를 홈 비교군과 섹터랭킹 각각에 적용한다. 미달은 수익률 ‘—’·해당 가격순위 제외·누락 표시이며0%로 채우지 않는다. 소수 구성은 대표기업 기준임을 표시한다. 섹터랭킹·섹터체크 관련종목은 밤에도 한국 종목·선택 성과기간 기준을 유지하고 홈 해외M과 혼동하지 않는다. 실제 공급·조정주가·캘린더 검증은 구현 선행조건이다.

##### 주요 매크로 자동 지정과 배치 {#macro-home-placement}

핵심 주장에 ORDINARY_FACT/SYSTEMIC_MACRO/SENSITIVE_UNCONFIRMED를 부여한다. SYSTEMIC_MACRO는 일반/주요 또는 SECTOR라는 기사명과 관계없이 공식 원문 1개 또는 독립 원출처 3개, 한국 전달 경로, 사실의 유효성을 확인해야 한다. 부족하면 A/B/C·일반 목록 모두 게시 보류다. 관리자 수동 게시에도 같은 게이트를 적용하며 우회 게시 권한은 두지 않는다.

공식 확인은 해당 기관이 확인한 사실 범위만 충족한다. 정책 발표 1개로 모든 기업 수혜를 확정하지 않는다. 같은 통신사·보도자료·동일 취재 재인용은 1건, 같은 소유 그룹은 보수적으로 최대 1건이다. 원출처/그룹 미확정은 독립3에 더하지 않는다. 카테고리 소속은 기업 직접 영향 근거가 아니다. 주요 A 승격은 위 기준에 중요도·현재 한국 시장 영향을 추가한다.

#### 20:00 해외 전환 회차와 일일 키워드 마감 {#daily-cutoff}

매 달력일20:00 실행한다. 범위 변화 없는 기존 검색어의 약어·표기 변형만 공식 용어 또는 독립 원출처3건·표본 검증 후 자동 별칭 연결한다. 기존 카테고리의 신규 의미 연결·새 기업/제품 역할·수혜 판정·카테고리 통합/삭제·새 출처 활성화는 자동 반영하지 않고 근거 있는 제안으로 보존한다. 예외가 대기해도 기존 조건으로 계속 운영한다. 하단D 앱 검색어·E 표시 설명·F 보조문맥은 뉴스 키워드 정비가 자동 변경하지 않는다.

키워드 정비 D일 묶음은 **전날20:00 초과~D일20:00 이하**의 연속24시간 창이다. 앱 게시일·한국장65회와 구분한다. 각 원문판본의 keyword_eligible_at은 max(최초 발견 작업의 예약시각, 확인된 원문 발표시각)으로 한 번 고정한다. 20:00 회차가 20:01 발표를 뒤늦게 받아도 다음날 묶음이고,19:50 작업이20:03에 끝나도 발표가19:50 이전이면 D일 묶음이다. 22:00 발표를22:10 수집하면 다음날20:00 묶음에 포함한다.20:01·23:59·00:00 자료도 빠짐없이 각각 한 번 포함한다. 발행시각 미확인은 PENDING_TIME으로 두고 확인 후 이 규칙에 따라 귀속하며 원래 날짜의 늦은 추가 묶음이 될 수 있다.

PENDING_TIME은 최초 발견 후72시간 상한이다. 그 안에 확인되면 위 규칙, 끝내 미확인이면 최초 발견 작업의 예약시각을 keyword_eligible_at으로 고정하고 ‘시각 미확인 · 발견 기준’ 표지를 남겨 그 귀속 날짜의 늦은 추가 묶음으로 처리한다. 확정한 귀속은 뒤늦은 원문 시각 발견으로 재이동·중복 반영하지 않고 정정 이력만 추가한다. 이는 키워드 정비 자료의 귀속 규칙일 뿐이며 기사 게시의 신선도/근거/HOLD 기준을 완화하지 않는다.

작업ID 목록과 SourceDocument/revision별 고정 귀속을 cutoff manifest로 보존한다. 한 폴링 작업이 경계를 넘는 판본을 받으면 판본별로 서로 다른 묶음에 배정할 수 있다. 이미 콘텐츠 판단 이벤트에서 처리한 자료도 같은 판본 ID로 한 번만 센다.20:30 미완료는 PARTIAL로 마감하고 뒤늦은 결과는 고정 귀속 날짜의 추가 묶음으로 처리한다. 신규자료를 임의로 과거 날짜에 넣거나 같은 판본을 다음날 재반영하지 않는다. 기준버전 충돌·재실행·부분 선적용·관찰·개별관계 롤백을 기록한다.

LLM 후보 추출·근거 비교 초안은 DB 잠금 밖에서 한다. 정부/기관 조치·정책·시장 공통 사건 또는 SYSTEMIC_MACRO 핵심 claim이 있거나 그 분류가 불확실하면 기사 표제와 관계없이 MACRO_ALL 파티션으로 보낸다. 기업 직접 사실만 확인된 사건만 entity/event_family 경로를 사용한다. 교차 사건도 MACRO_ALL→정렬 entity ID→정렬 Story ID 순으로 잠근다. 사후 병합도 같은 순서다.

병합 전 양쪽 Story의 거시/기업 분류와 필요한 entity 집합을 읽어 잠금 계획을 만든다. MACRO_ALL(해당/분류 불확실 시)→정렬 entity ID→정렬 Story ID 순으로만 진입한다. 잠금 후 다른 파티션/기업 잠금이 필요함을 알게 되면 전부 풀고 계획을 다시 만들어 처음부터 순서대로 재진입한다. 이미 Story 잠금을 잡은 상태에서 상위 파티션 잠금을 추가하지 않는다.

잠금 안에서는 최신 catalog/policy·canonical key·사실 집합을 재조회하는 짧은 결정/커밋만 한다. DB lock_timeout 초기2초·transaction5초, 실패 시 HOLD(H_CONCURRENCY) 후 재시도한다. 원문/LLM 네트워크 호출을 잠금 안에 두지 않는다. 불확실하면 초안을 저장하고 잠금을 풀어 재분석 후 expected_version 검사로 재진입한다. 외부 결정 ID unique와 정규 사건/Issue 방향 unique·outbox 효과키가 함께 중복을 막는다. 실제 처리량·교착은 구현 시험으로 검증한다.

공개 본문·resolver·설치설정 API와 관리자·worker API 권한을 분리하고 RLS/서버 검사를 함께 적용한다. 통계·원문권한·LLM비밀은 앱 공개 응답에 넣지 않는다. 입력 URL 허용목록·내부IP/SSRF·프롬프트 지시 차단과 로그 비밀 제거를 구현한다.

### 개발 전에 확정할 사항 {#decisions}

이 폴더의 서비스 v1.6·어드민 v1.1·제작 실행계획 v1.3·뉴스 상세로직 v1.1·매체별 부록을 하나의 개정 묶음으로 사용한다. 기존 판본은 이력으로 보존한다. 문서 해시는 bundle-manifest.json에 기록한다. 사용자 확정 요구가 우선이고, 같은 묶음의 운영 계약은 **공통-운영계약-v1.0.md**, 세부 처리 절차는 뉴스 상세로직 v1.1, 화면은 서비스 v1.6·어드민 v1.1, 순서는 제작 실행계획 v1.3을 따른다. 충돌이 발견되면 임의로 유리한 규칙을 택하지 않고 해당 작업을 보류한다.

### 24시간 뉴스 처리와 독립 순위 작업 {#continuous-news}

**확정 요구:** 뉴스 수집·분석·신규 게시·기존 글 업데이트·정정/철회는 주말·휴일을 포함해24시간 계속한다. 뉴스 한 건은 `발견 → 중복/홍보/범위 판별 → 허용된 본문·공식 근거 확인 → 사실/한국 영향 분석 → Story/Issue 비교 → 신규 작성 또는 기존 버전 수정 → 게시 검사 → 원자 공개·캐시/검색 반영` 순서로 처리한다. 게시 기준을 통과하면 다음10분 순위 회차·20시 키워드 작업·다음 장전까지 기다리지 않고 반영한다. **구현 계약:** 단계별 영속 큐·작업키·lease·재시도·실패 큐를 두고 서로 다른 사건은 제한된 동시성으로 처리한다. 같은 사건/Issue의 결정과 수정은 공통계약15절 잠금·expected_version·unique키로 직렬화한다. 한 기사 분석이 오래 걸려도 새 목록 수집과 다른 사건 처리는 계속된다. 원문/LLM 호출은 DB 잠금 밖에서 수행한다. ‘순차’는 기사 내부의 단계 의존성이지 전체 시스템 단일 직렬 실행이 아니다. 수집 빈도는 뉴스 상세로직4절의 허용 경로별 주기이고, 수집 후 단계는 준비 이벤트에 따라 실행한다. 새 근거가 없는HOLD를 매 순간 재분석하지 않는다. worker/LLM 비용·공급처 호출 제한도 계속 지킨다.

**홈과의 분리:** 공개 즉시 상세·이슈체크·검색·저장 resolver에 최신 공개 버전을 반영한다. A/B는 게시/중요변화 이벤트로 자격을 검사해 반영하고10분 만료 감시는 보조다. 20:00 키워드 정비와 뉴스 큐는 독립 실행한다. 정비 작업이 원문 발견·분석·게시·정정 큐를 중지하거나 같은 잠금을 장시간 독점하지 않게 자원을 분리한다. 푸시는 게시와 별도이며 기존 동의·야간·빈도·원인 중복 제한을 유지한다. 지연/실패는 단계별 상태·최초 발견/분석/게시 시각으로 관측한다. 실운영 지연시간은 공급·용량시험 전 보장하지 않는다.

### 뉴스 선정 시장과 한국 주식 분석 관점 {#korean-perspective}

**확정 요구:** 한국 시각09:10 이상~20:00 미만에는 한국 주가·섹터 신호,20:00 이상~다음09:10 미만에는 해외 주가·기업·매크로 신호를 뉴스 탐색·홈M의 우선 기준으로 사용한다. 한국 휴일에는 해외 기준을 유지한다. 시간대는 검색 우선순위·시장 지표를 바꾸며 다른 국가의 중요한 공시·한국 관련 매크로·악재 수집을 차단하지 않는다. 가격 상승은 게시 필수조건이 아니다.

핵심 이슈는 해당 사건 주체·시각·실적·정책 등 **원래 사건의 사실**을 쓴다. 해외 선정 기사라면 해외 기업/시장의 사건을 중심으로 쓰며 억지로 한국 사실로 바꾸지 않는다. 이슈 분석·예상 시나리오·수혜 섹터·피해 섹터·연관 섹터·리스크 체크리스트·주요 일정은 항상 **한국 상장기업과 국내 섹터의 관점**이다. 예: 엔비디아 실적은 핵심 사실, 국내HBM/후공정의 제품·고객·수요 연결과 불확실성은 한국 영향 분석이다. 국내 전달 근거가 없으면 해외 가격 급등만으로 게시하지 않는다.

기사 버전에는 `selection_market_basis(KR/FOREIGN_US), source_market, evidence_as_of, analysis_perspective=KR_EQUITY, impact_profile, visibility_policy_version`을 저장한다. 홈 스냅샷의 현재 market_basis는 별도다.09:10/20:00이 됐다는 이유로 기사를 다시 게시하거나 source_market/최초일을 바꾸지 않는다. 새 사건/근거 없이 기존 본문을 재작성하지 않는다. 해외 비교군과 시트 연관기업은 탐색 도구이며 국내 기업 영향 근거를 대신하지 않는다.

### 기사별 상세 영역 노출 {#article-visibility}

같은 템플릿을 사용하되 모든 영역을 채우지 않는다. 공통 필수는 기사 상단·핵심 이슈·한국 관점 이슈 분석·출처이고 선택 영역은 아래 결정표로 산출한다. 빈 제목·빈 구분선·‘등록된 정보 없음’ 자리 채움 문구를 표시하지 않는다. 부정 시나리오만 단독 표시하지 않는다.

| 근거 기반 분석 상태 | 예상 시나리오 | 섹터·리스크 노출 |
| --- | --- | --- |

서버의 방향 판정은 검증된 영향 경로를 먼저 구조화한 뒤 결정한다. `positive_path`는 BENEFIT 근거 또는 검증된 조건부 긍정 경로, `negative_path`는 DAMAGE 근거 또는 검증된 조건부 부정 경로의 존재다. 둘 다 있으면 POSITIVE_NEGATIVE로 긍정·부정을 함께 표시한다. BENEFIT과DAMAGE가 동시에 있으면 서로 다른 섹터/경로여도 반드시 이 규칙이며 긍정만으로 축소하지 않는다. 긍정만 있으면 POSITIVE_ONLY(피해 섹터 없음), 긍정 없이DAMAGE가 있으면 DAMAGE_ONLY로 시나리오를 숨긴다. 직접BENEFIT/DAMAGE 없이RELATED만 있으면 RELATED_CONDITIONAL로 두고 positive_path/negative_path 조합에 따라 긍정만/양쪽/미노출을 산출한다. 직접 피해 없이 부정 조건만 있는 경우도 시나리오는 숨기고 검증된 연관/리스크에 설명한다. 별도의 부정 단독 시나리오나 임의 예외는 두지 않는다. 이 판정은 LLM의 시나리오 문장 유무가 아니라 근거 ID가 붙은 영향 경로에서 산출하고 이후 문장을 작성한다.

RELATED_CONDITIONAL에서조차 근거 있는 긍정 경로가 없으면 긍정을 창작하지 않고 예상 시나리오는 숨긴다. 확인된 연관과 리스크만 설명할 수 있다. 이는 연관 섹터를 무조건 수혜로 바꾸지 않는 안전 조건이다. DAMAGE_ONLY의 리스크는 실제 피해의 지속·확대·해소를 확인할 항목을 근거로 작성하며 내용 없이 게시 형식만 채우지 않는다.

수혜/피해는 국내 사업·수요·원가·규제 등 방향과 전달 경로의 근거가 충분한 경우, 연관은 연결은 확인됐으나 방향/규모/조건이 미확정인 경우다. 여기서 확실한 호재·피해는 **영향 방향의 근거**를 뜻하며 주가 상승/하락 확정이나 수익 보장이 아니다. 같은 섹터·동일 영향 경로를 세 영역에 중복 배치하지 않는다. 서로 다른 경로는 구분 설명·근거를 두고 표시할 수 있다. `related_sector_ids`는 필터/관심알림 연결의 상위 집합이며 화면의 연관 섹터 목록과 같다고 가정하지 않는다. `impacts[].direction=BENEFIT/DAMAGE/RELATED`·한국 섹터/기업·경로·근거 ID·조건으로 표시 목록을 별도 산출한다.

주요 일정은 **해당 기사 이후 국내 영향 판단을 위해 실제 확인할 발표·시행·실적·행사**가 있고 시각/기간·시간대·공식/검증 근거가 있을 때만 표시한다. 해외 행사도 한국 영향 체크 대상이면 포함한다. 이미 끝난 사건 날짜나 막연한 ‘향후 확인’은 일정 칸을 만들지 않는다. 발표일은 미정이나 공식 예정기간이 확인되면 그 기간과 미확정 사실을 명시한다. 시간 경과/취소/정정 시 재검증해 지난 항목은 향후 일정에서 제거한다.

표시용 `visible_sections`는 서버가 최신 공개 article_version·검증 근거·visibility_policy_version으로 계산하고 관리자 미리보기와 Android/iOS가 같은 계약을 사용한다. 클라이언트의 임의 숨김만으로 잘못된 생성 데이터를 통과시키지 않는다. 선택 영역만 근거가 없으면 그 영역을 제외하고, 핵심 사실/한국 영향이 무너지면 기존 게시 차단·정정 절차를 적용한다. 시간 경과에 따른 일정 제거는 표시 갱신이며 최초 게시일을 변경하지 않는다. 본문 실질 변경은 새 버전·감사 이력으로 처리한다.

## 개발 프로세스 개정 — 시험·운영 활성화 경계 {#process-rollout}

제품의24시간 무인 뉴스 운영·한국/해외 기준·기사별 조건부 노출 계약은 유지한다. 제작 실행계획18절(development-gates)이 개발 증거와 배포 게이트의 단일 기준이다. 공통 큐/outbox·lease·재시작 복구는4단계, 한국 관점·영향/visible_sections 계약과 수동 경로 R05~R08은4~5단계, 가격·시장전환/달력 R01/R10은7단계, 실제24시간 파이프라인 R02~R04/R09는8~10단계에 연결한다.3단계 공급 시험은 병행하며 M1은 명시된 수동/샘플 fixtures로 만들 수 있다. 실제 공급 권한 통과를 샘플로 대체하지 않는다.

원문/발췌/파생 자료의 권한·보관 상한을 지키는 평가 registry·Story 분할·dataset/acceptance policy 버전을8단계까지 고정한다.9단계는 격리된 SHADOW 기능/품질 시험이며 운영 공개/실제 푸시는 없다. 운영 LIVE는12단계의 권한·경로 승격·고정평가·다중거래일/휴일 통합·환경·배포/이전앱 호환·복원·알림/공개문서 게이트에 결속된 activation_receipt 범위만 활성화한다. 이는 출시 전 개발/배포 증거이며 정상 운영의 기사별 사람 승인이나 새로운 이용자 알림 유형을 추가하지 않는다.

8단계부터 운영 담당용 오류/큐/정정지연/비용 경보를 두고10단계에서 긴급 중지·재개를 시험한다. 앱3종 알림과 별도 채널이다. 0~1단계부터 계정 유형·공급 허가·테스터 모집 등 긴 외부 준비를 병행한다. 소프트웨어 버전·계정별 스토어 조건·요금은 실제 착수 시 다시 확인하고 기존 기록을 실제 완료로 표현하지 않는다. 배포는expand→호환 서버/worker→앱→지원정책 확인 후contract이며 코드 롤백과 데이터 복원을 분리한다.
