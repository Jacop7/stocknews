## 구현 r1 검수 보완 · r2 준비

Codex r1의 S6DI-R1-01~04와 Claude r1의 S6DI-01~02는 CHANGES_REQUIRED로 보존한다. 아래는 작성자의 수정·시험 기록이며 검수자의 종결 판정을 대신하지 않는다.

- 미도달 COMMIT으로 서버가 STARTED에 남아도 원자 START_SEAL로 빠져나온다. 이미 적용된 정확한 새 세대 쿠키가 검증되면 같은 설치의 COMMIT/ACK 결과를 재개하며, COMMIT 재발급이나 옛 응답 헤더 재적용으로 복구하지 않는다. ACK 헤더가 이미 적용돼 pending 쿠키가 없으면 유효한 정확한 세대의 session 증명으로 재진입한다. 쿠키가 전혀 복구되지 않는 경우만 서버 기한·명시 포기 경로를 유지한다. 웹의 ACTIVE fence만 남고 session 쿠키가 만료된 경우에도 명시 재연결이 가능하다.
- native는 만료된 STARTED·ACK 전 capability 만료를 각각 봉인/포기 처리한다. 미등록 ROTATE/REVOKE START를 봉인했을 때는 아직 유효한 이전 capability를 버리지 않는다. 명시 연결 해제는 비밀 없는 revoked-v1 표지만 남겨 재시작 후 자동 새 발급을 막으며, revoked capability는 보안 저장소에서 제거한다. 재설치 시 이전 Keychain을 상속하지 않는 별도 marker 규칙은 유지한다.
- 적용한 SQL41~44는 바꾸지 않았다. 추가 SQL45에서 catalog → installation 잠금·capability 재확인 → settings 순서로 저장을 직렬화했다. 기본 설정의 no-op revoke 이후 오래된 저장이 알림을 다시 켜지 못한다. 실제 두 세션의 커밋 경쟁을 양쪽 순서로 시험했다.
- QA 통계의 완전성은 DB 트랜잭션에서 동기로 수락한 사건 기록의 스냅샷 범위다. 모든 앱 방문이 서버에 도달했다는 의미가 아니다. 마지막 조회 사건 시각과 검증 범위 끝을 구분하며 무이벤트 기간을 자동 누락으로 만들지 않는다. 알려진 수락 기록 누락은 service 전용 gap 기록으로 표시하고, 해소되지 않은 gap 또는 시작 범위 부족에서는 기간·기사별 UV를 모두 null로 반환한다. gap을 자동 지우거나 조기 삭제를 정상 자료로 덮지 않는다. 실제 감시·정기 실행 연결은 6E 후속이다. 관리자 화면은 요청 실제 기간과 마지막 수락 시각을 구분하고, 확보된 기록 시작 이후 기간을 별도로 조회할 수 있다.
- 기존 통계 시험의 미래 collected_through 주입을 제거했다. 실제 수락 후 현재 시각 질의의 COMPLETE/기간 UV, 명시 gap의 PARTIAL/UV null을 시험한다. 원래 자료 범위를 벗어난 요청을 COMPLETE로 꾸미지 않는다.
- Claude S6DI-03의 P3 권고(다른 세대 session이 남은 bootstrap의 서버 확인 플래그, 인증 없는 tombstone 장기 정리, 영구 view 오류·ticket 결과 고정 강화)는 비차단 후속 항목으로 보존한다. 현재 단계 완료나 운영 활성화를 뜻하지 않는다.
