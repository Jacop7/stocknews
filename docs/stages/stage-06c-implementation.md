# 6C 검색과 기기 저장 구현

승인 계획 r2 DUAL `f3d0271b2c5263fc4661e4e247b1c51f533c09d8ba2a29144ba9a14805265d8e`와 검증된 6B `73ab521`을 기준으로 구현했다. 현재 상태는 구현 재검수 대기이며 전체 6단계 완료가 아니다.

검색 헤더는 검색어·지우기·취소와 뉴스/종목 두 탭을 제공한다. 뉴스는 현재 공개된 전체 날짜의 제목·요약·핵심 이슈·분석과 실제 연결된 활성 섹터 키워드만 검색한다. 같은 Issue는 한 번만 표시한다. 종목은 기업명과 D열 직접 적용 검색어로 검색하고 E열 최신 설명글과 줄바꿈을 표시한다. 한 기업은 하나의 결과와 활성 관련 섹터 연결을 가진다. 코드·검증 별칭 검색은 7단계까지 보류한다. 339개 참조 기업의 미확인 코드·가격·증권 URL은 null을 유지한다.

새 공개 읽기 경로는 `/v2/search/news`, `/v2/search/companies`, `/v2/companies/:source_company_ref/sectors`, `/v2/saved`다. 이전 경로와 SQL 1~38은 보존하고 SQL 39·40을 추가했다. 검색은 최대 80자·6단어·20건이고 뉴스 날짜/UUID, 기업 이름/등급/UUID 커서는 질의·탭·분류 버전·페이지 크기에 결속된다. 호스트·Origin·인증정보 거부, 공통 요청 제한·시간·응답 크기 제한은 유지한다. 검색어를 외부로 보내거나 로그·기기 검색 이력에 저장하지 않는다.

저장은 로그인 없이 이 기기에 Issue UUID와 최초 저장 시각만 최대 500개 기록한다. 제목·본문·요약·비밀은 보관하지 않는다. 네이티브는 AsyncStorage 2.2.0, 브라우저는 Web Locks 안에서 최신 localStorage를 읽고 변경한다. 읽기 완료 전 쓰기, 쓰기 실패의 성공 표시, 손상 데이터 초기화, 한도 초과 자동 삭제를 하지 않는다. 잠금 미지원 브라우저는 저장 실패를 안내한다. alias 변환도 최신 목록에 직렬 적용해 삭제한 ID를 되살리지 않고 최초 저장 시각의 최솟값으로 중복을 합친다.

저장 화면은 현재 보이는 20개 ID만 서버에서 읽는다. 현재 공개된 카드는 최신 내용을 제공하고 숨김·철회·정정·미확인·연결 오류에는 과거 제목이나 본문을 표시하지 않는다. 해당 항목의 저장 해제는 가능하다. foreground 및 화면 재진입에서 재검사하며 취소된 요청·다른 질의의 늦은 응답을 무시한다. 429는 빈 결과/분류 변경과 구별하고 Retry-After 동안 재시도를 보류한다. 서버 저장 동기화는 추가하지 않았다.

네이티브 입력 5개를 고정한 digest는 `9c86c77dd9194b4677e470c5d8545f14702dcec773c7fa47f2ac54af740b3dc6`다. Android `5fa9f2ef-abe1-4cda-bd92-405290d2d319`, iOS `e9982851-1df3-49e0-a54f-80d0276fa7a0` 빌드가 각각 FINISHED다. 새 Android APK 설치·홈·저장·프로세스 종료 후 유지·숨김 글 차단·저장 해제를 실제 에뮬레이터에서 확인했다. 새 iOS 빌드의 실기기 확인은 사용자 요청으로 보류한다. 이전 0004 iPhone 확인을 0005 확인으로 재사용하지 않는다. native 상태는 `NATIVE_BUILDS_COMPILED`이며 기존 consistency/history 검사를 변경하지 않았다.

실제 로컬 SQL·익명 RPC·HTTP 8개 검사와 저장 경합/실패·커서 계약 5개 시험, 기존 게이트 회귀, 브라우저 두 탭 동시 저장/해제와 재로드, 실제 관리 권한의 합성 글 숨김/명시 재게시를 확인했다. 숨김에서 직접 재게시하려던 첫 요청은 기존 보호 장치가 거부했으며 수정하지 않았다. 명시적으로 정정 대기 → 검토 → 수동 게시 순서를 거쳐 테스트 글을 복원했다. 최초 발행 시각은 유지한다. 전체 verify·독립 clone·동일 바이트 검수·커밋 연결 증거는 저장소 밖 `outputs/development-stages/reviews/stage06c-implementation/`에 기록한다.

6D 설치 소유권·조회수·알림/설정, 6E 예약 게시, 7 시세, 8 실제 뉴스 수집 봇, 9 AI 분석은 후속 범위다. 실제 수집·AI·시세·push·광고 호출은 0이고 live 7/8은 CLOSED다. 클라우드 자원, 스토어 배포, git push는 수행하지 않는다.

## 구현 검수 r2 보완

첫 구현 검수에서 Claude는 READY(P3 2개), 독립 Codex는 P2 5개로 CHANGES_REQUIRED를 반환했다. 현재 수정본은 같은 검수 건의 재검수 대상이며 첫 통과를 전체 완료로 간주하지 않는다.

- S6CI-C01: 삭제보다 먼저 alias가 치환되는 순서도 처리한다. 저장 버튼이 요청 ID와 확인된 정규 ID를 함께 전달하고, 같은 런타임의 확인된 alias는 기기 저장과 별개의 메모리 한정 맵에 둔다. 삭제는 최신 잠금 구간에서 같은 글의 원래/정규 ID에 적용된다. 다른 탭이 변환했지만 정규 관계를 아직 확인하지 못한 경우에는 시각으로 추측하거나 성공한 무변경으로 처리하지 않고, 최신 목록과 명시적인 충돌 안내를 제공한다. 목록의 정규 항목에서 다시 해제할 수 있으며 오프라인 해제도 가능하다. alias를 영속 envelope에 추가하지 않는다. 두 실행 순서, 두 store의 치환 후 해제, 정규 근거 미확인 충돌을 실제 저장 모듈 시험으로 확인한다.
- S6CI-C02: 기사 상세도 `useCurrentRead`로 바꿔 재조회 시작부터 이전 제목·요약·본문을 가린다. 2.5초 지연 후 HIDDEN을 반환하는 로컬 읽기 전용 UI 시험에서 재조회 안내만 노출되는 것을 확인한다.
- S6CI-C03 및 Claude S6CI-02: 선택한 기업과 팝업은 검색 결과 행 밖에 둔다. 같은 질의의 자동 검색 반복을 없애고, 팝업 자체는 현재 데이터만 주기 재확인하면서 열린 상태와 페이지를 보존한다. 실제로 확인된 분류 버전이 바뀌면 첫 페이지로 재시작한다. 40개 합성 링크 시험에서 두 번째 페이지가 12초 뒤에도 유지되는 것을 확인한다. 현재 참조 기업에는 관련 섹터 4개 이상인 기업이 없어 시험 응답만 주입했으며 원본·DB는 바꾸지 않는다.
- S6CI-C04: 검색과 저장의 선행 catalog 조회에도 동일한 429 cooldown 훅을 사용한다. catalog의 Retry-After 상태를 화면에 구분하고, 기다리는 동안 catalog 재시도도 보내지 않는다. query 결과의 429만 확인하던 경로를 제거했다.
- S6CI-C05: 현재 Expo 준비 요약과 implementationLimits도 새 0005·AsyncStorage·두 FINISHED 빌드·iOS 실기기 보류에 맞췄다. 0004 확인은 과거 관측으로만 남긴다. 기존 native consistency/history 가드는 바꾸지 않는다.
- Claude S6CI-01: 저장일 표시에도 Asia/Seoul을 지정한다. 저장 정렬과 최초 시각은 UTC ISO를 유지한다.

추가 UI 하네스는 명시적인 로컬 합성 시험 모드에서만 실행하고 기존 Host/Origin/rate/응답 경계를 재사용한다. 429·40개 링크 팝업·지연된 숨김 응답을 주입하며 DB 쓰기·외부 뉴스 요청은 없다. 각 시험 후 하네스를 종료하고 원래 공개 읽기 게이트웨이와 실제 합성 기사의 공개 응답을 복원한다. 이는 실제 매체·실기업 운영 자료의 검증이 아니다.

## 구현 검수 r3 보완

r2 독립 Codex는 READY였고 Claude는 S6CI-03(P2)에서 상세 재조회 중 ScrollView 높이 축소와 읽던 위치 손실을 지적했다. 상세는 이전 본문을 유지하지 않고, 공개 응답의 렌더 높이 숫자만 현재 경로의 메모리 ref에 보관한다. 재조회 동안 이전 제목·요약·본문은 렌더에서 제거하고 그 높이만 빈 공간으로 유지해 스크롤 범위를 보존한다. 헤더에도 확인 중 상태를 표시한다. 최신 공개 응답은 새 본문으로 바꾸고, 비공개/실패 응답은 일반 안내만 표시하며 이전 높이 강제를 해제한다. 다른 기사 경로의 높이는 재사용하지 않는다. 높이 정보는 영속 저장하지 않는다. 실제 브라우저의 긴 기사 중간에서 재조회 전·중·후 scrollTop, 내용 높이, 이전 본문 부재를 함께 검사하고 다음 숨김 응답에서도 제목·본문 미노출을 확인한다. native 입력 5개·SQL 1~40·native 검사에는 변경이 없다.
