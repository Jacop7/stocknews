## 기준과 선행 증거

2단계는 최종 DUAL READY `4c76aa061cedb23e714b80bedcaf0ee162a38a29edee8352dbc8f468491eeee5` 후 같은 106파일로 `0c81416de798a4923ebdcf4dee2ead0f1955f416`을 커밋하고 main에 ff-only 병합했다. 커밋 뒤 전체 검사와 실제 새 Git clone의 바이트 일치도 확인했다. Android는 새 전용 에뮬레이터 직접 관측, iPhone은 사용자 네이티브 앱 실행 확인과 작성자의 iOS 번들 로딩 관측이다. 원격 push/CI는 아직 없다.

공통 운영계약 v1.0, 제작 실행계획 v1.3 §7, 뉴스 상세로직 v1.1과 매체별 부록이 권위다. 사용자 최신 요청인 무인 순차 진행과 **텔레그램 링크 우선 → 메시지 키워드로 원문 뉴스 검색**을 반영한다. 식자재 앱 코드·자원·설정·인증·DB는 계속 사용하지 않는다. 기존 기획 사본 11개는 수정하지 않는다.

2단계 비차단 지적 S2I-C04의 오래된 ‘native 미검증’ 설명은 이번 단계 상태 문서에서 최신 증거와 맞춘다. 이전 커밋·검수 원문은 재작성하지 않는다.

## 범위와 완료의 의미

이 단계는 공급 경로의 등록·권한·기술·품질·가격·거래일 계약을 검증하는 병행 트랙이다. 실제 수집·분석·게시 worker 가동은 4/6/8단계이고, 실제 가격 순위는 7단계다. consumer 앱 로그인은 추가하지 않는다.

모든 출처를 ACTIVE로 만드는 것이 목표가 아니다. 각 경로에 확인된 근거와 정확한 대기 사유를 남기고, 통과한 경로만 후속 실데이터 게이트를 열어야 한다. **등록/검사 기반 완성**, **허용된 개별 공급 시험 통과**, **7/8단계 LIVE 공급 통과**를 서로 다른 상태로 기록한다. 권한·자격증명·공급 계약이 없으면 실데이터 게이트는 PENDING이다. 이를 성공으로 바꾸지 않고, 제작계획이 허용한 4~6단계 M1의 수동/명시적 fixture 작업은 독립 진행할 수 있다.

외부 조건이 남으면 3단계 상태는 `IMPLEMENTED_SUPPLY_PENDING`으로 유지하고 외부 트랙을 완료 처리하지 않는다. 이 상태에서 4단계 M1을 시작할 때도 3단계가 전부 완료됐다고 소급 표시하지 않는다. 단계 상태·의존성 검사는 이 병행 경로와 7/8의 실공급 차단을 명시적으로 지원하도록 구현한다.

이번 범위에 공급 계약 체결, 약관 수락, 유료 API 구매, 사람·채널에 연락, 기존 Telegram 세션/쿠키 추출, 증권계좌 조회·주문, 실제 광고/푸시/자동 게시, 운영 DB 생성은 없다. 사용자에게 별도 조작이 필요한 항목은 구체적인 사유·준비 결과와 함께 대기 목록으로 남긴다.

## 원본 수집처 보존과 버전

승인된 원본은 `outputs/plan-unified-20261113/source-registry-snapshot.json`이다. 시트 `26-11-13`, 원본 SHA-256은 `e3c73be287b9a4eedf11218da402eef6346979cee3e22d3f87a338c6fea407fa`다. 106행, 112 URL이며 원본 type별 텔레그램53·리포트14·뉴스39다. 이 수치는 독립 언론사 수나 가동 수가 아니다.

원본 전체 바이트는 제품 Git 밖의 위 동결본으로 보존한다. 제품 data 영역에는 원본 row/name/type/category/market/urls를 모두 보존한 파생 registry와 원본 전체 SHA·bytes, 행 배열의 canonical SHA를 둔다. 원본의 source 메타데이터에 있는 Google Sheets 문서 URL·문서 ID·시트명은 제품 사본에서 논리 locator `approved-source-registry/2026-11-13`로 대체한다. 따라서 전체 원본과 제품 파일의 바이트가 같다고 주장하지 않는다. 제품 밖 검사는 원본 전체 해시와 양쪽 행 배열 일치를 확인하고, 이식 가능한 CI는 고정 행 배열 해시·수량·필드를 검증한다. 행을 삭제하거나 URL을 변경하는 방식으로 비식별화하지 않는다.

행은 고정 source_id로, 각 URL은 별도 endpoint_id로 식별한다. 같은 URL을 가진 행을 삭제하지 않고 다대다 연결한다. 원본의 ‘KB 리서치봇’처럼 대화형 리포트 봇은 원본 type을 유지하면서 effective_kind를 별도로 둔다. 일반 공개 채널 목록 adapter를 재사용하지 않는다. 로그인·명령/응답·다운로드 조건이 확인되기 전 요청하지 않는다.

원본에 없는 공식 발표·공시·IR·검색 API·가격·캘린더 경로는 별도 추가 레지스트리에 등록한다. 출처 이름만으로 소유 그룹·독립 취재·재배포 허가를 생성하지 않는다. 시트의 실시간 최신 여부를 조회하지 못하면 위 날짜의 동결본이라고 표시한다. 원본 시트는 쓰지 않는다. 최신 시트 읽기가 가능하면 읽기 전용 차이 보고만 만들고 승인된 기준을 조용히 덮어쓰지 않는다.

## 텔레그램에서 원문을 찾는 순서

### 1차 — 외부 링크

권한이 확인된 연동에서 외부 URL을 먼저 추출한다. 텔레그램 메시지를 기사 본문이나 독립 증거로 사용하지 않는다. 허용된 리디렉션을 따라 최종 원문·canonical URL을 확인하고, 이미 등록된 문서인지 검사한다. 제목·머리말로 1차 관련성을 판단한 뒤 필요한 본문 검증을 수행한다. 메시지에 첨부된 PDF/리포트도 별도 원문의 권한·형식 검사를 거친다.

단축 주소는 최대 hop·timeout·응답 크기·허용 host 정책을 적용한다. 사설 IP/localhost/link-local/클라우드 메타데이터 주소, 자격증명이 들어간 URL, 허용하지 않은 scheme과 포트는 차단한다. 추적 매개변수는 명시된 목록만 제거하고 기사 식별·언어·페이지 매개변수는 유지한다.

### 2차 — 원문 뉴스 검색

링크가 없거나 원문을 확인할 수 없으면, 허용 범위 안에서 기업명·산업·사건·발표시점의 최소 검색어를 만든다. 초기에는 로컬 카탈로그/별칭·규칙을 사용하고 Telegram 메시지 전체를 LLM이나 검색 API에 보내지 않는다. 이 단계의 검색어 활용 권한도 별도로 확인한다.

검색 결과는 발견 경로일 뿐 독립 근거가 아니다. 허용된 검색 API와 원문 경로에서 제목·시점·기업·사건 일치를 대조한다. 원문을 찾지 못하거나 핵심 사실/한국 전달 경로를 확인하지 못하면 HOLD다. 검색 순위나 비슷한 키워드만으로 원문을 지어내거나 게시하지 않는다.

네이버·Brave는 각각 별도 discovery-only `PLATFORM_RESOLVE` 경로와 쿼리 예산 큐로 등록한다. API 사용 여부·우선순위·허용 검색 필드·응답 범위·호출/비용 한도는 허용된 시험 뒤 버전 있는 구성 결정 기록으로 고정한다. 미확정 공급자는 비활성이며 키가 있다는 이유로 켜지 않는다. 검색 결과를 원문·독립 취재로 세지 않고, 원문 경로의 별도 접근/활용 조건을 다시 확인한다.

### 접근 조건과 대체 경로

Telegram 공식 content licensing/API 약관은 자동 수집과 AI 활용에 제한을 두며 예외에는 해당 범위의 명시적 동의 조건이 있다. **링크만 추출한다는 이유로 자동 허용하지 않는다.** 개인 계정 로그인·공개 채널 열람 가능 여부·Bot API 사용 가능성과 데이터 활용 허가는 다른 확인 항목이다. 실제 연동 조건이 미확정이면 Telegram 경로는 RIGHTS_HOLD이며 링크 추출/키워드 자동 검색도 실행하지 않는다.

그동안 언론사·증권사 원문 목록, 공식 공시/IR 등 독립적으로 허용된 직접 경로를 이용한다. Telegram에서 수집한 데이터를 다른 경로라고 가장하지 않는다. 사용자가 직접 제공한 외부 URL도 원문 경로의 권한·보안·중복 게이트는 통과해야 한다.

## 권한과 상태 계약

SourceStatus는 CANDIDATE / RIGHTS_HOLD / TECH_TEST / SHADOW / ACTIVE / PAUSED_RATE_LIMIT / PAUSED_ACCESS / PAUSED_ERROR / DISABLED다. 원본의 미확인 초기값은 RIGHTS_HOLD / RIGHTS_UNVERIFIED다. CANDIDATE는 평가 전이며 요청을 실행하지 않는다.

permission_profile은 버전·대상 endpoint·주체·근거 URL/문서해시·확인일·만료/철회·허용 예산을 갖고, 아래 용도를 각각 명시한다. 미확인 값은 허용이 아니다.

| 분리할 용도 | 확인할 범위 |
| --- | --- |
| 목록/메타데이터 발견 | 목록 요청, 제목·URL·시각·머리말 취득, 링크 추출, 검색어 사용 |
| 원문 접근 | 본문/PDF 취득, 로그인 필요 여부, 허용 endpoint/방식 |
| 보관 | 원문·revision·추출물·cache·파생본의 범위와 보관기간 |
| 분석 | LLM 전송·요약/분류·상업적 서비스에서의 처리 |
| 제공 | 재배포/요약 표시·인용 범위·출처 표시 조건 |
| 기계 접근 | API/RSS/HTML/브라우저 허용 방식, 요청량, 복구·철회 조건 |

허용된 기술 시험만 TECH_TEST로 진행한다. SHADOW/ACTIVE 전환은 권한·기술·품질 조건을 모두 만족해야 하며, 이번 시험 결과만으로 자동 승격하지 않는다. robots/RSS 공개·HTTP200·공식 기관이라는 사실을 이용 허가로 바꾸지 않는다. 401/403/CAPTCHA/로그인/약관 동의/제한에 막히면 우회·프록시·쿠키 재사용을 하지 않고 사유를 남긴다.

시간대는 한국 구간 Asia/Seoul·미국 세션 America/New_York, 시작 포함/끝 미포함이다. DST·조기 종료를 공식 캘린더로 계산하며 20:00 FOREIGN_US 전환과 키워드 정비는 콘텐츠 큐를 멈추지 않는다. Telegram/KB봇의 현 상태는 비활성이다. 일회 probe는 이 운영 주기를 시작하지 않는다. 30분 겹침·시간별 최근6시간·일일72시간 보완, 페이지 상한 PARTIAL·체크포인트 보존 계약을 합성 시험하며 운영 스케줄러는 후속 단계다.

복구는 상세로직 §3.1대로 버전 있는 순수 정책으로 검증한다. 신규/권한·adapter 변경은 TECH_TEST를 거쳐 SHADOW다. SHADOW 승격은 5거래일·성공 목록검사10회 이상·허용 본문1개 이상·미해결 치명 오류0·관측 성공률95% 이상을 모두 충족해야 하며 미달은 그대로 둔다. 품질 문제로 강등한 경로는 SHADOW 재승격을 거쳐야 한다. 이는 서비스 LIVE 승인과 별개다.

일시 장애 전 resume_state와 permission/adapter/quality 버전을 저장한다. 같은 버전·범위·권한 유효·미해결 품질 문제 없음인 경로만 5분 이상 간격의 정상 목록/파싱/ID/체크포인트 검사2회 후 직전 ACTIVE/SHADOW로 복귀한다. 빈 목록은 구조와 범위 유효성을 확인해야 한다. 새 경로를 이 절차로 ACTIVE에 올리지 않는다. 429는 Retry-After와 1/5/15분 중 더 느린 제한 및 일일 재탐색3회 이하, 일시403은1/6/24시간 최대3회, 5xx/네트워크는1/5/15분 뒤1/6/24시간 최대3회다. 이 상한 후 일시 장애만 1일1회·최초 허용 재탐색부터 최대14일의 LOW_FREQUENCY로 둔다. 더 늦은 Retry-After를 존중하고 실패 횟수를 초기화하지 않는다. 만료/영구 폐쇄는 DISABLED, 명시적 인증·결제·권한 부족은 자동 재탐색하지 않는다.

예산은 endpoint뿐 아니라 domain·검색식 버전별 합산으로 강제한다. 초기 큐 배분은 기본 탐색40%/상승·급변25%/HOLD·정정20%/늦은 기사15%이며 큐 최소 처리량과 실제 공급 상한이 우선한다. 목록·원문·PDF·검색 요청·LLM 토큰 비용을 별도로 기록한다. 계약/키/단가·한도가 미확정이면 실요청 비활성이고 숫자를 임의 구매 예산으로 해석하지 않는다.

기준선은 provider/endpoint·정책·기간·표본종류(SYNTHETIC 또는 PERMITTED_REAL)별로 기록한다. 허용된 실요청 중 시도/성공/실패/PARTIAL 수와 분모, 지연 표본 수·p50/p95/max, 원문 확보율, 사용량·통화·단가 근거·총비용·발견1건당/게시1건당 비용의 각각의 분모를 둔다. 차단되어 transport를 부르지 않은 건은 요청 성공률 분모에서 제외하고 별도 수로 센다. 미시도·실공급 없음·단가 미확인은 NOT_MEASURED와 null이고 0ms·100%·무료로 채우지 않는다. 게시 파이프라인이 없는 3단계의 게시당 비용은 미측정이다. 8단계의 고정 평가세트·정책 목표 확정, 12단계 LIVE 검증과 구분한다.

## 시험 방식과 보안 경계

기술 도구는 허용 요청 전에 permission_profile·source 상태·endpoint/redirect host·예산·timeout·size·method를 검사한다. 기본은 네트워크 비실행이다. 최초 초기값은 동시2·host별1, route당1요청, 제한적 재시도 최대1회라는 **제안값**이며 공급 조건보다 느슨하게 적용하지 않는다. 429는 Retry-After와 예산을 지키고, 인증/접근 거절은 새 경로·계정으로 회피하지 않는다.

비밀·쿠키·API key·private chat·개인 Telegram 세션은 source·fixture·로그·검수 파일에 넣지 않는다. 허용된 응답도 정책에 없는 원문 장기 보관을 하지 않는다. 로그에는 요청 식별자·endpoint ID·상태·시간·bytes/hash·검증된 필드와 사유만 남긴다. 공개 전 보관 만료/철회는 원문뿐 아니라 추출물·cache·파생 결과까지 연결한다. 실제 장기 삭제·백업 복원 작업은 8/12단계다.

## 시세·벤치마크·캘린더

한국 가격과 미국 비교군 가격의 계약·시각·시장·세션·조정 기준을 각각 확인한다. 개인 증권 API의 계정 사용 가능성을 상업적 앱 재배포 허가로 간주하지 않는다. 지연 종가 자료를 10분 실시간 시세라고 표시하지 않는다. 공개 사이트의 비공식 내부 API나 로그인 세션을 추출하지 않는다.

KRX·NYSE·Nasdaq 등 실제 구성 종목 시장을 명시하고 상장 종목 식별자/통화/venue를 검증한다. 미국 회사 목록 전체를 단순 평균하지 않으며, 수요/동종 비교군·버전·세션은 7단계 계약과 연결한다. 실제 종목 카탈로그를 아직 가져오지 못했으면 대표 표본 시험과 전체 구성 커버리지를 구분한다. 유효70%·유효수 min(3,N) 기준 미달/미확보를 0%로 채우지 않는다.

## 관련성·근거·중복 평가 기준

제목/머리말은 값싼 선별용이고, 게시 근거 확인은 원문/공식 자료 기준이다. 증시 전체에 영향을 주는 원인 또는 한국 섹터·기업으로 이어지는 구체 경로가 있어야 한다. 단순 등락 나열·금융상품/계좌 홍보·무관 생활뉴스를 관련 뉴스로 올리지 않는다. 회사명/매크로 키워드가 나왔다는 사실만으로 수혜·피해를 확정하지 않는다.

라벨은 대상 여부, 사실/전망 구분, 인과·영향 경로, source/claim provenance, Story/Issue 관계, DUPLICATE/UPDATE/NEW_ANGLE/HOLD를 담는다. 일반 추가 정보는 기존 Issue 업데이트, 새로운 사실·독립 영향 방향 등 공통계약 조건을 모두 통과한 경우만 새 Issue다. 정정·부정·피해 전용·조건부 관련·확인할 일정 없음 등의 콘텐츠 노출 사례도 포함한다.

초기 회귀 fixture는 직접 작성한 합성 사례로 시작하고 SYNTHETIC/게시 불가를 표시한다. 실제 허용 자료는 권한·버전·수집시각과 함께 별도 묶음으로 보존한다. 이 라벨 초안이나 소수 표본을 실제 분류 성능, 매체별 최근100건 평가 완료, 동결 출시 평가 세트로 표시하지 않는다. 본문 미확보는 근거/맥락 점수0이 아니라 미확보이며 분모·확보 수를 따로 기록한다.

## 공식 참고와 확인 범위

- [Telegram Content Licensing](https://telegram.org/tos/content-licensing), [Telegram API 약관](https://core.telegram.org/api/terms): 접근·AI 활용 조건의 확인 자료. 메시지 내용은 수집하지 않았다.
- [NYSE 공식 거래시간·캘린더](https://www.nyse.com/trade/hours-calendars), [Nasdaq Trader 공식 캘린더](https://www.nasdaqtrader.com/Trader.aspx?id=calendar): 공식 표 존재 확인. 이번 계획은 실제 거래일 파일이나 자동 이용 허가를 만들지 않는다.
- [KIS 공식 API 목록](https://apiportal.koreainvestment.com/apiservice-summary): 가격 API 후보 문서. 실제 계정·키·상업적 제공 범위·응답 시험은 미확인이다.
- [SEC 공식 API 안내](https://www.sec.gov/search-filings/edgar-application-programming-interfaces), [SEC 자동 접근 FAQ](https://www.sec.gov/about/webmaster-frequently-asked-questions): 공식 JSON/접근 정책 후보. 실제 요청/활용 범위는 별도 확인한다.

공식 문서 읽기와 수집 데이터 이용 허가는 다르다. 확인하지 못한 한국 거래소 공지·각 언론/리포트의 조건은 미확인으로 남긴다. 2단계 계정/기기 성공이나 사용자의 자동 진행 요청을 다른 제공자의 이용 허가로 확대하지 않는다.
