## 4. 6A 오프라인 파서 계약

입력은 동결 JSON 파일뿐이다. 네트워크·Google 쓰기·DB/Auth/Docker 호출·환경 비밀 읽기·앱 import가 없는 순수 Node 도구로 만든다. 출력은 제품의 ignored `.local-data/catalog-previews` 아래 미리보기 파일이다. `--apply`나 DB 연결 옵션은 만들지 않는다. 출력 경로를 검증하고 원본/기존 결과를 조용히 덮어쓰지 않는다.

원본 raw 문자열·배열·서식 run·좌표는 손실 없이 남긴다. 별도 정규화 값은 NFC·검색용 공백 정리 등 명시된 규칙만 적용한다. 카테고리명과 하단 B 연결을 대조하는 비교키는 NFC 후 앞뒤 공백만 trim하며 내부 공백·구두점·동의어를 임의 통일하지 않는다. 변환이 생기면 원본 좌표·셀 SHA·before/after·규칙을 normalization ledger에 남긴다. 실제 A45의 `철강 `은 `철강` 비교키로 B156·B157·B339·B389의 4개 연결과 대조하되 원본 공백을 보존한다. 서로 다른 원문 이름이 같은 비교키가 되면 충돌 HOLD이며 자동 합병하지 않는다. 숫자나 가격/수익률·수혜를 창작하지 않는다. 회사·카테고리의 원본 순서를 유지하며 분류명 교정은 stable ID를 유지하는 별도 변경으로 둔다. `비젼/카메라`와 `sdv`도 원문 보존이다.

하위 묶음 후보는 B열의 **줄 시작과 괄호 바깥 콜론 앞의 유효한 제목 글자**로 찾고, 굵은 서식을 보조 근거로 사용한다. 제목 전체에 서식이 없다는 이유만으로 후보를 버리거나 기업명으로 처리하지 않는다. 제목 글자가 굵은 일반 경로에서는 콜론 자체가 굵지 않은 ‘리플로우 장비’, ‘패키징 테스트 핸들러’도 인식한다. 굵은 쉼표·괄호·회사명 조각만으로 묶음을 만들지 않으며 제목 없는 B56의 굵은 `), `는 그대로 구두점이다. Google 서식 run의 startIndex는 UTF-16 단위이고 첫0이 생략될 수 있으므로 이를 명시 처리한다. 줄바꿈/NBSP와 원본 범위도 보존한다.

서식 없는 현재 원본은 명시된 예외 레지스트리와 셀 SHA·제목 목록이 일치할 때만 채택한다. B10 ‘반도체 기판’의 6묶음은 `FC-BGA`, `FC-BGA · MLB · SoCAMM`, `FC-BGA · SoCAMM`, `SoCAMM`, `MLB(고다층기판)`, `장비`이며 B37 ‘조선’은 `선박 건조`, `선박 엔진`, `LNG 보냉재`의 3묶음이다. 정확한 순서·철자·좌표와 서식 없음도 결과에 기록한다. 새로 생긴 서식 없는 접두어, 제목 목록/해시 불일치는 HOLD로 보고하며 자동 기업명 편입·묶음 생략·자동 채택을 하지 않는다.

B5의 `반도체 IP :`와 B6의 `팹리스 :`는 하위 묶음이 아니라 각 카테고리를 반복하는 단일 표지다. 명시적 레지스트리에서 B5는 ‘반도체 IP’, B6는 ‘반도체 팹리스’의 표지로 연결하고 해당 기업의 subgroup은 null로 둔다. 접두어를 raw와 categoryLabel 필드·원본 위치에 보존한 채 기업 분리에서만 제외한다. 이 두 예외를 일반적인 유사어 자동 제거로 확장하지 않는다. 괄호 보정은 별도의 승인 ledger를 거친 뒤 적용하고, 서식 없는 예외·반복 표지·굵은 구두점 규칙을 서로 분리해 검사한다.

기업 목록은 괄호 깊이를 유지하며 깊이0의 구분자에서만 나눈다. `NPU, 메모리(LPDDR, HBM) IP`의 쉼표를 다른 기업으로 분리하지 않는다. 하단 기업 사전/검증된 별칭을 longest-match로 대조하고 동명·미해결 이름은 차단 항목으로 남긴다. ‘후공정/패키징’의 슬래시를 카테고리 구분자로 쪼개지 않는다. 연결을 추정해서339개에 맞추지 않으며 미해결 행을 제외하고 전체 성공이라고 보고하지 않는다.

같은 기업은 여러 카테고리·묶음에 연결될 수 있다. 같은 membership의 중복만 구분하고, 다른 묶음의 역할 설명은 각 연결에 따로 둔다. 예를 들어 로보티즈의 핸드 행을 액추에이터/양산 검색어로 채우지 않는다. B열 그룹 설명은 관련종목 행에, 하단 E는 전체 종목 검색에 사용하도록 별도 필드로 출력한다.

키워드는 한 행 안의 정확한 중복만 표시하되 raw를 삭제하지 않는다. 카테고리 사이의 HBM·CXL 등 중복은 모두 연결한다. 직접 기업 검색어와 산업 발견어를 구분하며 키워드 일치만으로 모든 연결 기업의 수혜/피해를 확정하지 않는다. 미국·중국 기업은 원문의 모든 항목과 역할을 보존하고 검증 여부를 따로 둔다.

초기 상위11분류 연결은 승인 서비스 기획안의 ‘초기 섹터 분류’를 사용한다. 엔터는 **통신 · 엔터 · 게임**에만, 소비재는 엔터/편의점 없이 연결한다. 피팅·밸브는 에너지다. AI 데이터센터는 여러 산업의 검색/분석 주제로 보존하되 전력·풍력·피팅 기업 전체를 직접 데이터센터 수혜로 만들지 않는다. 분류56개와 상위 표의 일대일 포함/누락·추가를 검사한다.

## 5. 원본 괄호 두 곳의 이관 보정 제안

최신 원본 B5와 B36에는 닫는 괄호가 하나씩 빠져 있다. 원본을 수정하지 않고 source-cell SHA와 정확한 before 문자열을 조건으로 하는 보정 제안 ledger를 만든다. 각각 한 위치만 일치할 때 아래 보정을 적용한 **별도 미리보기**를 생성하며 원문도 함께 유지한다. 불일치하면 자동 적용하지 않는다.

| 셀 | 제안 보정 | 보존 내용 |
| --- | --- | --- |

## 6. 식별자와 이관 미리보기

신규 namespace의 카탈로그 레지스트리로 상위/섹터/묶음 ID를 첫 생성 후 고정한다. 매 실행마다 표시명으로 ID를 다시 계산하지 않는다. 이름이 바뀌면 새 레코드로 자동 대체/삭제하지 않고 명시적 rename/move 후보와 diff를 만든다. 이름 정규화 충돌도 보고한다. 실제 DB 적용은6B의 expected catalog_version·관리자 권한·감사·원자 적용 계약을 따른다.

하단339개는 **원본 기업 레코드 수**다. 운영 기업 ID·종목 링크는 검증된 거래소/종목코드/주식종류에 결속해야 한다. 이름만으로 거래소 코드나 상장 여부를 만들어내지 않는다. 미검증 회사는 source_company_ref와 UNRESOLVED로 보존하며 웹뷰/가격 연결을 생성하지 않는다. 회사명 변경·별칭·표기 오류는 공식 코드 대조와 별도 변경 이력으로 해결한다. 한국 관련종목 목록에 미국·중국 기업을 끼우지 않는다.

미리보기는 source hash, parser version, normalization ledger, 원본 좌표, 연결/설명/키워드 수, unresolved/중복/누락, 상위 분류 차이, 이름 변경/추가/비활성 후보를 포함한다. 원본339개가 모두 보존됐는지와 연결이 모두 해석됐는지는 별도 상태다. 초기 적용 후 운영 DB가 기준이고 시트와 양방향 자동 덮어쓰기를 하지 않는다.

## 7. 6B 이후 반드시 해결할 연결 계약

**카탈로그 호환성:** 현재 M1 공개 검사는 article_version의 catalog_version과 활성 카탈로그/섹터 버전을 결속한다. 이름·설명만 바꾸고 catalog_version을 올렸다는 이유로 기존 모든 글을 차단해서는 안 된다. 6B는 승인된 과거 snapshot의 참조와 현재 active identity 검사를 분리하고, 이전 기사 결정/당시 구성/정책은 불변으로 남긴다. 새 초안/게시/예약은 최신 head의 version으로 CAS한다. 삭제·정책 철회·근거 불가는 계속 안전 차단하며 구버전 호환 허용을 blanket bypass로 쓰지 않는다. 이름/설명 메타데이터 변경으로 최초 게시일·본문 수정일을 바꾸지 않는다.

**섹터 삭제:** 실제 연결 영향과 대표 섹터 사용 글/예약, 활성 하위 묶음을 먼저 보여준다. 비활성화·이동·기존 검증 영향 경로의 대표 대체를 원자 적용한다. 새 대체 섹터의 수혜를 자동 생성하지 않는다. 적법한 대체 경로가 없으면 게시 글을 정정대기로 차단하거나 작업을 보류하며 임의 재연결하지 않는다. 삭제된 ID는 옛 작업·저장·필터가 재활성화하지 못한다.

**필터/검색:** 상위 섹터 탭 순서대로 하위 섹터를 한 팝업에 표시한다. 선택칩과 본문 버튼 크기를 맞추고 하단 선택값·닫기/결과 보기를 유지한다. ‘상위 전체’는 그 상위의 활성 ID 집합이며 선택 표시도 하위 버튼에 반영한다. 적용 전 선택은 임시 상태이며 취소하면 기존 조건을 유지한다. 오늘·어제·이번주·지난주·이번달·지난달은 한국 달력과 최초 앱 게시일 기준이다. 6단계의 달력 목록/검색을 7단계 시장 수익률 랭킹처럼 표시하지 않는다. 복합 `(first_published_at,issue_id)` cursor와 필터 문맥을 함께 결속해 동시 시각/페이지 경계 누락을 막는다.

**한국 종목/저장:** 그룹별 B 역할 설명, 전체 검색의 하단 E, 내부 상세 역할을 분리한다. 미연결 가격·등락률은 빈 상태로 표시하며0%/합성 시세를 실제 값처럼 넣지 않는다. 검증된 한국6자리 코드만 네이버증권 종목 URL로 구성한다. 저장은 canonical Issue ID·저장 시각을 기기에 보존하고 alias 치환·중복 제거·숨김의 본문 없는 안내·재실행·취소를 시험한다. 기기 저장은 로그인/계정 동기화를 뜻하지 않는다.

**새 native 입력:** WebView·AsyncStorage·설치 소유권 비밀 보관용 SecureStore가 필요하면6C/D 계획에서 실제 SDK58 호환 패키지와 lock diff를 고정한다. native0004를 조용히 재사용하지 않는다. 새 native 지문/runtime/build·Android/iPhone 관측과 누락 모듈 음성 시험을 거친다. AsyncStorage에는 설치 비밀/관리자 JWT를 넣지 않는다. 설치된 빌드와 JS 입력 불일치를 OTA로 우회하지 않는다. Expo 공식 [WebView](https://docs.expo.dev/versions/latest/sdk/webview/), [AsyncStorage](https://docs.expo.dev/versions/latest/sdk/async-storage/), [개발 빌드](https://docs.expo.dev/develop/development-builds/introduction/) 안내를 확인했으며 설치/새 빌드를 실행한 것은 아니다.

**조회와 비밀 경계:** 설치 secret_hash/version/만료/철회, 상세 체류·foreground·한 navigation visit의 event key, 재시도 payload 결속과 서버 수락시각을 사용한다. 관리자 미리보기·테스트·재렌더링과 실제 조회를 구분한다. 현재 read-only gateway를 승인 없이 service-role 쓰기 proxy로 바꾸지 않는다.6D에서 고정된 설치/조회/설정 route와 서버 전용 자격 증명·rate/size/origin/소유권 경계, 명시적 local 시험과 LAN 활성화 조건을 별도 검수한다. 공개 앱에 PV/UV/내부 점수를 주지 않는다. 원시30×24h·초기1h 안전여유·watermark와 같은 DB snapshot으로 UV 지원창을 판정하며 창밖/누락은 미지원·미확보다. 일별 UV 합을 기간 UV로 표시하지 않는다.

**예약 U05:** 즉시 게시와 예약 실행 권한을 분리한다. 예약 부여 시 실제 관리자 권한, due 시 현재 사용자/역할·정책·카탈로그·근거·예약/초안 revision을 재확인하는 durable grant 계약을6E에서 결정한다. 만료된 브라우저 JWT를 저장해 재사용하거나 worker에 임의 관리자 권한을 주지 않는다. 로그아웃과 예약 취소의 의미·지연 허용·취소 경합을 명시한다. Cron은 같은 예약키로 큐 등록, worker는 최신 조건 재검사 후 게시 또는 HOLD, 취소/변경된 옛 작업은 무효다. 첫 게시시각은 실제 commit 시각이며 예정시각으로 소급하지 않는다. 같은 effect_key와 outbox/영수증으로 재시작·중복을 처리한다.

## 9. 완료의 뜻과 남는 작업

6A 완료는 **이관 준비 도구와 검수 가능한 미리보기**다. 실제 카탈로그 적용·DB/API·앱 필터·검색·기업코드 검증·가격·저장·웹뷰·조회 수집·예약·양쪽 기기 완료가 아니다. B5/B36 이외 미해결 해석과 미검증 코드는 결과에 남긴다.
