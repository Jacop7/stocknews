# 7B2B 구현 범위와 검증 기준

기준 커밋은 `37929a37fbc77cef91a87e267bfbb9321ad84d8a`, 계획 승인 manifest는 `2ead18b915cfdb64385784779283e06df4b46fc443c75c9703a22220f12f6080`이다. 계획 SHA-256은 `becc78aae5420c475fcde57643b50f5cdd2ee448f9a871680b4f4ffc7f3ccd18`이다. 결과 승인은 별도 outputs 검수 기록으로 보존한다.

`home-ranking.ts`는 고정 시각의 SYNTHETIC 입력만 받는 순수 조합 함수다. 7B1 우선순위와 7B2A 시각 모듈은 변경하지 않고 직접 가져온다. 공개 domain 진입점, 앱, API, DB, worker는 연결하지 않았다. 기존 338개 파일 중 package·verify·dispatcher·단계 상태 4개만 정확한 추가 항목으로 변경하고, 새 파일은 7개로 제한한다. 이전 검사 본문과 공급처 자료를 동결한다.

Story별 A/B/C 자격을 먼저 계산하고 기존 최고 자격 대표를 유지한다. 대표가 사라지거나 더 높은 자격의 방향이 생기면 대표를 교체한다. 대표만 대상으로 T/M/P 완결성과 UV 표본을 판단하므로 중복 기사가 표본을 부풀리지 않는다. 전체 16분석군 검색 자료가 유효할 때 MACRO_ALL의 T는 개별 값을 쓰지 않고 중립값 0.5를 유도한다. 자료 부재로 검색 모드를 활성화하지 않는다. 기존 I/T/M/P 수식과 HIGH 비가격 원칙은 유지한다.

A는 최대 2개, B는 최대 3개, C는 최대 20개이며 Story는 전체에서 한 번만 표시한다. 기존 생존 대표의 작은 점수 변화는 유지하며, 같은 비교 맥락에서 5점 이상 우세가 연속 5분 프레임 두 번에 걸쳐 확인될 때 순서를 바꾼다. 새 Story·대표·등급·역할 또는 실질 변경은 첫 프레임에 점수 위치로 진입한다. 모든 이전 쌍 비교는 고정된 직전 프레임의 점수로 수행한다.

HIGH의 구조 서명에는 수치 I/T/P, 시장, 대상일, M 모드가 없다. 따라서 작은 T 변화가 있어도 08:10·20:00 전환의 비가격 연속성을 유지한다. P3 S7B2BP-04에 따라 HIGH 대표 집합 자체가 달라지면서 시장도 전환되면 새 구조 비교로 정렬한다. 기존 생존 HIGH만 별도로 보존하는 확장은 이번 계약에 포함하지 않았으며 해당 동작을 명시적인 회귀 시험으로 고정한다.

C의 같은 섹터 제한은 같은 중요도 안에서만 적용한다. 발견 슬롯 5·10·15·20에는 STANDARD만 진입하며, 최초 게시부터 60분 미만이고 이전에 노출되지 않은 항목을 사용한다. 정확히 60분이면 발견 후보와 seen에서 제외한다. 자료 재확인으로 최초 게시 시각을 갱신할 수 없다. UV를 만들어 발견 점수로 사용하지 않는다.

입력은 own-data JSON 복제로 정규화한다. getter, 커스텀 iterator, 숨은 필드, 희소 배열, 순환과 비표준 prototype을 거부한다. 깊이·크기·유한 수치 한도가 있다. 직전 상태는 등급·점수 수식·전체 pool 집합·시각·seen 일관성을 재검증한다. 이 검사는 인증이나 DB 봉인을 대신하지 않는다. 동등 UTC 표기와 달력 순서도 동일한 결과가 되도록 반환 context를 정규화한다.

46개 단위 시험은 대표 선택, 중복 표본, MACRO 중립값, 용량·HIGH 초과, 5점·2프레임, 신규 즉시 진입, 숨김·만료·정정, 시장 전환, 다양성·발견, 최초 게시 불변성, 결정성과 입력 경계를 다룬다. 전체 필수 검사는 `pnpm verify`이며 독립 Git 객체를 가진 복제본 및 잘못된 ref·추가 커밋·변조 fixture 거부도 별도로 검증한다. 실행 결과는 검수용 외부 증거에 기록한다.

구현 r1 Codex P2 S7B2BI-01은 직전 상태의 동등 UTC 표기 정규화 누락이다. r2에서 직전 cutoff·context·material·게시·seen 시각을 의미 검증 뒤 정규화하고, 08:10·20:00의 5점 미만 유지, 전체 이전 시각·달력 표기의 동등성, 전환 시 두 회차 교체를 회귀 시험으로 추가한다. 입력 객체는 변경하지 않는다.

같은 ID를 쓴 Claude r1 P3 S7B2BI-01은 별개의 삽입 경계 권고다. 기존 안정화 순서에 작은 역전이 남아 있으면 신규 항목은 자신이 처음 이기는 항목 앞에 들어간다. 따라서 신규 항목이 더 높은 기존 항목보다 위일 수 있으며 기존 생존자 간 5점 지연 규칙을 보존하는 결정적 경계로 유지한다. 해당 동작도 시험으로 고정하며 P3를 자의적으로 종결하지 않는다. Claude P3 S7B2BI-02의 오래된 직전 상태 순서 재사용 제한은 7B2C의 15분 읽기·복구 계약에서 명시적으로 다룬다.

실제 DB 원자 저장·동시성·15분 만료 읽기는 7B2C, 공개 DTO·앱 화면은 7B3, 실데이터 권한·상품 조정은 7B4다. 전체 source-input manifest 봉인(P3 S7B2AI-01), 실제 상품 조정 의미(P3 S7AI-01)도 후속 단계다. 112개 공급처는 RIGHTS_HOLD, 실제 공급/AI/시세/발송/광고 요청은 0이다. M2나 전체 7B 완료를 주장하지 않으며 iPhone은 USER_DEFERRED다.
