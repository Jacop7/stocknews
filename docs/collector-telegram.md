# 공개 텔레그램 링크 저장

47개 공개 `/s/` 주소의 게시물 내부 외부 HTTPS 링크만 저장한다. 메시지·미디어·원문 제목·본문·작성자·조회수는 보관하지 않는다. 원문 열기, AI 분석, 앱 기사 게시까지 연결한 상태가 아니다. 단축 주소·플랫폼 주소의 실제 원출처도 아직 미확인이다.

- 기존 112주소+보조1, 웹37개 활성·20개 제외·게시자 이용 근거 프로필을 유지한다. 초대 NH5개와 KB 리포트봇1개는 계속 보류한다. KB 건설38·공개 NH 바이오41은 포함한다.
- `telegram-config.mjs INPUT OUTPUT [ISO_TIME]`는 실제 운영 설정에서 47개의 별도 `telegram_link_collection` 필드만 추가하고 모든 게시자 프로필 바이트를 보존한다. 원본 등록부와 다르면 거절한다. 이 설정은 사용자 요청의 운영 범위이며 외부 게시자의 이용 허가를 주장하지 않는다. 종료일 없이 철회까지 동작한다.
- 단일 worker에서 웹은 이전 주기 완료 후60초 이상, Telegram은 최소5초마다 순차 실행한다. 같은 채널은10분 이후 다시 방문하고 robots·Retry-After·429·접근거절 대기가 우선한다. 두 수집기를 병렬 실행하지 않는다.
- 방문 간격(2026-11-26 사용자 합의, `scripts/providers/pacing.mjs`): 같은 호스트는 기존 최소 간격에 0~3초 랜덤을 더한다(t.me 포함). 서로 다른 호스트로 이어지는 요청 사이에는 1~3초 랜덤으로 쉰 뒤 다음 슬롯을 예약하므로 호스트별 최소 간격이 줄지 않는다. robots·Retry-After·429·접근거절 대기는 그대로 우선한다. 랜덤 값은 운영 실행에서만 주입되고 라이브러리 기본값과 시험은 고정 간격이다. 간격 조정은 접속 부담을 나누는 목적이며 접속 정보 위장·차단 우회를 하지 않는다.
- t.me 전용 A레코드 조회·공개 IPv4 검증·DNS 고정만 추가한다. 공통 SSRF·TLS·robots 검사는 그대로다. 다른 호스트·로그인·초대·Telegram API를 사용하지 않는다.
- `/data/telegram-links.sqlite`에 endpoint+정규화 URL 관계를 중복 없이 기록한다. 전역 고유 URL과 출처 관계 수는 다르다. 최대100개 head 링크를 보관하고 초과는 PARTIAL이다. 과거 전체 수집을 보장하지 않는다.
- 마지막 관측 후7일 TTL이며 다시 관측되면 갱신한다. 수집 flag OFF·등록부 읽기 실패에도 만료 정리를 계속한다. 실제 철회·binding 변경은 해당 채널의 자료·진단·schedule만 정리한다. 매체 제외 변화는 해당 URL만 제거하고 다른 링크·채널 schedule을 지우지 않는다. 읽기 실패를 철회로 오인하지 않는다. URL 내용의 무기한 백업을 만들지 않는다.
- 직접 제외16행은 최신 DISABLED endpoint의 www 제거 호스트와 하위 호스트만 배제한다. 홈4행은 정확 목록 URL만 배제한다. 매일경제TV의 다른 MBN 호스트·미등록 별칭은 아직 확인하지 않았다(P3). 단축·재전송 링크는 미확인 후보이며 제외 원출처의 기사가 섞일 수 있다. 후속 원문 처리 전에 별도 판정해야 한다.
- 기존 웹 worker의 장애 의미는 유지하며 Telegram 요청·DB 실패는 웹 결과를 버리지 않는다. 운영 진단에는 HTTP·상태·시각·링크 수만 기록하고 원시 메시지/HTML/예외는 로그에 남기지 않는다.

## 배포 및 되돌리기

첫 순회·호스트 대기·실제 저장 증거를 구별한다. 최대10분 확인 후에도 건강한 worker에 링크가 아직 없으면 VERIFICATION_PENDING으로 유지하고 성공을 주장하거나 잘못 롤백하지 않는다. 저장된 유효 링크가 한 건 이상 있어야 실제 연결 성공으로 표시한다. 채널별 수집 성공 수는 별도로 확인한다.

구현과 관련 시험·양측 검수 후 현재 이미지에서 변경된 소스와 준비된 두 등록부 파일만 더한 파생 이미지를 만든다. 네트워크 없는 import/설정 검사 후 이미지 ID·기존 Compose·볼륨을 대조한다. `activate-telegram.sh RELEASE IMAGE IMAGE_SHA MANIFEST_SHA`가 웹 SQLite 온라인 백업·quick_check, 기존 자료 수, 동일 볼륨, 건강 상태·47개 설정·6개 보류와 실제 URL 저장을 확인한다. 새 포트·키·비용·외부 계정 권한을 추가하지 않는다.

첫 반영은 기존 Telegram DB가 없어야 한다. 이전 실패를 되돌린 경우에는 소유 롤백 표식과 URL행0을 확인해 재시도하며 호스트 대기를 유지한다. 웹 백업은 매 시도 고유 이름으로 만들고, 정상 만료를 허용하면서 아직 만료되지 않은 백업 행의 보존을 대조한다. 실제 Telegram 저장 행을 조회해 활성화를 확인하므로 빈 채널·PARTIAL·WAIT 로그만으로 성공이나 실패를 단정하지 않는다. 기존 Compose override도 겹쳐 쓰므로 이미지 외 설정을 잃지 않는다. 실패하면 새 worker를 중지하고 Telegram URL 행과 WAL을 비운 뒤 이전 이미지/Compose를 시작한다. 이전 바이너리가 TTL을 처리하지 못하므로 Telegram URL을 남긴 채 되돌리지 않는다. 기존 웹 DB를 삭제하거나 과거 백업으로 되감지 않는다. 배포 후 모든47개 채널 시도 상태를 회수하고 설정 수와 성공 수를 구별해 시트에 기록한다.
